## P03-1. 쉬어도 이기는 원정대

- **한 줄:** 아이가 “조용히·쉬고 싶어”를 고르면 성공 조건이 바뀌고, 보호자가 휴식 경유를 결정하는 협동 이야기.
- **장면:** 박물관 가는 길의 공룡 구조 이야기가 아이의 “조용히” 요청에 공룡도 잠드는 장면으로 바뀐다. 쉬어도 진행 손실·점수 차감·연속 기록 손실이 없다.
- **차에서 할 이유:** 차량 공용 오디오와 현재 박물관 경로를 한 이동 세션으로 묶어 동승자 모두의 놀이와 보호자의 경유 선택을 연결한다.
- **근거:** E1의 개인 차이·점진적 변화를 보고 고정 시간마다 건강 상태를 판정하는 대신 언제든 사용자 요청을 바꾸게 했다. 가족 협의가 쉬워진다는 효과는 가설이다.
- **SDK·외부 가정:** TTS 3.3.1의 재생·중지, 선택적으로 STT 3.3.1에서 명시적으로 시작한 세션의 제한된 선택어를 받는다. NaviHelper 3.0.5로 보호자가 확정한 경유지 한 곳을 요청한다. 휴게소 검색 API는 가정하지 않고, 최소 시연은 사전 검토한 한 경로의 POI를 수동 등록한다. 실제 운영·진입 가능 정보는 별도 확보가 필요하다.
- **작은 시연 계획:** 실제 Pleos 앱에서 목적지 요청·완료 이벤트 → 짧은 TTS → “조용히” 선택 → stop·onStop 확인 → 정차한 보호자가 휴식 POI 확정 → 경유 요청의 성공·오류 표시 → 손실 없이 이야기 재개. STT 대신 수동 입력한 경우 음성 성공으로 표시하지 않는다.
- **약점·검증 질문:** 오디오를 끄고 휴게소를 찾는 행동에 비해 무손실 이야기 규칙이 가족에게 추가 가치가 있는가?

## P03-2. 박물관에 없는 전시품 운송국

- **한 줄:** “공룡의 잃어버린 하품”을 차량으로 운송하고, 도착 후 닮은 진짜 전시품 하나를 찾는 엉뚱한 놀이.
- **장면:** 미리 정한 길의 구간을 지나면 보이지 않는 하품이 짧은 대사 하나를 바꾼다. 박물관에서는 하품과 닮은 모양 하나를 고르고, 차에 돌아와 “하품과 닮은 돌” 같은 가상 이름표를 완성한다.
- **차에서 할 이유:** 차량 위치가 막을 넘기는 무대 장치가 되고 가는 길·차 밖 관람·복귀가 이어진다. 빨리·멀리 가야 얻는 점수는 없으며 쉬거나 구간을 건너뛰어도 결말은 열린다.
- **근거:** E1은 화면 읽기에 크게 의존하지 않을 이유, E2는 이미지 하나를 골라 살펴보는 활동의 선례다. 재미·학습·멀미 감소 효과는 미검증이다.
- **SDK·외부 가정:** FusedLocation 1.1.3 업데이트와 앱에 저장한 좌표 구간, TTS 3.3.1 고정 대본을 쓴다. 구간당 한 번만 진행하고 null 위치면 전환을 보류한다. 허구 전시품은 자체 작성해 LLM·외부 서버가 필요 없다. 실제 작품 명칭·사진을 넣을 때는 박물관별 제공·이용 조건이 추가로 필요하다. 차 밖에서는 기억한 한 문장만으로 참여할 수 있다.
- **작은 시연 계획:** 실제 앱에서 전시품 선택 → 에뮬레이터 시험 위치 주입 → 실제 FusedLocation 콜백으로 TTS 장면 전환 → 무음 선택 시 보류 → 정차 후 차 밖 임무 확인 → 복귀했다는 수동 선택으로 이름표 완성. 시험 좌표·수동 확인을 실제 방문 감지로 설명하지 않는다.
- **약점·검증 질문:** 아이에게 재미있는 상상인가, 관람 대상과 무관한 말장난으로만 남는가?

## P03-3. 오늘 전시는 딱 하나

- **한 줄:** 차에서 정한 “한 점·짧게·쉬고 결정” 약속을 관람 카드로 바꾸고, 일찍 나와도 완료 처리하는 방문 앱.
- **장면:** 긴 이동 후 가족이 “마음에 드는 것 하나만 고르자”로 계획을 줄인다. 카드에는 전시 하나와 공식 안내에서 확인한 쉴 장소 하나만 넣는다. 정원·로비에서 돌아가기로 바꿔도 완료되고, 귀가할 때 짧은 음성 기념표를 듣는다.
- **차에서 할 이유:** 같은 차 안에서 방문 직전 기대를 맞추고 복귀 후 선택을 남긴다. 현재 목적지를 재사용하며 도착 이벤트는 계획 확인을 준비하는 데만 쓴다. 주차·하차 완료로 해석하지 않는다.
- **근거:** E2의 휴식 공간 안내와 모든 공간을 방문할 필요가 없다는 설명을 차량의 방문 계획으로 확장한 가설이다. 해당 공간의 멀미 회복 효과와 국내 시설 존재를 주장하지 않는다.
- **SDK·외부 가정:** NaviHelper 3.0.5 목적지 정보·도착 이벤트와 TTS 3.3.1을 쓴다. 관람 분량은 직접 선택하며 이동시간·목소리로 체력을 계산하지 않는다. 최소 시연은 예시 박물관 1곳의 공개 안내를 사람이 확인한 작은 데이터 파일이다. 국내 전시·휴관·휴식 시설은 별도 검토가 필요하고 예약·실내 위치·혼잡 API는 가정하지 않는다. 차 밖 카드는 정차 후 보호자가 사진으로 기록할 수 있다. 폰 웹 연동은 별도 서버·접근성 검토가 필요한 확장이다.
- **작은 시연 계획:** 실제 앱에서 목적지 정보 읽기 → 정차 후 “딱 하나” 선택 → 관람 카드 구성 → 도착 이벤트와 별개로 보호자가 정차 확인 → TTS 안내 → 관람 후 “하나 골랐어·쉬다 왔어·다음에 올래” 중 선택 → 동등한 완료 기념표. 입장·관람을 자동 검증하지 않는다.
- **약점·검증 질문:** 공식 박물관 사이트·지도 앱을 쓰는 보호자가 방문 직전 차량에서 관람 목표를 다시 정할 만큼 약속을 유용하게 느끼는가?

버전은 [정식 SDK 리뷰](../../pleos-sdk-review.md)의 2026-11-11 공개 패키지 대조 기준을 재사용했다. 이번에 AAR·해시를 다시 검증하지 않았다. 구조는 차량 앱의 로컬 규칙 엔진·짧은 콘텐츠·선택 상태를 기본으로 하며 외부 서버는 필수가 아니다. 원음·건강 기록·이동 이력의 외부 전송은 최소 구상에 포함하지 않았다.

우선 확인할 것은 실제 Pleos 앱의 TTS 재생·중지, NaviHelper 연결·완료·오류, 필요한 위치 콜백이다. 이어서 중단·null·연결 실패·내비 음성 공존과 동승자 조작의 적합성을 확인해야 한다. 고정 화면은 실제 SDK 시연을 대신하지 않는다. 운전자 화면 조작은 정차 후로 구상했으며 실제 주행 UI 제약은 미검증이다.

이번 수행은 문서 읽기·로컬 상태 확인·외부 원문 열람·이 파일 작성이다. 앱 빌드·SDK 실행·실차·계정 권한·마켓 승인·의료 효능·운전 안전 개선은 검증하지 않았다. 시장성·재이용률·인터뷰 결과도 만들지 않았다. 후속 검토에서는 이 파일과 기준 SDK 보고서를 먼저 읽고 새 증거·실행 결과가 생긴 범위만 갱신한다.
