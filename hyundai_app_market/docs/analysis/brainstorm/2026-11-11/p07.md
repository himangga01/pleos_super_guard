# P07 · 병원 가는 고양이 보호자의 작은 불편

- 작성·확인일: 2026-11-11 KST, Asia/Seoul. 독립 발산용 가상 페르소나이며 실제 인터뷰가 아니다.
- 페르소나: 반려묘와 병원을 오가는 보호자. 조용한 이동·대기를 원하고 독서를 좋아하며, 평소 넘기는 작은 불편을 확대해 보는 비평가다.
- 기준: 프로젝트 `AGENTS.md`, 공통 분석 정책, 공모전 조사·출처 목록, 2026-11-11 SDK 리뷰 및 NaviHelper·FusedLocation·TTS 개발 노트를 읽었다. 독립성을 위해 다른 페르소나 아이디어는 읽지 않았다.
- 로컬 확인: `git rev-parse --is-inside-work-tree`는 Git 저장소가 아니라는 오류를 반환했다. 브랜치·커밋·작업 트리 차이는 확정할 수 없다. 이번 산출물은 기획 문서이며 구현·빌드·에뮬레이터 시험은 하지 않았다.
- 공통 구상: Pleos 차량용 Android 앱의 로컬 카드·메모와 명시적 사용자 확인을 기본으로 한다. 휴대폰으로 이어지는 화면은 별도 구현이 필요한 가정이다. 생체·감정·고양이 감지, 병원 대기열 API, 차량 전체 음량 제어를 가정하지 않는다.
- 기술 범위: 다섯 공개 SDK는 공모전 개발에 사용 가능하다. Gleo 승인·Pleos LLM SDK·차량 마이크의 외부 STT 전송을 전제하지 않는다. 모든 아이디어에서 보호자가 고양이와 함께하며, 고양이를 차에 혼자 남기는 흐름은 없다.

## 1. 진료실 앞 책갈피

- **이름:** 진료실 앞 책갈피. 길 안내가 끝난 순간부터 병원 문을 통과할 때까지의 짧은 인계 메모.
- **한 줄과 장면 · 가설:** 병원 앞에 주차한 보호자가 “어느 입구로 가고, 접수에는 무엇을 말하지?”를 다시 찾지 않도록, 도착 전에 정한 입구·연락 방식·준비물을 한 장으로 이어 준다.
- **차에서 할 이유 · 해석:** 내비게이션의 도착과 실제 진료실 입실 사이에 공백이 생긴다. 차량 화면에서 목적지와 주차 메모를 묶고 휴대폰으로 넘기면, 이동장을 든 뒤 재검색하는 불편을 줄일 수 있다는 가설이다.
- **SDK·외부 데이터 가정:** [NaviHelper 목적지·이벤트](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/event-listeners)를 사용하고, [FusedLocation](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/location-data-access)은 선택적으로 주차 위치를 저장한다. 위치가 없거나 오래됐으면 수동 입력한다. 입구·연락 규칙은 보호자가 병원에 미리 확인해 입력하며, 휴대폰 인계용 QR 화면은 별도 기능이다.
- **작은 시연 · 계획:** 가상 병원 경로 도착 → 사용자가 적절한 환경에서 정차했음을 확인 → “보호자와 함께 차에서 대기 / 입구 B / 준비되면 병원에서 전화”라는 수동 메모 표시 → QR로 휴대폰에 옮김 → 사용자가 입실 완료 표시. 실제 전화·병원 시스템 연동은 시연 범위에 넣지 않는다.
- **약점·검증 질문:** 병원의 대기 방식이 다르거나 자주 바뀌는데, 보호자가 입력한 세 줄이 일반 메모 앱보다 실제 입실을 편하게 만들까?
- **문제 근거 · 확인된 사실:** FelineVMA의 보호자 안내는 대기실에서 불안해하거나 개가 있는 경우 진료실 입실을 요청하고, 준비되지 않았다면 적절한 냉난방 아래 고양이와 차에서 기다린다고 접수처에 알린 뒤 준비되면 전화해 달라고 요청하는 방식을 설명한다.[S2] 이것은 병원과 사전 조율할 상황의 근거이며 앱 수요나 효과의 증거는 아니다.

## 2. 사서 고양이의 무음 도서관

- **이름:** 사서 고양이의 무음 도서관. 차 안에서 가장 조용한 직원은 고양이라는 엉뚱한 독서 앱.
- **한 줄과 장면 · 가설:** 보호자가 고양이와 함께 정차 대기하는 동안, 차 화면에 직접 쓴 짧은 소설 한 쪽과 “사서님은 휴식 중”이라는 작은 도장을 띄운다. 소리·점수 경쟁 없이 페이지를 덮으면 자동 책갈피만 남긴다.
- **차에서 할 이유 · 해석:** 병원의 전화를 기다리며 고양이 곁을 지키는 짧고 끊기는 대기에 맞춘다. 큰 글씨와 한 번에 닫히는 화면이 차량의 공동 공간에서 쓸모 있을 수 있지만, 운전자 독서는 사용자가 확인한 정차 상황에만 제안한다.
- **SDK·외부 데이터 가정:** [NaviHelper](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro)의 목적지·도착 이벤트로 해당 병원의 책갈피를 찾는다. 도착 이벤트를 정차 판정으로 쓰지 않는다. 소설은 직접 작성하거나 이용 권리를 확보하며, 앱 자체가 음성을 내지 않는 설계다. 다른 앱·내비 음성을 끄는 권한은 가정하지 않는다.
- **작은 시연 · 계획:** 가상 병원 도착 → 정차·동반 대기 수동 확인 → 8문장짜리 소설 표시 → “사서님 휴식 중” 도장 → 병원 연락을 받은 보호자가 닫기 → 다음 대기 때 같은 문장부터 재개. 주행 중 읽기·자동 안정 판정은 시연하지 않는다.
- **약점·검증 질문:** 휴대폰으로도 가능한 독서에 차량 화면을 쓰면, 고양이를 살피거나 병원 연락을 받는 일을 더 번거롭게 만들지는 않을까?
- **문제 근거 · 확인된 사실과 유추:** 보호자 안내는 이동장 위 수건이 낯선 시각 자극과 소리를 줄이는 데 도움이 된다고 설명한다.[S2] 여기서 “대기 앱 자체도 소리를 더하지 말자”는 설계 원칙을 유추했다. 독서나 무음 UI가 고양이의 스트레스를 줄인다는 연구 결과를 확보한 것은 아니다.

## 3. 캐리어 반납대

- **이름:** 캐리어 반납대. 병원에서 돌아온 날을 다음 이동 준비의 시작으로 표시하는 차량 속 반납 카드.
- **한 줄과 장면 · 가설:** 집에 도착하자마자 이동장을 다시 창고에 넣기 쉬운 보호자에게, “생활공간에 둘 자리”와 다음 번 준비 메모를 정차 화면에서 한 번 보여 준다. 실제 배치와 선택은 보호자가 결정한다.
- **차에서 할 이유 · 해석:** 병원 왕복이 끝나는 순간은 사용한 이동장과 담요가 아직 차에 있어 기억을 행동으로 옮기기 쉬운 시점일 수 있다. 앱은 이동 중 기록이 귀가 후 생활공간으로 이어지는 매듭 역할을 맡는다.
- **SDK·외부 데이터 가정:** [NaviHelper 목적지 도착 이벤트](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/event-listeners) `onDestinationArrived`와 사용자가 지정한 “귀가” 목적지를 연결한다. 선택적 [FusedLocation 근접 알림](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/location-data-access)은 권한·지원 확인이 필요하며 항상 작동하는 알림을 약속하지 않는다. 집 위치와 메모는 로컬 저장하고 자동으로 집 안 행동을 관찰하지 않는다.
- **작은 시연 · 계획:** 보호자가 “이동장을 둘 자리: 거실 구석”을 입력 → 가상 귀가 목적지 도착 → 사용자가 정차 확인 → 반납 카드와 “다음엔 담요 위치 확인” 메모 표시 → 사용자가 나중에 완료 표시. 고양이가 이동장에 익숙해졌는지는 채점하지 않는다.
- **약점·검증 질문:** 귀가 화면의 한 번짜리 카드가 집 안의 행동으로 이어질까, 아니면 보호자가 곧바로 닫는 반복 알림이 될까?
- **문제 근거 · 확인된 사실과 가설:** FelineVMA의 2025 입장문은 이동장에 익숙해지게 하는 준비를 권고하고 내원 경험이 집에서 시작된다고 설명한다.[S1] 보호자 안내는 이동장을 고양이가 자주 머무는 공용공간에 두고 익숙해지는 준비를 하도록 설명한다.[S2] 귀가 때 이를 떠올리게 하자는 시점 선택과 앱의 도움 정도는 검증하지 않은 가설이다.

## 검증 경계와 다음 확인

- 문제 근거는 공식 수의학 단체의 입장문·보호자 안내다. 위 앱에 대한 임상 시험, 사용자 인터뷰, 수요 조사, 시장 최초·수익 근거는 확보하지 않았다. 자료 속 권고를 앱의 치료·안전 효과로 바꾸지 않았다.
- 구조는 로컬 카드·사용자 확인·선택적 휴대폰 인계라는 계획이다. SDK 사용 가능 여부는 기존 정적 리뷰를 기준으로 삼았다. 2026-11-11 공식 이벤트 문서를 직접 열어 `onDestinationArrived`와 경로 탐색 완료인 `onRoutingCompleted`의 구분을 확인했다. 이벤트 제공은 Navigation 앱 구현에 좌우되며 정차 판정도 별도다. SDK 실행·새 릴리즈 비교·인증·센서·오디오·위치·화면 제한은 확인하지 않았다.
- 후속 검증에서는 보호자가 실제로 겪는 입실 공백, 독서의 방해 정도, 귀가 카드의 행동 연결을 각각 확인해야 한다. 병원 정책·휴대폰 인계 구현·정차 상태 검증은 열린 제품·기술 질문이다.
- 갱신할 때는 [SDK 리뷰](../../pleos-sdk-review.md)와 [SDK 목차](../../../sdk/README.md)를 먼저 읽고 이 파일의 근거·가설·실행 한계를 함께 고친다. 이 파일은 P07의 독립 발산 기록이며 다른 페르소나의 결과를 합치지 않았다.
