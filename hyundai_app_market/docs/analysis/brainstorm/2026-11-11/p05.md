# P05 · 조부모를 만나러 가는 대학원생의 첫 발산

- 작성일: 2026-11-11 KST, Asia/Seoul.
- 가상 페르소나: 주말마다 조부모를 방문하는 대학원생. 반복 장거리 운전, 가족 안부, 선물에 관심이 있고 오디오북을 즐긴다. 사람 사이의 어색함을 줄이는 관찰자의 관점으로 발상했다. 실제 인터뷰 대상이 아니다.
- 범위: 서로 다른 차량 앱 아이디어 3개. 아래 장면과 불편은 페르소나에서 만든 가설이며, 공식 자료가 한국 가족의 수요나 앱의 효과를 입증하지는 않는다. 다른 페르소나 산출물은 읽지 않았다.
- 기준: 프로젝트 [AGENTS.md](../../../../AGENTS.md), [공모전 조사](../../hyundai-vehicle-app-contest-2026.md), [출처 기록](../../hyundai-vehicle-app-contest-2026-sources.md), [SDK 리뷰](../../pleos-sdk-review.md), [SDK 목차](../../../sdk/README.md)와 NaviHelper·TTS·STT 노트를 읽었다. 프로젝트 루트에 `.git`은 없고, 루트 항목은 `docs/`와 `AGENTS.md`였다. 기존 앱 구현이나 테스트 통과를 전제하지 않았다.

## 1. 질문 한 개 싣고 가기

- **한 줄:** 방문 전 차 안에서 관심사에 맞는 질문 한 개와 후속 질문 한 개를 골라, 문 앞에서 안부가 끊기는 순간을 준비하는 앱.
- **구체 장면:** 매주 “밥 잘 드셨어요?” 뒤에 휴대폰을 보게 되는 대학원생이 휴게소에 주차한 뒤 “할아버지의 화분”을 고른다. 앱은 “이번 주 새잎이 난 화분이 있어요?”와 “물을 얼마나 주셨어요?”를 읽어주고, 대학원생은 자기 말투로 바꿔 한 번 말한다. 실제 방문에서는 상대가 다른 이야기를 시작하면 질문 카드를 버린다.
- **차에서 할 이유:** 반복되는 방문 경로가 대화를 준비할 계기다. 내비의 해당 목적지 경로 시작을 계기로 이번 방문용 카드를 보관하고, 주차 후 한 번만 연습한다. 차량 화면과 음성으로 방문 직전 준비를 마치는 가치가 있다는 가설이다.
- **SDK·외부 가정:** [NaviHelper](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro)의 경로·목적지 이벤트, [TTS](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro)의 문장 낭독, [STT](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/intro)의 선택·짧은 연습을 사용한다. 관심사는 사용자가 직접 고르고 질문은 앱에 넣은 문구에서 고른다. 대화 평가용 LLM, 조부모의 대화 녹음, 오디오북 서비스 계정 연동은 필요 없다.
- **작은 시연:** 가상 목적지 선택 → 경로 연결 결과 표시 → 사용자가 주차를 확인하고 관심사 선택 → TTS가 질문 두 개 낭독 → 사용자가 “이 질문으로”라고 선택 → 도착 후 기억할 한 문장 표시. 내비 이벤트만으로 주차를 판정하지 않는다.
- **약점·검증 질문:** 준비한 질문이 면접처럼 들릴 수 있다. 실제 방문자에게 카드 한 개를 주었을 때 자발적인 후속 대화가 생기는가, 아니면 대본을 읽는 부담이 늘어나는가?
- **불편의 근거:** [NIA, *Participating in Activities You Enjoy As You Age*](https://www.nia.nih.gov/health/healthy-aging/participating-activities-you-enjoy-you-age), 본문 검토일 2022-03-28, 열람 2026-11-11. 나이가 들며 집에 혼자 있는 시간이 늘어날 수 있다고 설명하고, 취미와 가족·친구와의 활동을 제안한다. 이는 관계를 이어갈 활동의 필요성을 뒷받침한다. 가족 대화가 실제로 자주 끊긴다거나 질문 연습이 효과적이라는 증거는 아니다.

## 2. 우주선 가족위원회

- **한 줄:** 방문길에 시작한 짧은 우주 라디오극의 마지막 결정을 조부모 집 식탁에서 함께 내리는, 일부러 엉뚱한 오디오북.
- **구체 장면:** “우주선 식량 담당 할머니가 마지막 감자 세 개를 지켜라”라는 90초짜리 이야기를 휴게소 주차 중 듣는다. 손자는 감자를 심겠다고 고르지만 결말은 잠겨 있다. 도착해 할머니에게 “선장님, 먹을까요, 심을까요?”라고 묻고 가족이 결말을 고른다. 실제 건강·재산·가족 갈등은 소재로 쓰지 않는다.
- **차에서 할 이유:** 반복 장거리 여행의 시작과 방문 완료가 한 이야기의 앞뒤가 된다. 차량에서 프롤로그를 듣고 다음 장소로 결말을 가져가는 경험이다. 운전자에게 주행 중 답변을 재촉하거나 도착 제한시간 경쟁을 시키지는 않는다.
- **SDK·외부 가정:** [TTS](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro)로 자체 작성한 분기 대본을 읽고, [NaviHelper](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro)로 방문 경로와 이야기를 연결한다. 성우 흉내·다중 캐릭터 음색 지원은 가정하지 않는다. 저작권을 확보한 자체 대본과 고정 선택지만으로 시작한다. 결말 카드의 휴대폰 QR 전송은 별도 웹 페이지·통신·접근 통제가 필요한 확장 가설이며 SDK 기본 기능이 아니다.
- **작은 시연:** 주차 확인 → 자체 대본 한 편 재생 → 두 선택 중 하나 보관 → 경로 완료 뒤에도 주차를 다시 확인 → 식탁용 결말 코드 표시 → 별도 휴대폰 목업에서 가족이 선택. 시연에서는 차량 화면의 카드만으로도 결말을 보여줄 수 있다.
- **약점·검증 질문:** 어린아이 취급으로 느껴질 수 있고 휴대폰 오디오 콘텐츠로도 가능하다. 조부모가 이야기의 결정권을 갖는 설정을 즐기는지, 다음 방문에도 결말을 기다리는지 확인해야 한다.
- **불편의 근거:** [NIA, 같은 활동 안내](https://www.nia.nih.gov/health/healthy-aging/participating-activities-you-enjoy-you-age), 본문 검토일 2022-03-28, 열람 2026-11-11. 가족·친구와 게임하기, 책·영화 모임, 손주에게 놀이 가르치기를 활동 예시로 제시하고 활동이 스트레스가 되어서는 안 된다고 설명한다. 함께 할 소재를 마련한다는 발상의 근거이며, 우주극 수요나 외로움 감소 효과의 근거는 아니다.

## 3. 반찬 입국심사

- **한 줄:** 선물과 반찬을 차에 싣는 순간부터 상대 집 냉장고에 넣을 때까지, 음식의 인계가 끝났는지 확인하는 왕복 방문 앱.
- **구체 장면:** 손자는 선물 케이크를 싣고 출발하고, 귀가할 때는 조부모가 싸준 국과 반찬을 싣는다. 출발 전 “냉장 필요한 것 두 개, 보냉 준비 확인”을 읽고, 도착 후 인사나 짐 정리에 밀리지 않게 “냉장할 음식부터 내려주세요”를 한 번 알린다. 선물을 거절하기 어색할 때는 출발 전에 보관 공간과 운반 준비를 직접 확인하게 한다.
- **차에서 할 이유:** 음식이 차량 안에 있는 운반 구간과 내비 목적지 변경을 함께 다룬다. 휴게소 경유나 목적지 변경이 생기면 음식 목록이 남아 있음을 알리고, 도착 뒤 냉장 인계까지 사용자가 마쳐야 방문 짐 목록이 닫힌다. 차량 밖 부엌까지 이어지는 경험이다.
- **SDK·외부 가정:** [NaviHelper](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro)의 경로·목적지 변경 이벤트와 [TTS](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro) 알림을 사용한다. 음식 종류·차에 실은 시각·보냉 여부는 수동 입력한다. Vehicle이 음식 내부 온도나 보냉함 온도를 준다고 가정하지 않는다. 식품 센서, 냉장고 연동, 가족 메시지 발송은 별도 연동이며 최소 시연에 없다.
- **작은 시연:** 주차 중 냉장 필요 음식 두 개 등록 → 출발 전 운반 준비 확인 → 모의 경유지 추가 시 목록 유지 → 도착·주차 확인 후 하차 알림 → 실제 음식 모형을 내려놓고 “인계 완료” 선택. 음식의 잔여 안전시간이나 섭취 가능 판정은 표시하지 않는다.
- **약점·검증 질문:** 센서가 없어 사용자가 입력·완료 표시를 잊을 수 있다. 이 확인이 기존 메모보다 유용하고, 조부모가 싸준 음식을 감사히 받는 대화를 방해하지 않는가?
- **불편의 근거:** [FDA, *Refrigerator Thermometers - Cold Facts about Food Safety*](https://www.fda.gov/food/buy-store-serve-safe-food/refrigerator-thermometers-cold-facts-about-food-safety), 본문 기준일 2024-03-05, 열람 2026-11-11. 냉장이 필요한 구입 식품과 남은 음식을 신속하게 냉장하고, 식료품을 차량 안에 필요 이상 오래 두지 말라고 안내한다. 음식 운반 뒤 보관 행동까지 확인할 이유를 뒷받침하지만, 이 앱이 식중독을 예방한다는 검증 결과는 없다.

## 공통 구현 경계와 실제 확인 범위

세 아이디어는 모두 **Pleos 차량 앱에 대한 서비스 가설**이다. 공통 구조는 사용자 선택 → 차량 내비 이벤트·음성 서비스 → 앱의 로컬 상태 → 주차 후 행동 확인이다. 앱 코드, 가족 수요 검증, 빌드, 에뮬레이터 호출, 실차 시험은 이번에 실행하지 않았다. 우선 검증할 것은 가족의 자발적 참여, 차량에서 준비할 가치, 해당 환경의 권한·음성·내비 이벤트 동작이다.

[공모전 개발 범위 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)는 2026-11-11 원문을 다시 읽었다. Vehicle·NaviHelper·TTS·STT·FusedLocation 다섯 SDK는 공모전 에뮬레이터 개발에 사용할 수 있다. Gleo 승인 신청, Pleos LLM SDK, 차량 마이크의 외부 STT 전송은 범위에 넣지 않는다. 음성은 Pleos SDK의 ON_DEVICE 우선 가정이며, 엔진 지원과 실제 권한은 미확인이다. 서버 모드 사용 시 별도 등록·인증이 필요하다. 휴대폰 연동과 외부 서비스 연결은 공개 SDK가 자동으로 제공하는 기능으로 보지 않는다.

실제 조사에서는 `agbrowse fetch <URL> --json --browser never`로 NIA·FDA 원문 전체를 읽었고 두 응답 모두 HTTP 200·`strong_ok`·본문 잘림 없음이었다. `agbrowse search --verify`로 공모전 공지 본문을 읽었으며 응답은 `weak_ok`였다. 웹 도구에서도 NaviHelper 공식 소개의 기능·비동기 이벤트 범위를 읽었다. NIA의 웹 도구 열람은 405로 실패했지만 직접 HTTP 읽기로 보완했다. USDA 후보는 접근이 차단되어 근거에 쓰지 않았다. 제품 효과, 한국 가족의 선호, 제휴·권리 확보, 외부 데이터 제공 조건, 계정별 허가, 음성 인식률과 주행 중 사용성은 미검증이다.
