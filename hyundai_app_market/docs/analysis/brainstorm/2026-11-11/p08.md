# P08 독립 발산: 첫 차를 산 게임 좋아하는 사회초년생

- 작성일: 2026-11-11 KST, Asia/Seoul.
- **가상 페르소나**: 자동차를 처음 산 사회초년생. 초행길·주차·차량 경고가 낯설고, 쓸모없어 보여도 재미있으면 시험하는 발명가 관점이다. 실제 인터뷰나 특정 사용자의 진술이 아니다.
- 목적·범위: Pleos 차량 앱 아이디어 정확히 3개를 자유롭게 제안한다. 다른 페르소나의 아이디어·파일은 읽지 않았다. 수요·시장 최초·안전효과를 입증한 문서가 아니다.
- 소스 기준: 프로젝트 `AGENTS.md`, 공통 분석 정책, 2026-11-11 공모전 보고서·출처 목록, `pleos-sdk-review.md`, `docs/sdk/README.md`와 다섯 SDK 노트를 읽었다. 작업 시작 시 `.git`과 이 파일은 없었다. 앱 코드·실행 상태를 새로 감사하지 않았다.
- 공통 설계 가정: 아래 흐름은 전부 제안이다. 차량 앱의 로컬 카드·메모를 기본으로 하고, 사용자 확인을 거쳐 내비게이션이나 휴대폰 QR 화면으로 이어 간다. 게임 조작·퀴즈·QR·긴 설명은 정차 중에만 제공하며 정차 판정 방법과 화면 정책은 구현 전에 확인해야 한다.
- SDK 경계: 다섯 공개 SDK의 공모전 사용 허용은 [공식 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)를 확인한 [종합 리뷰](../../pleos-sdk-review.md)를 따른다. Gleo 승인·Pleos LLM SDK·차량 마이크의 외부 STT 전송을 전제하지 않는다. 차량 원격제어·정비진단·카메라 장애물 감지·주행 채점도 전제하지 않는다.

## 1. 세이브포인트: 내 차를 지키는 슬라임
- **한 줄·장면**: 낯선 지하주차장에서 내리기 직전 “B3, 보라 기둥, 42번”을 남기면 슬라임이 그곳을 자기 집으로 삼는다. 휴대폰에서 슬라임의 집 카드를 열어 차를 찾는 엉뚱한 주차 메모 게임이다.
- **차에서 해야 할 이유**: 주차를 끝낸 바로 그 순간에 차량 위치·메모를 묶는다. 내려서 앱을 따로 여는 일을 줄일 수 있다는 가설이며, 차량 화면에는 QR과 저장 결과만 보여 준다. 펫 성장에는 운행거리·속도·추가 이동을 보상하지 않는다.
- **SDK·외부 데이터 가정**: [FusedLocation 위치 접근](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/location-data-access)으로 마지막 위치와 시각을 확인하고, 선택적으로 [Pleos STT](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/intro) ON_DEVICE로 메모를 받는다. 지하 층수·주차면은 사용자가 입력한다. QR은 좌표·메모를 담는 별도 휴대폰 페이지 연결 가정이며 SDK 제공 기능으로 보지 않는다.
- **작은 시연 흐름**: 에뮬레이터 위치를 표시 → 정차 화면에서 “B3 보라 42”를 입력 → 저장된 좌표의 시각·메모 확인 → QR을 휴대폰으로 열기 → 슬라임 카드에서 같은 메모 읽기. 좌표가 없으면 “좌표 없음”과 메모만 저장한다. 실내 보행 길찾기는 시연 범위에 넣지 않는다.
- **약점·검증 질문**: 휴대폰에도 주차 저장이 있는데 차에서 QR까지 여는 흐름을 쓸까? 지하 위치 오차와 만료 없는 QR의 노출도 확인해야 한다. 비교 실험에서는 메모를 남기는 시간과 실제 재사용 여부만 보고, 길찾기·안전 개선을 추정하지 않는다.
- **실제 불편 근거와 가설 구분**: [S1]은 주차한 곳을 다시 찾기 위해 위치를 저장하고 층수·잔여시간 메모를 추가할 수 있다고 안내한다. 이는 주차 후 기억 보조가 실제 공식 서비스의 사용 과제라는 근거다. 초보 차주에게 특히 심하거나 슬라임이 기록 습관을 높인다는 주장은 아직 가설이다.

## 2. 경고등 도감: 처음 만난 디버프 카드
- **한 줄·장면**: 처음 본 노란 표시를 정차 후 도감에서 고르면 해당 차종 매뉴얼의 의미·확인할 조건·안내 행동을 한 장으로 보여 준다. 가상의 “디버프 카드”는 별명과 수집 재미만 담당하고, 실제 경고는 매뉴얼 명칭으로 표시한다.
- **차에서 해야 할 이유**: 눈앞의 계기판과 설명을 같은 자리에서 대조할 수 있다. 휴대폰 검색창에 아이콘 모양을 문장으로 묘사하는 대신 정차한 차에서 표시를 고른다. 경고 발생 중에는 수집 연출·퀴즈를 숨기고 매뉴얼 안내를 먼저 표시한다.
- **SDK·외부 데이터 가정**: 최소안은 사용자가 아이콘·점등/점멸을 직접 고른다. [Vehicle Capability](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/check-capability)에서 관련 상태의 읽기 지원이 실제 확인될 때만 선택을 보조한다. [TTS](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro)는 검수된 문구를 읽는다. 차종·연식·판매지역에 맞는 공식 매뉴얼 매핑과 콘텐츠 이용 조건이 별도로 필요하다.
- **작은 시연 흐름**: 시연용 차종·연식을 명시 → “타이어 표시” 선택 → 사용자가 “계속 켜짐/한동안 깜박인 뒤 켜짐/잘 모르겠음” 선택 → 서로 다른 매뉴얼 항목과 원문 링크 표시 → 모르겠으면 임의 진단 없이 원문 확인 경로 표시. 여기서 차량 상태를 고치거나 고장을 확정하지 않는다.
- **약점·검증 질문**: 초보자가 표시와 점멸 방식을 정확히 고를 수 있을까? 맞는 매뉴얼을 못 찾거나 복합 경고를 놓치면 잘못된 확신을 줄 수 있다. 첫 검증은 소수의 검수된 카드에서 아이콘 식별과 원문 대응의 정확성을 확인하는 것이다.
- **실제 불편 근거와 가설 구분**: [S2]는 저압 경고와 TPMS 이상에서 점등 방식이 다르며, 표시의 모양·위치는 차량 사양과 소프트웨어에 따라 달라질 수 있다고 설명한다. 따라서 아이콘 하나만 보고 뜻을 확정하기 어려운 조건이 문서에 존재한다. 한국 초보운전자의 오해 빈도나 이 앱의 이해 개선은 측정하지 않았다.

## 3. 보스 입구 공략집: 건물 핀 옆의 차량 출입구
- **한 줄·장면**: 처음 가는 회사나 공연장에서 “방문객 차량은 후문으로”라는 공략 카드를 출발 전에 꽂는다. 건물 정문과 차량 출입구를 별도 장소로 보여 주고, 확인한 차량 출입구를 내비 목적지로 보낸다.
- **차에서 해야 할 이유**: 차량이 향할 목적지를 정하는 자리에서 출입구 정보를 확인한다. 목적지 시설의 안내를 출발 전에 한 번 읽고, 차 밖에서는 같은 QR 카드로 주차 후 걸어갈 출입구·접수처 메모를 이어 본다. 주행 중 미니게임이나 임의 차선 지시는 하지 않는다.
- **SDK·외부 데이터 가정**: [NaviHelper Destinations](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/destinations)에 사용자가 확인한 출입구 좌표를 요청한다. 시설 공식 안내 또는 시설 담당자가 입력한 좌표·사진·확인일이 필요하며, 자동 수집 API나 실시간 개방 정보가 있다고 가정하지 않는다. 안내문 TTS는 선택 사항이다.
- **작은 시연 흐름**: 가상의 행사장 카드 한 장 준비 → “건물 정문/방문객 차량 입구” 두 좌표와 데이터 제공자를 표시 → 사용자가 차량 입구 선택·확인 → 내비 경로 요청의 성공/실패 이벤트 표시 → 정차 후 QR로 “주차장 A출구에서 접수처” 메모 열기. 시설 자료와 에뮬레이터 좌표는 모의 데이터로 표시한다.
- **약점·검증 질문**: 시설이 정확한 입구 좌표와 변경일을 유지할까? 잘못된 좌표는 오히려 우회를 만들 수 있다. 공식 안내가 있는 시설 한 곳에서 정문 핀과 차량 입구가 실제로 구분되는지 먼저 확인하고, 최신성이 없으면 자동 경로 전송을 제공하지 않는 기준이 필요하다.
- **실제 불편 근거와 가설 구분**: [S1]은 출발 전 주차 장소 찾기와 도착 후 주차 위치 저장을 별도 과제로 안내한다. 차량 도착에 주차 정보가 별도로 필요하다는 좁은 근거로만 사용한다. “정문으로 잘못 가는 초보 차주가 많다”와 “공략 카드가 우회를 줄인다”는 추가 현장 확인이 필요한 가설이다.

## 검증 기록과 남은 범위

- 실행한 확인: `Test-Path`로 `.git`과 대상 파일이 없음을 확인했다. SDK·공모전 기존 보고서와 관련 노트를 읽고, S1·S2 및 SDK 링크 본문을 웹 도구로 열었다. `agbrowse search --verify ... --browser never`에서 S2는 `strong_ok`, S1은 `blocked`였다. S1은 웹 원문 열기로 본문을 확인했으며 agbrowse 성공으로 기록하지 않는다. 공모전 공지의 이번 웹 재열기는 Internal Error여서 같은 날 종합 리뷰의 공식 확인 기록을 사용했다.
- 구현 상태: 이 문서 외에 앱·휴대폰 페이지·서버·QR 동기화·콘텐츠 DB를 만들지 않았다. 빌드·에뮬레이터·실차·음성·위치·내비 호출·Vehicle Capability는 실행하지 않았다.
- 검증 우선순위: 먼저 필요한 SDK의 최소 호출과 정차 UI 정책을 확인한다. 그다음 각 아이디어의 위 질문을 관찰로 검증한다. 위치·QR 접근권한·매뉴얼 이용권·시설 데이터 최신성도 구현 전에 확인한다. 이번 발산에서는 후보를 점수화하거나 구현안을 확정하지 않는다.
- 이 파일은 독립 초안이다. 이후 종합 보고서에서 사용할 때 작성일·출처·SDK 노트를 먼저 읽고 새 근거로 해당 가설을 갱신해야 한다.
