## 1. 트렁크 빨래 리그

- **한 줄 제안:** 경기의 마지막 득점을 ‘내 유니폼이 다음 경기 전에 돌아오는 일’로 바꾸는 차량 중심 세탁 인계 장부다.
- **장면:** 원정 경기 후 개인별 이름표를 붙인 유니폼 봉투 3개와 공용 조끼 봉투를 차에 싣는다. 세탁 담당자가 차 밖에서 인수하고, 다음 모임에서 돌려준다. 축구 점수처럼 보이는 ‘3개 인계, 1개 미확인’ 표시가 장난스러운 요소다.
- **차량에서 할 이유:** 여러 사람의 물건이 한 차량에 모였다가 다시 갈라지는 순간이 인계 기록의 기준점이다. 차량 위치와 내비 경유지를 봉투별 목적지에 연결하고, 문 열림 이벤트는 인계 확인을 제안하는 계기로만 쓴다. 문 상태로 적재물의 존재나 수량을 감지했다고 표시하지 않는다.
- **SDK·외부 가정:** NaviHelper 3.0.5로 세탁 담당자 인계 장소를 경유지로 요청하고 FusedLocation 1.1.3으로 도착 장면을 보조한다. Vehicle 2.3.2의 지원되는 문 상태는 Capability와 읽기 권한을 확인한 뒤 선택적으로 쓴다. 차량 카메라·무게센서는 가정하지 않는다. 휴대폰의 봉투 QR 확인·공유 장부는 별도 웹·서버 연동 가설이며 세탁업체 제휴는 없다.
- **작은 시연 흐름:** 정차한 에뮬레이터에서 봉투 3개 등록 → 인계 장소 1곳을 내비에 요청 → 위치·문 이벤트를 시험 입력 → 사람이 ‘2개 전달’을 확인 → 미확인 봉투 1개를 남긴다. 차 밖 수령 화면은 모의 화면이라고 표시한다.
- **근거·추론:** [CDC 운동선수 위생 안내 E1](https://www.cdc.gov/mrsa/prevention/athletes.html)는 사용 후 유니폼·수건·의복의 세탁·완전 건조를 권한다. [난지천 이용수칙 E2](https://yeyak.seoul.go.kr/web/reservation/selectReservView.do?rsv_svc_id=S120423174310156240)는 경기 후 반입 물품과 쓰레기의 회수를 요구한다. 여기서 후속 정리 업무가 존재함을 읽었다. 공동 세탁 인계 앱의 필요성과 분실 감소 효과는 서비스 가설이다. 개인 의복은 소유자를 구분하고, 앱이 세탁·위생 상태를 인증하지 않는다.
- **약점·첫 검증 질문:** 봉투 등록이 차량 담당자의 일을 더 늘릴 수 있다. 실제 모임에서 한 경기만 수동 장부와 비교했을 때, 봉투 등록보다 인계 확인에 드는 수고가 더 줄어드는가?

## 2. 귀가 역전골

- **한 줄 제안:** 경기 전에 ‘누구를 태울까’보다 ‘운전자는 몇 시에 해산할까’를 먼저 정하고, 동승자를 합의한 환승 거점까지 데려다주는 귀가 약속 앱이다.
- **장면:** 22시에 원정 경기가 끝난다. 정차한 차에서 동승자 3명과 운전자가 ‘A역 2명, B역 1명, 운전자 해산 목표’를 함께 확인한다. 집 주소를 전원에게 공유하는 대신 각자의 하차 거점만 공유한다.
- **차량에서 할 이유:** 합의한 귀가 계획이 차량 내비의 실제 경유지가 되어야 한다. 승객 수동 하차 확인과 차량의 현재 위치를 같은 화면에 연결하고, 계획이 늦어지면 다음 정차 때 귀가 약속을 다시 결정한다. 휴대폰에서 따로 합의한 목적지를 운전자가 다시 입력하는 단계를 줄이려는 제안이다.
- **SDK·외부 가정:** NaviHelper 3.0.5로 합의한 최대 2개 경유지와 최종 목적지를 요청하고 FusedLocation 1.1.3으로 위치를 보조한다. SDK가 다인승 배차·귀가 최적화·대중교통 환승 계산을 제공한다고 가정하지 않는다. 서울교통공사 시간표 API는 별도 인증·연동 대상이다. 첫 범위는 환승 없는 직통 귀가와 사람이 고른 승하차 가능 거점으로 제한하며, 시간표만으로 막차 탑승이나 귀가를 보장하지 않는다.
- **작은 시연 흐름:** 경기 종료 후 정차 상태 → 동승자 3명과 거점 2개 선택 → 날짜·방향이 표시된 모의 열차 시간표 확인 → 운전자 최종 확인 → 두 경유지를 내비로 전달 → 도착 이벤트와 실제 하차 확인을 구분해 표시한다.
- **근거·추론:** [난지천 야간 운영 E2](https://yeyak.seoul.go.kr/web/reservation/selectReservView.do?rsv_svc_id=S120423174310156240)는 22시까지의 야간 이용을 안내한다. [서울교통공사 막차 시간표 E3](https://data.seoul.go.kr/dataList/OA-110/A/1/datasetView.do)는 역별 시간표를 제공하면서 실제 도착시간과 다를 수 있음을 명시한다. 늦은 운동과 시간 제약이 있는 교통수단을 연결한 문제 설정이며, 동호회 차량 담당자에게 부담이 집중된다는 빈도·규모는 조사하지 않았다.
- **약점·첫 검증 질문:** 하차 거점에서부터의 이동이 동승자에게 불편할 수 있다. 실제 모임에서 동승자가 거점 하차를 받아들이면서도 운전자의 합의한 해산시간을 지킬 수 있는가?

## 3. 우천취소 환전소

- **한 줄 제안:** 축구가 취소되면 이미 모인 시간을 근처 실내 문화 원정으로 바꾸고, 차에서 고른 짧은 관람 미션을 차 밖에서 완성한다.
- **장면:** 비 때문에 구장 관리자가 이용 불가를 알렸지만 팀원들은 이미 차에 모였다. ‘오늘은 공 대신 가장 둥근 전시물 찾기’ 같은 고정 미션을 고르고, 박물관·전시공간 등 확인된 대안 장소로 이동한다. 무작위 결과는 사전 확인한 후보 안에서만 나온다.
- **차량에서 할 이유:** 차가 원래 목적지를 향해 움직인 뒤 벌어진 취소에 대응한다. 이미 모인 동승자, 차량의 현재 위치, 남은 모임 시간을 한 번에 다루고 대안 장소를 실제 내비 목적지로 바꾸는 전환점이 된다. 미션 수행과 결과 확인은 차량 밖으로 이어진다.
- **SDK·외부 가정:** FusedLocation 1.1.3으로 현재 위치를 받고 NaviHelper 3.0.5로 선택한 대안 목적지를 요청한다. TTS 3.3.1의 ON_DEVICE 모드는 고정 미션 한 문장을 읽는 선택 기능이며 엔진 지원은 미검증이다. 서울시 문화공간 데이터의 위치·관람시간·휴관일은 후보를 거르는 자료다. 실시간 입장 가능·단체 수용·주차·예약·취소 API는 확보하지 않았으며 담당자가 별도로 확인한다. 구장 취소는 사람이 입력하며 날씨만으로 자동 취소·환불하지 않는다.
- **작은 시연 흐름:** 정차한 에뮬레이터에서 ‘관리자 취소 확인’ 입력 → 미리 확인한 실내 후보 3개와 데이터 확인시각 표시 → 동승자가 ‘미술관, 40분’ 선택 → 고정 미션 1개 제시·선택적 음성 재생 → 내비 목적지 변경 → 차 밖 미션 완료는 모의 휴대폰 화면으로 구분한다.
- **근거·추론:** [난지천 시설 안내 E2](https://yeyak.seoul.go.kr/web/reservation/selectReservView.do?rsv_svc_id=S120423174310156240)는 폭우·폭설로 사용이 불가능할 수 있고, 미세먼지 비상저감조치 때 제한·중단될 수 있다고 안내한다. [서울시 문화공간 정보 E4](https://data.seoul.go.kr/dataList/OA-15487/A/1/datasetView.do)는 위치·관람시간·휴관일 등의 공개 데이터를 설명한다. 취소 발생 가능성과 대안 후보 데이터의 존재가 근거다. 축구팀이 문화 원정을 원한다는 직접 근거는 없으며, 이는 의외성을 실험하는 서비스 가설이다.
- **약점·첫 검증 질문:** 운동을 못한 사람은 다른 활동보다 귀가를 원할 수 있다. 이미 모인 성인 축구팀에서 ‘바로 귀가’와 ‘40분 실내 원정’을 함께 제시하면 대안 모임에 실제로 참여할 사람이 있는가?

- 웹 원문 열람: E1~E4, 공모전 공지, 위 SDK 문서를 확인했다. 공모전 공지는 웹 도구에서 열리지 않아 `agbrowse search --verify ... --json --browser never`의 직접 HTTP 본문으로 확인했다.
- 같은 명령으로 E1·E3·E4는 `ok: true, verdict: strong_ok`, E2·공모전 공지는 `ok: true, verdict: weak_ok`, 모두 `source: fetch, chromeUsed: false`였다. 이 응답에는 전체 조사 `evidenceStatus`가 없으므로 자동 sufficient 판정을 받았다고 주장하지 않는다.
- 우선 검증은 1번의 인계 수고, 2번의 하차 합의와 시간표 처리, 3번의 취소 후 대안 참여 의향이다. 공식 자료는 각 장면의 일부만 지지한다. 실제 이용빈도·차량 담당자의 불편 크기·재이용·사업성은 모두 미검증이다.
- 실제 차량 상태, 개별 권한, 위치 정확도, 내비 서비스 연결, ON_DEVICE 엔진, 외부 API 인증·호출 제한·데이터 신선도, 휴대폰·서버 연계는 시험하지 않았다. 설치·커밋·외부 메시지 전송은 하지 않았다.
