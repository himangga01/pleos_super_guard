# P09 자유 발상: 집밥 없는 전기차 출퇴근자와 작은 모임

- 작성일: 2026-11-11 KST, Asia/Seoul.
- 가상 페르소나: 집에서 충전하기 어려운 세입자이며 전기차로 출퇴근한다. 짧은 충전 틈에 보드게임을 즐기고 가족·동료·동네 사람과 느슨하게 연결되고 싶다는 설정이다. 실제 인터뷰나 검증된 고객군을 뜻하지 않는다.
- 범위·기준: 프로젝트 `AGENTS.md`, 공유 분석 정책, 같은 날의 [SDK 리뷰](../../pleos-sdk-review.md)와 다섯 SDK 개발 노트를 읽었다. 다른 페르소나 파일·아이디어는 읽지 않았다. `git status --short`는 Git 저장소가 아니라는 오류를 반환했고, 루트에는 `docs`와 `AGENTS.md`가 있었다. 이번 산출물은 발상 문서이며 앱·빌드·실행 결과는 없다.
- 구조 가정: 차량 화면에서 정차 중 한 작업을 시작하고, 필요한 경우 별도 모바일 웹과 자체 서버로 가족·동료에게 이어 준다. 모바일 웹·서버·계정·동기화는 새로 구현할 부분이다. 아래의 시연은 제안 흐름이며 수행 결과가 아니다.

## 1. 주차왕국 한 수

- **한 줄:** 충전할 때마다 가족의 우스운 작은 왕국에 한 수를 두는 비동기 협동 보드게임이다. 동시에 접속할 필요 없이 각자 돌아와 이어 한다.
- **장면:** 퇴근길 공용 충전소에 정차한 운전자가 “오늘은 왕국의 비 오는 날” 카드에서 우산 공장 하나를 고른다. 집에 있는 가족은 모바일 웹에서 다음 수로 지붕을 놓는다. 충전량을 점수로 바꾸거나 오래 충전할수록 보상하지 않는다.
- **차에서 할 이유:** 충전이라는 반복되는 틈에 짧은 회차를 붙이고 차량 오디오로 지난 한 수를 들려준다. 자동차 전용이어야 할 필연성은 약하므로 휴대폰 게임보다 이 회차 구분이 편한지 확인해야 한다.
- **SDK·외부 가정:** TTS로 고정 문장을 읽고 STT로 두세 선택지 중 하나를 받는다. ON_DEVICE 지원을 먼저 확인한다. Vehicle의 배터리·충전 관련 조회는 실제 Capability가 허용한 범위만 쓰며, 왕국 상태 동기화는 자체 서버가 담당한다. 기존 상용 게임의 규칙·이미지·계정 연동은 전제하지 않는다.
- **작은 시연:** 정차 전용 화면 진입 → 미리 만든 가족 수신 기록 재생 → 선택지 한 개 확정 → 저장 → 모바일 웹에서 다음 수 확인. 차량 상태 변경 시 게임 중단은 구현·검증해야 하며, 자동 정차 판정이 성립하지 않으면 차량 게임 화면을 열지 않는 설계다.
- **약점·첫 검증 질문:** 다음 차례가 오지 않으면 연결감보다 숙제로 느낄 수 있다. “충전할 때 가족과 한 수를 나누는 경험이 각자 휴대폰으로 놀 때보다 다시 하고 싶었나요?”
- **문제 근거:** [S1]은 캘리포니아 공동주택 세입자의 편리한 충전 접근 제약을 설명한다. 그 제약 속에서 충전 틈이 반복될 수 있다는 것은 유추이며, 짧은 협동놀이를 원한다는 것은 이 페르소나에 둔 서비스 가설이다. 충전 대기시간·외로움·게임 수요를 측정한 자료로 인용하지 않는다.

## 2. 동네 충전 타일 수첩

- **한 줄:** 자신이 실제로 들른 충전 장소의 생활 경험을 타일 한 장으로 남겨, 초대한 이웃·동료끼리 돌려보는 작은 수첩이다.
- **장면:** 집밥이 없는 운전자가 정차 후 “밤에도 근처 편의점에 들를 수 있었음”, “나는 이곳에서 차 안에 머물렀음” 중 한 기록을 남긴다. 동료는 다음 날 자신의 이동을 계획하며 작성 시각이 붙은 경험을 읽는다.
- **차에서 할 이유:** 현장에서 위치·시각과 함께 짧게 기록하면 나중에 장소를 기억해 입력할 부담을 줄일 수 있다는 가정이다. 차량이 충전기 번호나 주변 시설 상태를 자동 식별한다고 전제하지 않는다.
- **SDK·외부 가정:** FusedLocation으로 지원·권한·시각을 확인한 위치를 제시하고 사용자가 장소를 확정한다. STT로 한 문장 받아 사용자가 검토한다. 장소 목록은 시연용 수동 입력 자료, 공유·삭제·신고는 자체 서버 기능이다. 실시간 빈자리·고장 여부·요금·영업 여부를 보장하지 않는다.
- **작은 시연:** 가상 장소 두 곳 표시 → 현장 기록 한 장 작성 → 작성자가 위치·문장 확인 → 동료 모바일 웹에 출처와 날짜 표시 → 오래된 타일 표시. 동료의 경로 선택이 필요하면 확정한 좌표를 NaviHelper에 전달하는 단계만 별도로 시연한다.
- **약점·첫 검증 질문:** 소규모 모임에는 기록이 적고, 개인 경험이 현재 상태로 오인될 수 있다. “평소 충전 앱의 시설 정보에 없는 어떤 경험 한 가지가 실제 다음 방문 결정에 도움이 되었나요?”
- **문제 근거:** [S1]의 관찰 범위는 캘리포니아 공동주택 충전 접근이다. 충전 장소의 생활 맥락도 선택에 영향을 줄 수 있다는 것은 유추이며, 한국의 작은 모임에서 경험 수첩을 유지할지는 미검증 서비스 가설이다.

## 3. 충전소 옆 보드게임 우체통

- **한 줄:** 충전하러 가는 동선과 친구 사이의 보드게임 빌려주기를 한 약속 카드로 묶는다. 실제 보관함이나 충전기 기능을 설치하는 앱은 아니다.
- **장면:** 회사 근처 충전 장소로 가려는 운전자가 동료에게 빌릴 게임을 고른다. 동료가 모바일 웹에서 동의하면 두 사람은 미리 정한 사무실 로비에서 게임을 건넨다. 상대가 답하지 않으면 평소 충전 계획을 그대로 쓴다.
- **차에서 할 이유:** 이미 필요한 충전 이동의 목적지와 전달 장소를 함께 검토한다. 차량에서 확정한 경유지를 내비게이션에 전달하는 것이 연결점이며, 사람에게 연락하고 수락받는 기능은 외부 서비스가 맡는다.
- **SDK·외부 가정:** NaviHelper의 목적지·경유지 요청과 FusedLocation의 위치를 검토한다. 주소·운영시간은 구성원이 직접 확인한 시연 자료이고, 게임 목록·초대·수락·약속 취소는 자체 모바일 웹·서버 기능이다. 충전 예약·시간 보장·주차장 출입·제삼자 사업자 계정 연동은 제공하지 않는다.
- **작은 시연:** 게임 한 상자 선택 → 상대 모바일 웹에서 수락 → 정차 중 전달 장소 확인 → 확정 좌표로 경유지 요청 → 차 밖에서 두 사람의 전달 완료 버튼 확인. 이 흐름에서는 메시지나 약속을 실제로 보내지 않는다.
- **약점·첫 검증 질문:** 짧은 충전 틈에 약속을 얹으면 상대에게 부담을 주거나 우회가 늘 수 있다. “기존 충전 동선에 거의 맞는 친구에게만 제안해도 충분히 쓸 만한 약속이 생기나요?”
- **문제 근거:** [S1]은 집 가까이 편리한 충전을 확보하기 어려운 세입자 맥락을 제공한다. 필요한 충전 이동에 작은 물건 전달을 겹칠 수 있다는 것은 유추이며, 보드게임 대여 약속이 성립한다는 것은 서비스 가설이다. 실제 대여 수요·약속 성사율·이동 절감 효과는 확인하지 않았다.

## 직접 읽은 문제 근거

**[S1] California Energy Commission, 2026.** [Reservation-Based Shared Level 2 EV Charging in Multi-Family Properties: An Analysis of Shared Public and Private Multi-Family Charging in Three California Regions](https://www.energy.ca.gov/publications/2026/reservation-based-shared-level-2-ev-charging-multi-family-properties-analysis). 보고서 번호 CEC-600-2026-023, 웹페이지 갱신일 2026-09-23, 확인일 2026-11-11 KST.

- **확인한 사실:** 기관의 공식 발행 페이지와 초록은 캘리포니아 공동주택 세입자의 편리한 충전 접근이 제한된다고 설명하며, EVmatch의 예약 소프트웨어·공개/거주자 접근 관리 실증을 소개한다. 이는 충전 접근 문제와 그 지역의 특정 실증에 대한 자료다.
- **읽은 범위:** `agbrowse fetch <S1 URL> --json --browser never`로 원문 HTML·초록을 읽었고 `ok: true`, `verdict: strong_ok`, `source: fetch`, `contentTruncated: false`를 확인했다. 41쪽 PDF 본문은 읽지 않았다. 한국 세입자 전체나 세 아이디어의 수요로 일반화하지 않았다.
- **제외한 탐색:** Board Game Arena FAQ는 직접 요청에서 본문을 얻지 못했고, 문서 주소의 대체 응답은 관련 없는 최근 변경 목록이었다. 검색 결과 요약은 근거로 사용하지 않았다. 문제 근거 한 건을 확보한 뒤 추가 탐색을 끝냈다.

## SDK 기준과 검증 한계

- Vehicle·NaviHelper·TTS·STT·FusedLocation 다섯 SDK의 공모전 사용 허용은 [개발 범위 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)와 로컬 SDK 리뷰를 기준으로 한다. 이번 발상에서 새로 API·패키지·릴리즈를 조사한 것은 아니다.
- 공식 기술 링크: [Vehicle Capability](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/check-capability), [NaviHelper 경유지 포함 경로](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/route-with-waypoints), [TTS 시작·중지](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/start-and-stop), [STT 시작·중지](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/start-and-stop), [FusedLocation 위치 접근](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/location-data-access).
- 전력 공유·충전예약·충전기 제어·실시간 빈자리·사업자 계정 연결은 위 SDK가 제공한다고 가정하지 않았다. Gleo 승인, Pleos LLM SDK, 차량 마이크의 외부 STT 전송도 전제하지 않는다.
- 구현·실행은 전부 미검증이다. 우선순위는 각 아이디어의 첫 질문으로 이용 의사를 탐색하고, 차 안에서 쓰는 이유가 남는지 확인하는 것이다. 이어서 정차 상태 판정·주행 전환 중단·ON_DEVICE 한국어 음성·위치 권한과 null·내비 응답을 에뮬레이터에서 검증해야 한다. 수익·안전 효과·최초성·참여율은 주장하지 않는다.
