# P04 독립 발산: 장거리 연애 연구원의 주말 차 안

- 작성일: **2026-11-11 KST, Asia/Seoul**. 아래 인물은 가상이며 실제 인터뷰·수요조사 결과가 아니다.
- 페르소나: 장거리 연애 중인 연구원. 혼자 이동하는 주말, 통화와 도착 후 피로를 떠올린다. 취미는 팟캐스트이며 차를 작은 방·무대·작업실로 보는 공간 기획자의 관점이다.
- 기준선: 프로젝트 AGENTS와 공통 분석 정책, 같은 날의 공모전 보고서·출처 기록, [SDK 리뷰](../../pleos-sdk-review.md), SDK README와 Vehicle·NaviHelper·TTS·STT 노트를 참조했다. 다른 페르소나의 파일·아이디어는 읽지 않았다. `git rev-parse --show-toplevel`은 저장소가 아니라는 결과였다.
- 구현 상태: **아이디어만 작성했다.** 구상 구조는 Pleos 차량 앱 → 지원되는 차량·내비 상태와 음성 SDK → 로컬 텍스트 저장 → 선택적인 차 밖 연결이다. 다섯 공개 SDK의 공모전 사용은 허용되지만 실제 호출·계정 인증은 검증하지 않았다.
- 공통 범위: 아래 대화·편집·QR 표시는 주차한 뒤 사용한다. Vehicle의 지원 범위와 플랫폼의 주행 제한을 구현 전에 확인하며, 주차 여부를 확인하지 못하면 해당 기능을 열지 않는 설계다. 주차 브레이크 신호 하나를 안전한 주차의 증명으로 쓰지 않는다. Gleo 승인, Pleos LLM SDK, 차량 마이크의 외부 STT 전송은 전제하지 않는다.

## 1. 문턱 90초

- **한 줄·사용 장면:** 연인의 집에 도착한 뒤 차를 작은 전실로 쓴다. 운전자는 내리기 전 “지금은 조용히 쉬고 싶어 / 바로 산책하고 싶어” 중 자신의 상태와 첫 행동을 고른다. 피로는 사용자의 자가 표현이다.
- **차에서 해야 하는 이유:** 이동이 끝나고 만남이 시작되기 직전의 개인 공간이 차다. 폰에서도 가능한 카드지만, 차량 앱은 내비 도착과 주차 후 진입 시점을 연결하는 역할을 맡는다.
- **SDK:** [NaviHelper 이벤트](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/event-listeners)의 목적지 도착은 준비 신호로만 쓰고, Vehicle의 지원 상태를 별도로 확인한다. 선택 항목을 TTS로 읽거나 STT로 한 문장을 덧붙이는 구상이다.
- **외부 가정·차 밖 연결:** 카드 내용을 담은 로컬 QR을 주차 중 폰으로 읽어 가져간 뒤 직접 보여준다. 폰의 QR 읽기·화면 보관은 별도 기능이며, 상대에게 자동 전송하거나 상대의 위치를 수집하지 않는다.
- **작은 시연 제안:** Pleos 앱에서 도착 이벤트 수신 → 주차 조건 확인 → “말없이 10분 쉬기” 선택 → “그다음 같이 저녁 만들기” 입력 → 카드 QR → 폰으로 읽고 차 밖에서 보여주기. 도착 이벤트만으로 대화 화면을 열지 않는다.
- **약점·검증 질문:** 만남 직전의 표현이 형식적인 설문처럼 느껴질 수 있다. 두 사람이 이 카드를 보여주면 바로 말로 설명하는 것보다 편한가?
- **문제 근거:** [E2, Jiang·Hancock의 2013년 원문](https://onlinelibrary.wiley.com/doi/abs/10.1111/jcom.12029)은 장거리 관계의 자기표현·상대 반응 인식과 친밀감을 조사했다. 도착 피로와 첫 일정의 불일치, 90초 카드의 효과는 이 연구가 입증한 사실이 아닌 발상 가설이다.

## 2. 두 도시 우체국

- **한 줄·사용 장면:** 주말에 서로 다른 도시로 이동하는 두 사람에게 차 안 우편함을 만든다. 휴게소에 주차했을 때 “오늘 본 것 하나 / 나중에 같이 할 것 하나”를 짧은 편지로 남기고, 상대의 답장은 다음 주차 때 연다.
- **차에서 해야 하는 이유:** 이동 중 계속 통화할 시간을 확보하는 부담을 가정했다. 차의 이동 구간과 정차 구간을 구분해, 소식을 주고받는 시간을 정차한 차라는 작은 방에 배치한다.
- **SDK:** [SpeechToText](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/intro) ON_DEVICE로 편지 초안을 만들고, [TextToSpeech](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro) ON_DEVICE로 받은 텍스트를 낭독하는 구상이다. 주행 중에는 우편 도착 알림·답장 요구를 보류한다.
- **외부 가정·차 밖 연결:** 두 계정의 텍스트 교환에는 동의·인증·삭제 기능을 갖춘 별도 서버나 폰 연계가 필요하다. SDK는 연인 계정이나 메시지 전달을 제공하지 않는다. 차량 밖에서도 편지를 읽는 화면은 별도 구현이며 실시간 위치 공유는 필요 없다.
- **작은 시연 제안:** 주차 상태 확인 → STT로 두 문장 입력 → 최종 인식 결과를 확인해 로컬 보관 → 사전 탑재한 가상 답장을 TTS로 낭독 → 주차 조건 해제 시 대화 종료. 서버 없이 하는 첫 시연에서는 실제 상대에게 보냈다고 표시하지 않는다.
- **약점·검증 질문:** 답장을 정차 때까지 보류하는 경험이 오히려 답답할 수 있다. 기존 메신저의 음성·텍스트 메시지와 비교해 이 우편함을 따로 열 이유가 있는가?
- **문제 근거:** [E1, NHTSA 원문](https://www.nhtsa.gov/book/countermeasures-that-work/distracted-driving)은 통화 등을 주의 분산 활동에 포함한다. [E2, 2013년 관계 연구](https://onlinelibrary.wiley.com/doi/abs/10.1111/jcom.12029)는 동시성 등 소통 매체의 속성에 따른 차이를 조사했다. 짧은 비동기 편지의 선호·관계 개선 효과는 미검증이다.

## 3. 주차장 1인 학회

- **한 줄·사용 장면:** 팟캐스트를 듣고 휴게소에 주차한 연구원이 혼자 학회를 연다. 차량 스피커의 가상 사회자가 “발표자님, 오늘 주장에 제목을 붙여 주세요”, 이어 “그 주장의 반례는요?”라고 묻고 끝에는 짧은 가상 박수를 친다.
- **차에서 해야 하는 이유:** 혼자 큰 소리로 설명하고 연기해도 되는 임시 무대라는 가정이다. 차량 오디오를 사회자에, 운전석을 발표석에 대응시킨다. 연속 사용을 유도하지 않고 정차한 동안 한 회만 여는 구상이다.
- **SDK:** TTS로 미리 쓴 사회자 대사를 읽고 STT ON_DEVICE로 제목·주장·반례 세 항목을 저장한다. [Vehicle Capability](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/check-capability)를 확인해 사용할 상태를 고른다. 대사 순서는 고정하며 실제 논문 심사나 LLM 평가라고 표시하지 않는다.
- **외부 데이터 가정:** 팟캐스트의 제목·내용·재생 위치를 자동으로 가져올 API는 확인하지 않았다. 첫 시연은 사용자가 직접 주제를 넣고, 권리를 확보한 짧은 박수 파일을 앱에 포함한다. 타 서비스의 오디오·대본을 추출하지 않는다.
- **작은 시연 제안:** 주차 조건 확인 → “오늘 주제: 회의는 왜 길어지는가” 선택 → 사회자 TTS → 주장·반례를 각각 STT로 입력 → “주차장 학회 초록 1호” 카드 → 가상 박수 → 세션 종료. 재미를 위한 역할극이지 생산성 효과의 시연은 아니다.
- **약점·검증 질문:** 연구자에게도 부담스러운 숙제나 유치한 장난일 수 있다. 두 번째 주말에도 다시 열 만큼 웃기거나 생각 정리에 도움이 되는가?
- **문제 근거:** [E1, NHTSA 원문](https://www.nhtsa.gov/book/countermeasures-that-work/distracted-driving)의 좁은 사실은 대화·기기 조작이 운전의 주의를 분산할 수 있다는 점이다. 그래서 토론을 주차 후로 옮겼다. 팟캐스트 뒤 반론을 남기려는 수요와 차 안 역할극 선호는 가상 페르소나에서 나온 가설이다.

## 직접 연 원문과 검증 한계

- **E1: NHTSA, “Distracted Driving”, 게시연도 표기 미확인, 2026-11-11 확인.** [공공기관 원문](https://www.nhtsa.gov/book/countermeasures-that-work/distracted-driving)의 Overview에서 통화·차량 내 대화·기기 조작과 시각·인지·손 동작의 주의 분산 구분을 읽었다. 사고 감소 수치나 본 앱의 안전 효과를 도출하지 않았다.
- **E2: L. Crystal Jiang·Jeffrey T. Hancock, “Absence Makes the Communication Grow Fonder: Geographic Separation, Interpersonal Media, and Intimacy in Dating Relationships”, Journal of Communication 63, 556–577, 2013.** [출판사 원문·초록](https://onlinelibrary.wiley.com/doi/abs/10.1111/jcom.12029), [Cornell 저자 사본 PDF](https://cpb-us-e1.wpmucdn.com/blogs.cornell.edu/dist/c/6136/files/2014/01/2013-Jiang-Hancock-Absence-makes-the-communication-grow-fonder.pdf)를 직접 열고 초록·일지 조사 방식·논의를 확인했다. 특정 한국 운전자나 차량 앱을 시험한 연구가 아니다. 자기표현과 상대 반응 인식을 발상에 참고했으며 앱의 치료·피로 회복·수요 근거로 쓰지 않았다.
- **공식 SDK 확인:** 위에 연결한 TTS·STT 소개, Vehicle Capability, NaviHelper 이벤트 본문을 직접 열었다. [SDK 릴리즈](https://document.pleos.ai/docs/pleos-only/release-note/sdk-release-note)는 2026-10-19 기준 Vehicle 2.3.2, NaviHelper 3.0.5, TTS·STT 3.3.1, FusedLocation 1.1.3을 표시했다. [공모전 범위 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)는 CLI HTTP 읽기로 다섯 SDK 허용과 제한을 다시 확인했다.
- **실제 실행:** 웹 도구에서 E1·E2 원문을 읽었다. `agbrowse search --verify ... --browser never`는 E1 `strong_ok`, 공모전 공지 `weak_ok`였고 출판사·PDF는 `blocked`였다. 이 CLI 차단과 별개로 웹 도구에서 원문을 확인했으며 전체 조사에 대한 자동 `sufficient` 판정을 주장하지 않는다. 출판사·저자 사본은 같은 연구로 계산한다.
- 앱 코드·APK·빌드·에뮬레이터·실차·SDK 음성·주차 판별·QR·폰·서버 연결은 실행하지 않았다. 사용자 인터뷰·시장성·차별성·지불 의사는 미검증이다. 근거 확보 후 추가 시장·경쟁작 탐색은 하지 않았다. 첫 실행 확인 우선순위는 주차 조건·해제 처리, ON_DEVICE 한국어 음성, 내비 도착 이벤트의 실제 전달 여부다.
