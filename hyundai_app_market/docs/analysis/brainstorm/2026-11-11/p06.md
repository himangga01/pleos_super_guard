# P06 독립 발산: 조용히 지나가며 남기는 것

- 작성일: **2026-11-11 KST, Asia/Seoul**. 정확히 세 가지 아이디어를 제안하는 첫 발산이다.
- **가상 페르소나:** 작은 지역 도서관의 순회 담당자. 산간 마을을 방문하고 대출·수거·일정을 챙기며 이야기를 모은다. 말로 확인하기보다 조용한 신호와 자동 정리를 선호한다고 설정했다. 실제 인터뷰나 직업군 전체의 특성을 뜻하지 않는다.
- 기준: 프로젝트 `AGENTS.md`, 공통 분석 정책, 공모전 조사·출처 기록, `pleos-sdk-review.md`, `docs/sdk/README.md`, 위치·내비 노트를 읽었다. 독립성을 위해 다른 페르소나의 파일·아이디어·종합 브레인스토밍은 읽지 않았다. `git status --short`는 Git 저장소가 아니라고 반환했고, 작성 전 이 파일은 없었다.
- 대상·구조: **실제 Pleos 차량 앱**의 제안이다. 차량 위치 → 방문지 후보 → 정차 후 사용자 확인 → 카드·문장을 로컬에 묶는 구조를 가정한다. 현재 앱 구현·실행 결과는 없으며, 아래 시연은 모두 제안한 흐름이다.
- 공통 제약: Vehicle·NaviHelper·TTS·STT·FusedLocation의 공모전 사용은 허용된다. 여기서는 위치와 필요한 경우 내비만 사용한다. 개별 센서 지원·권한·플랫폼 서비스 연결은 별도 확인 대상이다. Gleo 승인, Pleos LLM SDK, 차량 마이크의 외부 STT 전송에 의존하지 않는다. 자동 생성은 미리 정한 규칙에 따른 묶음·정렬을 뜻한다.

## 1. 되돌아갈 일, 한 칸

- **한 줄·장면:** 방문지마다 남은 일을 작은 빈칸으로 남기는 차량용 마감 카드. 가상의 A마을에서 책상자를 내려놓고 돌아온 담당자에게 ‘수거 봉투 확인 1건’만 표시하고, 끝내지 못한 일은 다음 방문 카드로 넘긴다. 방문 간호·공구 순회 점검에도 확장하는 가설이다.
- **차에서 할 이유:** 차를 세우고 다시 출발하는 순간이 방문 업무의 경계다. 오늘의 전체 할 일 대신 현재 정류장의 물건·약속만 열고, 마지막 귀환 때 미완료 건을 방문지별로 묶는다. 실제 수거 여부는 사람이 확인하며, 문이 열렸다는 이유로 완료 처리하지 않는다.
- **SDK·외부 데이터 가정:** FusedLocation의 위치를 방문지 후보와 대조하고, 다음 목적지는 NaviHelper로 요청한다. 위치·내비 권한과 서비스 연결이 필요하다. 일정·회수 목록은 사용자가 넣은 로컬 자료로 시작하며 도서관 전산 API는 가정하지 않는다. 위치가 없거나 오래됐으면 방문지를 직접 고른다.
- **작은 시연:** 가상 정류장 두 곳과 업무 세 개를 넣기 → 시험 좌표로 A카드 열기 → 정차 후 ‘미수거’ 표시 → B카드 처리 → 귀환 화면에 ‘다음 A방문에 가져갈 것’ 한 묶음 표시. 경로 요청과 실제 탐색 성공은 별도로 보여준다.
- **약점·검증 질문:** 체크가 하나 더 늘 수 있고 공식 대출·반납 처리와 중복될 수 있다. **순회 담당자는 출발 직전 이 한 칸을 확인할 만큼 자주 현장 할 일을 다시 떠올려야 할까?**
- **상황의 근거와 추론:** 의왕시 공식 [이동도서관 안내](https://www.uwlib.or.kr/global/menu/10368/contents/40019/contents.do)는 도서관 접근이 어려운 시민을 위한 방문, 정류장별 시간표, 공휴일에 따른 반납일 변경을 설명한다. 2026년 운행 안내이며 2026-11-11 본문 확인. ‘장소·날짜에 묶인 반복 방문’의 근거로만 사용했다. 산간 지역의 미수거 빈도나 이 앱의 수요는 확인하지 않았다.

## 2. 침묵우표: 오늘 여기의 ‘사각사각’

- **한 줄·장면:** **엉뚱한 안이자 차 밖으로 이어지는 경험.** 녹음 대신 들은 소리를 글자 우표로 모은다. 정차한 뒤 허용된 산책 공간에서 잠깐 주변을 듣고 돌아와 ‘낙엽 / 사각사각’을 고르면, 오늘 지나온 길에 소리 우표 한 장이 붙는다. 시간과 단어는 가상의 예다.
- **차에서 할 이유:** 차는 여러 장소 사이를 이어 주고 다시 돌아오는 수집함이 된다. 앱은 이동 중 새 과제를 띄우지 않고 다음 정차 때 지난 방문의 우표 하나를 꺼낸다. 동일한 길도 다시 관찰할 이유가 생길 것이라는 가설이다.
- **SDK·외부 데이터 가정:** FusedLocation으로 우표의 장소 후보를 붙이고 날짜와 사용자가 선택한 단어를 로컬 저장한다. 위치 권한·서비스가 필요하며, 차 밖 활동의 시작·종료는 사용자가 확인한다. 마이크·소음 센서·문 센서·종 판별 모델·외부 소리 데이터는 사용하지 않는다. 위치 미확보 시 이름만 적는다.
- **작은 시연:** 정차 후 시작 → 차 밖에서 한 가지 소리 찾아 돌아오기 → ‘자연/사람이 만든 소리’와 의성어 선택 → 두 번째 시험 장소에서도 반복 → 오늘의 경로를 따라 두 우표를 나열. 측정된 소음 수치나 ‘조용한 장소’ 점수는 만들지 않는다.
- **약점·검증 질문:** 우표가 개인적 기록에 머물 수 있고 휴식이 기록 숙제로 바뀔 수 있다. **사용자는 두 번째 방문에서도 스스로 새 우표를 남기고 싶을까?**
- **상황의 근거와 추론:** 미국 국립공원관리청의 [Enhance Your Soundscape](https://www.nps.gov/subjects/sound/enhance.htm)는 주변 소리 세기, 걸으며 듣기, 마음에 드는 소리를 글자로 적기 등을 제안한다. 최종 갱신 2018-01-03, 2026-11-11 본문 확인. 이 관찰 활동을 차량의 반복 이동에 붙이는 것이 제안이다. 스트레스 감소·청력 개선·소음 측정 효과의 근거로 사용하지 않았다.

## 3. 다음 마을에 건네는 한 문장

- **한 줄·장면:** 한 차량이 오가는 마을들이 이어 쓰는 작은 창작 소설. A마을의 종이 카드에 ‘골목 끝 우체통이 밤마다 달아났다’가 적히면, 담당자가 정차 중 옮겨 두고 B마을에서 그 다음 한 문장을 받는다. 인용한 문장은 이번 발산을 위한 허구의 예다.
- **차에서 할 이유:** 한 차가 실제 주민 접점을 이어 주고, 방문 순서가 곧 이야기의 목차가 된다. 주민은 휴대폰 가입 없이 종이로 참여하고, 차량 앱은 중복·수정 이력과 다음에 보여줄 마지막 문장을 관리한다. 도서 대출과 별도로 동네 행사·순회 문화 활동에도 적용하는 가설이다.
- **SDK·외부 데이터 가정:** FusedLocation으로 마을 후보를 붙인 뒤 사람이 확인한다. 다음 방문지 안내가 필요할 때만 NaviHelper를 쓴다. 사람의 문장을 방문 순서대로 연결하며 LLM이 이어 쓰지 않는다. 종이 카드와 담당자의 입력이 기본이고 외부 데이터 API는 필요 없다. 공개 허락을 받지 않은 문장은 공유 원고에서 제외한다.
- **작은 시연:** 가상 마을 두 곳 방문 → 첫 창작 문장을 입력하고 공유 허락 표시 → 다음 마을에 마지막 문장만 보여주기 → 두 번째 문장 추가 → 차량 앱에서 방문 순서대로 원고 내보내기. 소책자 인쇄·게시판 배포는 차 밖의 별도 작업으로 구분한다.
- **약점·검증 질문:** 담당자의 옮겨 적기 부담과 원치 않는 실명·타인 이야기의 유입이 생길 수 있다. **주민은 앞 문장만 보고 한 문장을 잇는 방식을 부담 없이 재미있게 받아들일까?**
- **상황의 근거와 추론:** 공식 서비스 [StoryCorps, Mobile Tour 2026](https://storycorps.org/MOBILE-TOUR/)은 이동식 스튜디오로 여러 도시·마을을 찾아 지역 기관과 협력해 대화를 기록·보존해 왔다고 설명한다. 2026년 안내, 2026-11-11 본문 확인. 이동 방문이 이야기 참여의 접점이 되는 선례다. 종이 기반 공동 창작의 수요·재미나 산간 마을 적합성은 이 사례로 입증되지 않는다.

## SDK 원문과 실제 확인 범위

- [FusedLocation: 위치 데이터 접근](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/location-data-access), 게시·수정일 미표시, 2026-11-11 본문 열람. 마지막 위치는 새 측정이 아니며 `null`일 수 있고, 위치 변경 콜백을 제공한다. 자동 방문 확정이나 정차 판별을 보장하지 않는다.
- [NaviHelper: Destinations](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/destinations), 게시·수정일 미표시, 2026-11-11 본문 열람. 목적지 요청·조회·취소와 결과 이벤트를 설명한다. 최적 순회 계산기를 제공한다는 가정은 하지 않았다.
- 자료 확인은 `web` 검색 후 공식 URL 본문 열람과 `agbrowse fetch --json --browser never`로 했다. 의왕·NPS는 해당 본문을 받았다. StoryCorps의 자동 HTTP 조회는 무관한 댓글 피드를 골라 근거에서 제외했고, `web`으로 열린 원래 Mobile Tour 본문을 읽었다. 하남 자료는 본문 재조회 시간 초과, 미국 의회도서관 후보는 403으로 제외했다. 검색 요약만으로 사실을 확정하지 않았다.
- 먼저 검증할 것은 세 안의 반복 사용 의향과 현장 입력 부담이다. 실제 담당자·주민 인터뷰, 이용 수요·지불 의향, 문장 공개 동의 절차, 주행 중 UI 제한, 차량 위치의 최신성·오차·권한 거절, 내비 서비스 연결, 빌드·에뮬레이터·실차 시연은 **실행하지 않았다**. 시장 최초나 안전 효과를 주장하지 않는다.

이 파일이 P06의 독립 원본이다. 후속 작업은 이 파일과 최신 공식 근거를 먼저 읽고, 가설을 확인한 사실로 바꾸는 경우 확인 방법과 날짜를 함께 갱신한다.
