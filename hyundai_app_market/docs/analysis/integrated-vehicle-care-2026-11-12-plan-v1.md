# Pleos 차량 이상 기록·긴급 안내 앱 기획안

작성일: **2026-11-12, 한국 시간**. 상태: **제품 기획과 기능 확인 계획**. 앱 구현·차량 연결·실차 검증은 진행하지 않았습니다.

**기존 2번 경고등 도감, 5번 이상 가속·페달 착각 대응, 6번 사고 기록·보호자 공유를 하나의 Pleos 앱으로 합칩니다. 지원 대상은 Pleos 탑재 차량으로 한정합니다.** 일반 차량용 제품이나 다른 차량 지원으로 확장하지 않습니다. 안드로이드 휴대폰은 해당 Pleos 차량의 사고 대응 백업과 보조 입력·자료 보관을 맡습니다.

이 문서는 합친 세 아이디어의 현재 기준입니다. [여섯 아이디어 요약](six-app-ideas-2026-11-12.md), [기존 네 아이디어 상세](selected-app-ideas-2026-11-12.md), [기존 안전 아이디어 상세](vehicle-safety-app-ideas-2026-11-12.md)는 통합 전 이력으로 참고합니다. 나머지 세이브포인트·귀가 역전골·반찬 입국심사는 이번 통합 대상이 아닙니다.

## 1. 앱이 하는 일

**차의 이상을 이해하고, 잠깐 나타난 증상을 남기고, 위험할 때 행동을 안내하며, 사고 뒤에는 보호자에게 상황을 전달하는 앱입니다.**

| 기능 | 사용자가 겪는 문제 | 앱의 역할 |
| --- | --- | --- |
| 경고등·오류 찾기 | 표시의 이름과 뜻을 모릅니다. | 전체 도감에서 직접 찾거나 사진으로 후보를 찾습니다. |
| 순간 고장 기록 | 소음·떨림·오류가 사라져 정비소에서 설명하기 어렵습니다. | 증상 전후의 허용된 차량 정보·소리·영상을 묶습니다. |
| 급가속·감속 실패 안내 | 당황해 페달을 헷갈리거나 브레이크를 밟아도 속도가 줄지 않습니다. | 상태에 맞는 음성과 Pleos 화면 애니메이션을 함께 제공합니다. |
| 사고 알림·백업 | 운전자가 응답하지 못하거나 차량 전원이 꺼집니다. | 사고 신호를 먼저 보내고 휴대폰이 가능한 기능을 이어받습니다. |

첫 화면은 ‘경고등 찾기’, ‘지금 증상 기록’, ‘기록 보기’, ‘보호자·백업 상태’로 구성합니다. 긴급 안내는 앱이 받은 신호에 따라 별도 상태로 전환합니다. 주행 중 글을 입력하거나 메뉴를 여러 번 열지 않도록 만듭니다.

## 2. 지원 범위와 세 장치의 역할

### 2.1 Pleos 차량 앱이 중심입니다

| 구성 | 맡을 일 | 맡지 않는 일 |
| --- | --- | --- |
| Pleos 차량 앱 | 차량 정보 수신, 경고등 도감, 증상 구간 보관, 긴급 판단, 음성·화면 안내, 사건 전송 | 공개 API로 확인되지 않은 자동 제동·가속 차단 |
| 안드로이드 휴대폰 보조 앱 | 출발 전 백업 준비, 허용된 최근 자료 복사, 자체 위치·움직임 기록, 차량 중단 시 안내·전송·구조 요청 음성의 백업, 사진·영상 전달 | Pleos 없는 차량을 위한 독립 서비스, 꺼진 차량의 센서 복구 |
| 서버와 보호자 화면 | 사건 정보 수신, 중복 사건 묶기, 허용된 파일 저장, 보호자 통지와 열람 상태 | 인터넷이 끊긴 차량을 원격으로 되살리거나 구조기관 출동을 보장하는 일 |

차량 앱만 사용하는 안은 전원 차단 후의 대응이 약합니다. 휴대폰을 주 앱으로 삼는 안은 사용자가 정한 방향과 다릅니다. 따라서 **Pleos 차량 앱을 주 앱으로 두고, 휴대폰을 출발 전부터 준비한 백업으로 사용하는 구조**를 채택합니다.

백업을 위해 두 앱이 자료와 상태를 주고받는 연결 기능은 별도로 개발해야 합니다. 기존 차량 블루투스 연결이 앱 간 자료 전송까지 제공한다고 가정하지 않습니다. 사용할 연결 방식과 권한은 Pleos에서 허용하는 방법으로 확인합니다.

### 2.2 지원 차량을 등록할 때 확인합니다

Pleos 차량의 모델·연식·동력 방식·사양·소프트웨어 버전을 확인합니다. 차량 정보 기능으로 확인되는 값과 사용자가 확인한 값을 구분합니다. 실제 지원 목록은 Pleos 적용 여부와 기능 시험을 마친 차량으로 작성합니다.

경고등 자료가 있는 것과 그 차에서 실시간 신호를 받을 수 있는 것은 다릅니다. 도감 자료, 실시간 조회, 음성, 녹음, 영상, 움직임 센서, 블랙박스, 휴대폰 연결의 지원 상태를 각각 표시합니다.

## 3. 전체 경고등·오류 도감

### 3.1 세 가지 경고등으로 제한하지 않습니다

지원하는 Pleos 차량의 공식 설명서에 나오는 **전체 경고등·표시등·계기판 경고문구**를 대상으로 합니다. 기존의 세 항목 제한은 폐기합니다. 다른 차량의 표시를 섞어 전체 목록을 만든 것처럼 보이지 않게 합니다.

각 항목에는 모양, 이름, 색, 켜짐·깜박임, 동반 문구, 해당 사양, 뜻, 공식 대응 안내, 원문 주소와 자료 버전을 보관합니다. 같은 그림이라도 상태에 따라 안내를 나눕니다. 정상 작동을 알리는 표시등을 모두 고장으로 분류하지 않습니다.

차량 컴퓨터가 저장하는 진단 고장 코드(DTC)는 그림이나 경고문구와 다른 자료입니다. 코드를 받는 공개 경로는 아직 확인하지 못했습니다. 허용된 조회 경로가 확인되면 기록에 추가하며, 도감 전체 수록과 모든 제어기의 코드 자동 조회를 같은 기능으로 설명하지 않습니다.

모델별 공식 목록을 기준으로 항목 수와 누락을 대조합니다. 검토하지 않은 목록은 ‘전체 수록 완료’라고 표시하지 않습니다. 실제 Pleos 대상 모델의 설명서와 자료 목록을 확보하는 작업은 아직 남아 있습니다.

### 3.2 직접 고르거나 사진으로 찾습니다

| 방법 | 사용 순서 | 결과 |
| --- | --- | --- |
| 직접 찾기 | 모양·색·분류·표시 문구로 좁힌 뒤 비슷한 그림을 고릅니다. | 선택한 차의 공식 설명과 현재 조건을 보여 줍니다. |
| 사진으로 찾기 | 정차 후 허용된 카메라로 촬영하거나 휴대폰에서 사진을 보냅니다. | 사진 속 모양과 글자를 읽어 후보를 보여 주고 사용자가 확인합니다. |

사진에 경고등이 여러 개 있으면 각각 찾습니다. 흐리거나 가려진 경우에는 찾지 못했다고 표시합니다. 찾기 결과만으로 고장 원인을 확정하지 않습니다.

차량 카메라를 쓸 수 없다면 휴대폰 카메라를 보조 입력으로 사용하고 결과를 Pleos 앱의 같은 사건에 붙입니다. 휴대폰으로 운전 중 직접 촬영하게 하지는 않습니다. 사진 인식 결과가 긴급 제동의 직접 실행 조건이 되지도 않습니다.

### 3.3 가까운 현대 서비스센터로 이어집니다

경고의 대응 수준은 해당 차량의 공식 안내로 정합니다. 색 하나만으로 심각도를 결정하지 않습니다.

| 공식 안내의 성격 | 앱의 동작 |
| --- | --- |
| 안전하게 정차하거나 운행을 중단해야 하는 문제 | 먼저 정차·도움 요청 안내를 표시합니다. 가까운 센터까지 계속 운전하라고 안내하지 않습니다. |
| 점검을 받아야 하는 문제 | 위치와 정비 가능한 항목을 기준으로 현대 하이테크센터·블루핸즈 후보를 보여 줍니다. |
| 정상 상태 표시 | 뜻을 설명하며 정비가 필요한 고장으로 바꾸지 않습니다. |

센터 카드에는 주소, 거리의 기준, 연락처, 정비 가능 여부와 확인 시각을 담습니다. 필요하면 내비에 목적지를 보냅니다. 위치가 없으면 지역을 직접 고를 수 있게 합니다. 정비 항목과 실제 접수 가능 여부는 센터 확인이 필요합니다.

현재 공식 검색·예약 웹페이지는 확인했습니다. 외부 앱에서 가까운 센터를 검색하고 예약까지 확정하는 공개 API는 확인하지 못했습니다. 따라서 공식 페이지 연결과 허용된 정비소 자료·내비 연결을 나누어 개발합니다. 링크를 열었다는 이유로 예약 완료라고 표시하지 않습니다. [현대자동차 공식 서비스 네트워크](https://www.hyundai.com/kr/ko/service-membership/service-network/service-reservation-search)

## 4. 잠깐 나타난 고장 증상 기록

### 4.1 증상이 사라져도 정비사에게 보여 줄 수 있게 합니다

대상은 순간 소음, 떨림, 일시적인 출력 변화, 화면 오류, 잠깐 켜진 경고등과 경고문구 등입니다. 고장이라고 확정되지 않은 현상도 ‘사용자가 느낀 증상’으로 남길 수 있게 합니다.

사용자는 ‘지금 증상 기록’을 한 번 누르거나 허용된 음성 인식 세션에서 기록을 요청합니다. 자동으로 받은 경고 신호도 사건을 만들 수 있습니다. 스티어링 휠 버튼이나 별도 호출어로 앱을 항상 깨울 수 있다는 기능은 확인되지 않았으므로 확정하지 않습니다.

최근 자료를 짧게 보관하다가 요청이 들어오면 해당 구간을 지우지 않는 방식입니다. **증상 전 30초와 후 60초**를 첫 시험값으로 사용합니다. 이는 제안값이며 녹음·녹화 지속 실행이나 길이를 SDK가 보장하는 것은 아닙니다. 계속되는 증상과 재발은 같은 사건에 추가할 수 있도록 합니다.

### 4.2 한 사건에 묶을 자료

| 자료 | 기록할 내용 | 사용할 수 없을 때 |
| --- | --- | --- |
| 차량 상태 | 속도·브레이크·지원되는 경고 표시·핸들 각도·기타 허용된 정보 | 항목별 미지원·권한 거절·오래된 값·오류를 표시합니다. |
| 위치·시각 | 측정 시각, 앱 수신 시각, 위치 정확도와 출처 | 마지막 위치와 경과 시간을 표시합니다. |
| 증상 설명 | 사용자가 말하거나 적은 내용, 인식 문장 | 원본 설명과 앱의 분류를 구분합니다. |
| 원본 소리 | 허용된 내부 마이크·외부 마이크·블랙박스 음성 채널 | 녹음 없음으로 표시합니다. 인식 문장으로 원본을 대신하지 않습니다. |
| 영상·사진 | 허용된 카메라·블랙박스 구간, 사용자가 붙인 자료 | 촬영 채널과 빈 구간을 표시합니다. |
| 앱 대응 | 받은 신호, 판단 상태, 재생한 안내, 화면 단계, 전송 결과 | 어떤 대응이 실행되지 않았는지도 남깁니다. |

실내 마이크에 들린 외부 소리와 차체 외부 마이크의 녹음은 구분합니다. 실내에서 녹음했다고 소리의 발생 위치를 자동으로 알아낼 수는 없습니다.

녹음·녹화가 시작되기 전의 구간은 복구할 수 없습니다. 음성 인식 SDK는 말을 글로 전달하는 기능이므로 원본 녹음을 별도로 확보해야 합니다. 기록이 꺼져 있거나 제한된 상태도 첫 화면에서 알 수 있게 합니다.

### 4.3 정비 방문 자료로 정리합니다

증상이 나타난 순서, 주행 상태, 발생 횟수, 영상·소리, 자료가 없는 구간을 함께 볼 수 있게 합니다. 사용자가 원하는 구간을 골라 정비사에게 보여 주거나 공유할 수 있게 합니다. 정비 결과와 다시 나타났는지도 같은 기록에 추가합니다.

이 자료는 증상을 설명하기 위한 기록입니다. 앱이 고장 원인이나 책임을 판정한 결과와 구분합니다. 정비사에게 보낼 자료와 보호자에게 보낼 자료의 접근 범위도 나눕니다.

## 5. 급가속·브레이크 입력·감속 실패 안내

### 5.1 두 상황을 구분합니다

| 상태 | 사용할 자료 | 앱의 대응 |
| --- | --- | --- |
| 의도하지 않은 급가속이 의심되며, 최신의 유효한 브레이크 값이 ‘밟지 않음’임 | 유효한 차량 속도 변화, 브레이크 값 `false`, 당황 음성·직접 요청 등 보조 자료 | 브레이크 페달을 밟고 올바른 페달인지 확인하도록 음성과 애니메이션을 제공합니다. |
| 실제로 움직이고 있으며, 의도하지 않은 가속 대응 중이거나 사용자가 정지 실패를 요청했고, 브레이크 입력 뒤에도 감속이 관측되지 않음 | 유효한 브레이크 값 `true`, 시간에 따른 차량 속도, 진행 중인 사건·사용자 요청 | 단순히 같은 페달 안내를 반복하지 않고 차종별 비상 제동 안내로 전환합니다. |
| 차량 정보가 없거나 오래됨 | 자료의 출처·마지막 수신 시각 | ‘판단 불가’를 표시합니다. 사용자가 직접 긴급 안내를 요청할 수 있게 합니다. |

‘어 이거 왜이래!’, ‘아이고!’, ‘안돼!’와 같은 표현은 보조 자료입니다. 음성이 들어와야만 긴급 상태를 처리하는 조건으로 만들지 않습니다. 에어백 신호나 직접 긴급 요청을 음성 인식 완료 때문에 늦추지 않습니다.

브레이크 입력은 눌림 여부입니다. 올바른 발 위치, 충분한 힘, 실제 제동력을 확인한 값은 아닙니다. 자료에는 ‘브레이크 입력 확인, 감속 미관측’처럼 받은 사실을 남깁니다. 이를 운전자 실수나 기계 고장으로 단정하지 않습니다.

브레이크 값은 ‘밟음’, ‘밟지 않음’, ‘확인 불가’로 나눕니다. 권한 거절·미지원·값 없음·오래된 값·수신 오류를 `false`로 바꾸지 않습니다. 이미 정차한 차에서 브레이크를 밟고 있거나 정상 주행 중 속도가 일정한 상황은 감속 실패 조건에 넣지 않습니다. 전진·후진 방향과 이동하는 빠르기를 구분해, 후진의 음수 속도가 더 작아진 것을 감속으로 오해하지 않도록 합니다.

급가속의 기준과 감속 실패의 관측 구간은 실제 차량 신호의 갱신 주기와 오류를 시험한 뒤 정합니다. 속도 하나가 갑자기 튄 경우, 정상 가속, 경사로, 자료 수신 지연도 시험해야 합니다. 신호가 모순되면 어떤 상태로 판단했는지 남깁니다.

### 5.2 음성과 Pleos 화면 애니메이션을 함께 제공합니다

**음성만 제공하는 안으로 축소하지 않습니다. 같은 안내 단계의 말·짧은 설명·그림·움직임을 함께 제공하는 것이 제품 요구사항입니다.**

| 안내 단계 | 음성의 역할 | Pleos 화면의 설명과 애니메이션 |
| --- | --- | --- |
| 페달 확인 | 현재 해야 할 행동을 한 문장으로 알려 줍니다. | 해당 차량의 페달 배치에서 브레이크를 강조합니다. 발을 옮길 방향을 짧게 보여 줍니다. |
| 브레이크 입력 후 감속 확인 | 입력 상태와 다음 대응을 알려 줍니다. | 현재 상태를 표시하고 다음 안내가 왜 나오는지 짧게 설명합니다. |
| 비상 제동 장치 안내 | 검토된 해당 차량의 조작 방법을 순서대로 읽습니다. | 실제 장치의 위치, 조작 방향, 유지해야 하는 동작을 같은 단계에 맞춰 보여 줍니다. |
| 정차 후 안내 | 다음에 해야 할 확인과 도움 요청을 안내합니다. | 정차 후 확인할 내용을 더 자세하게 보여 줍니다. |

페달 그림은 운전자의 실제 발을 촬영해 확인한 화면이 아니라 올바른 동작의 예시입니다. 실제 발 위치를 알고 있다는 표현은 사용하지 않습니다. 페달과 비상 제동 장치의 배치가 검토되지 않은 차량에는 임의의 배치 그림을 내보내지 않습니다.

큰 글씨와 충분한 대비를 사용하고 한 번에 한 행동을 보여 줍니다. 움직임은 행동 방향을 설명하는 범위로 제한합니다. 주행 중 화면을 계속 보거나 다음 버튼을 누르게 만들지 않습니다. 정차 상태의 설명에서는 전체 순서를 자세히 볼 수 있게 합니다.

Pleos는 주행 중 애니메이션·영상과 화면 조작을 제한할 수 있습니다. 실제 표시 형식은 앱 종류·지역·`CarUxRestrictions`에 맞춰 확인해야 합니다. 허용되지 않는 경우에는 해당 주행 상태에서 승인된 짧은 그림·설명과 음성을 사용하고, 상세 애니메이션은 정차 후 제공합니다. 긴급 기능이라는 이유로 제한을 우회하지 않습니다. [Pleos 주행 안전 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)

내비 등 다른 앱이 보이거나 이 앱이 화면 뒤에 있을 때 긴급 안내를 표시할 수 있는 공식 경로도 확인해야 합니다. 자동으로 화면 맨 앞에 나타나거나 계기판을 덮을 수 있다고 가정하지 않습니다. 허용된 알림·표시·전면 전환 경로와 오디오 재생을 각각 시험합니다. 필요한 경로가 확보되지 않으면 해당 상태의 화면 안내 요구를 충족하지 못한 것으로 남기고, 충족한 기능처럼 출시 설명에 넣지 않습니다.

### 5.3 긴급 상황에서 문장을 새로 생성하지 않습니다

차량의 정확한 사양과 공식 설명서를 기준으로 안내 순서를 미리 검토합니다. 음성, 장치 그림, 조작 애니메이션을 차량과 휴대폰에 저장해 통신 없이도 사용할 수 있게 합니다. 같은 단계 번호를 사용해 말과 화면이 서로 다른 동작을 설명하지 않게 합니다.

브레이크 문제, 가속이 계속되는 문제, 전원·장치 이상을 한 가지 조작 순서로 처리하지 않습니다. 중립 변속, 전자식 주차 브레이크(EPB), 비상 시 전원 조작은 해당 Pleos 차량의 공식 절차와 조건이 검토됐을 때만 안내 순서에 넣습니다. 일반적인 정차 조작과 비상 제동 조작도 구분합니다.

조사한 현대차 CE1/2024 설명서에는 브레이크 페달 문제 시 EPB 스위치를 유지해 사용하는 비상 제동 안내와 제동거리 관련 주의가 있습니다. 이는 설계 참고 자료이며 **해당 차가 Pleos 지원 대상이라는 증거가 아닙니다.** 이 문구와 장치 위치를 실제 대상 Pleos 차량에 그대로 옮기지 않습니다. [제조사 비상 제동 설명 예시](https://ownersmanual.hyundai.com/full_webhelp/CE1/2024/ko_KR/iddb9b77f2061.html)

독립된 보조 자료인 AAA의 2010년 안내도 차종별 조작 차이를 확인하고 전방 주시를 유지하도록 설명합니다. 과거의 일반 안내를 현재 Pleos 차량의 확정 절차로 사용하지 않습니다. [AAA 원문](https://news.aaa-calif.com/news/auto-club-recommends-steps-to-154948)

신호 수신 뒤 첫 음성과 화면 전환을 빠르게 시작하도록 설계합니다. 첫 시험 목표는 유효한 긴급 신호를 앱이 받은 뒤 1초 이내로 두되, SDK 지연·오디오 포커스·실제 장치에서 측정해야 합니다. 판단 완료, 실제 음성 시작, 실제 화면 표시까지의 시간을 나누어 기록합니다. 음성 재생이 허용된 상태라면 화면 전환 응답 때문에 음성을 늦추지 않습니다. 이는 사고 발생부터 안내까지 1초를 보장하는 성능이 아닙니다.

### 5.4 대응 과정도 기록합니다

속도·브레이크·음성, 판단 시각, 선택한 안내 버전과 단계, 재생 성공·실패, 화면 상태, 이후 속도 변화를 같은 사건에 남깁니다. 음성이 재생됐다고 사용자가 들었거나 행동을 마쳤다고 표시하지 않습니다.

안내 화면 자체의 녹화도 허용된 경로가 있는지 확인합니다. 사용할 수 없다면 당시 안내 자료 버전과 단계 이력으로 다시 보여 주되, 이를 실제로 촬영한 화면 영상이라고 표시하지 않습니다.

앱이 직접 차량을 제동하거나 가속을 끊는 명령은 확인되지 않았습니다. 여기서 계획하는 것은 **사람이 정지 동작을 할 수 있도록 정확한 안내를 제공하는 기능**입니다.

## 6. 사고 감지·즉시 알림·자료 보관

### 6.1 사고 관련 신호를 받으면 작은 정보부터 보냅니다

새 에어백 전개, 사용자의 긴급 요청, 지원되는 차량 신호와 움직임의 조합 등을 사건 시작 조건으로 검토합니다. 이미 전개된 상태를 처음 읽은 경우는 새 사고와 구분합니다. 큰 충격 하나, 기울기 하나, 연결 끊김 하나만으로 사고를 확정하지 않습니다.

**사건을 인지한 시점부터 즉시 첫 전송과 자료 보관을 각각 시작합니다.** 첫 전송은 파일 저장 성공·새 위치 조회·영상 완성·사용자 응답을 기다리지 않습니다. 사건 번호·신호 수신 시각·관측한 신호만으로 먼저 보낼 수 있게 하고, 위치가 없으면 ‘위치 없음’으로 보냅니다. 저장이 실패해도 전송 시도까지 막지 않도록 나눕니다. 실제 충돌 시각, 차량이 신호를 만든 시각, 앱이 받은 시각은 다를 수 있어 구분합니다.

첫 정보는 사건 번호, 관측된 신호와 분류, 시각, 위치와 정확도, 차량·휴대폰의 연결 상태입니다. 이후 자료와 상황 변화를 같은 사건에 추가합니다. 잠정 사고 의심과 확인된 신호를 구분해 알리고, 잘못된 알림을 취소하면 취소 이력도 보호자에게 전달합니다.

모든 사고에서 에어백이 펼쳐지지는 않습니다. 다른 센서의 실제 지원 여부와 판단 규칙은 따로 검증해야 합니다. 차량 연결이 끊긴 사실은 ‘연결 중단’으로 기록하며 단독 사고 판정으로 바꾸지 않습니다.

### 6.2 사용자가 응답하지 못해도 이어집니다

직접 긴급 요청이나 강한 사고 관련 신호는 운전자의 응답을 기다리지 않고 사전 동의한 보호자에게 보냅니다. 응답 확인 화면과 음성을 제공하되 최초 전송을 늦추는 단계로 사용하지 않습니다.

응답하지 않는 상태는 ‘사용자 응답 없음’으로 표시합니다. 이를 기절이나 의식 소실의 진단으로 설명하지 않습니다. 야간이나 외진 장소에서도 등록된 보호자에게 위치·마지막 수신 시각을 전달하고, 수신·열람 확인을 구분합니다.

차량이 움직이는 동안에는 정지 안내를 우선합니다. 사고 후 정차했거나 움직이지 못하는 것으로 판단되는 상황에서는 설정한 조건에 따라 ‘도와주세요. 사고가 났습니다.’와 같은 큰 음성으로 주변의 도움을 요청하는 안을 넣습니다. 운전 중 긴급 제동 안내와 구조 요청 음성이 서로 겹치지 않게 합니다.

차량 스피커와 휴대폰 스피커의 실제 소리 크기, 무음 설정·통화·오디오 포커스의 영향을 시험합니다. 실내 스피커의 소리가 차 밖에 충분히 들린다고 보장하지 않습니다. 외부 스피커·경적을 원격으로 작동시키는 기능은 별도로 확인되지 않았으므로 확정하지 않습니다. 응답 확인과 반복 간격·최대 재생 시간은 시험으로 정합니다.

보호자 통지와 구조기관의 신고 접수·출동은 다른 일입니다. 이번 계획에서 구조기관 자동 신고가 이미 연결된 것으로 표시하지 않습니다. 해당 기능이 필요하면 공식 긴급 서비스와 별도 연동을 확인해야 합니다.

### 6.3 받은 자료를 보존하고 빈 구간을 보여 줍니다

차량 정보, 인식 문장, 원본 소리와 영상, 위치, 판단·안내·전송 이력을 **사용이 허용되고 실제로 받은 범위에서 모두** 사건에 보관합니다. 사고로 고정한 구간은 일반적인 최근 자료 지우기에서 제외합니다.

원본은 유지하고, 재생·사진 인식·정비용 설명은 별도 자료로 보관합니다. 파일 식별값과 수신 이력, 시간 오차, 끊긴 구간을 남깁니다. 이를 공인 사고기록 장치나 원인 판정 결과로 설명하지 않습니다.

큰 파일은 나눠 저장·전송하고, 서버가 받은 부분과 아직 남은 부분을 구분합니다. 저장 공간이 부족하면 사용자가 알 수 있게 하며 조용히 사건 자료를 지우지 않습니다. 보관 기간·용량·삭제·공유 철회는 설정으로 관리하며 영구 무제한 보관을 약속하지 않습니다.

## 7. 차량 전원이 꺼졌을 때의 안드로이드 백업

### 7.1 사고 뒤에 켜는 방식으로만 만들지 않습니다

차량이 갑자기 꺼지면 휴대폰을 깨우라는 마지막 명령조차 보내지 못할 수 있습니다. 따라서 출발 전에 사용자가 보조 앱을 준비하고 필요한 권한과 실제 작동 상태를 확인합니다. 차량과 휴대폰이 최근 자료·사건 상태·안내 자료를 미리 나눠 보관합니다.

휴대폰은 허용된 범위에서 자체 위치·움직임·소리를 수집하는 백업을 준비합니다. 이 기능은 별도 개발·시험이 필요합니다. 앱이 꺼진 뒤에도 항상 자동으로 되살아난다는 보장은 없습니다. Android의 위치·마이크·카메라 전경 서비스 조건을 확인해야 합니다. [Android 서비스 종류와 권한](https://developer.android.com/develop/background-work/services/fgs/service-types)

### 7.2 휴대폰이 이어받을 수 있는 범위

| 차량 상태 | 휴대폰의 동작 | 받을 수 없는 것 |
| --- | --- | --- |
| 차량 앱이 정상 작동 | 백업 상태·최근 자료를 확인하고 사건을 중복 보관합니다. | 허용되지 않은 차량 정보 |
| 사고 정보가 전달된 뒤 차량이 꺼짐 | 이미 받은 사건을 보관·전송하고 같은 단계의 안내·도움 요청 음성을 이어갑니다. | 전원 차단 뒤의 새 차량 센서값 |
| 사고 정보가 전달되기 전에 차량이 꺼짐 | 자체 센서·위치와 기존 자료로 별도 사고 의심 여부를 검토합니다. | 받지 못한 에어백·페달·차량 속도값 |
| 차량과 휴대폰 모두 인터넷이 없음 | 기기 안에 저장하고 미리 저장한 안내를 제공합니다. 재연결되면 전송합니다. | 즉시 원격 전달 보장 |
| 휴대폰 전원·권한·실행도 중단됨 | 마지막 작동·수신 상태를 남깁니다. | 계속되는 백업 보장 |

휴대폰 GPS 속도를 차량 속도로 바꾸어 표시하지 않습니다. 휴대폰이 흔들리거나 떨어진 것을 차량 충돌로 오인하지 않도록 시험합니다. 사고와 일반 시동 종료·블루투스 끊김도 구분해야 합니다.

두 기기가 같은 사건을 각각 만들면 서버에서 묶습니다. 통신이 될 때에는 안내 단계를 맞추고 한 기기가 중심 음성을 재생하도록 합니다. 연결이 끊겼을 때 두 안내가 겹칠 가능성과 휴대폰의 인계 지연도 시험해야 합니다. 같은 사건을 두 번 알린 것을 별도 사고 두 건으로 표시하지 않습니다.

## 8. 차량 안 블랙박스 연동 조사 결과

차 안에 설치된 블랙박스와 사람을 촬영하는 실내 카메라 채널은 다른 개념입니다. 전방·후방·실내·음성 중 무엇을 제공하는지 각각 확인해야 합니다.

| 경로 | 확인한 내용 | 이 앱에서의 판단 |
| --- | --- | --- |
| 현대 순정 빌트인 캠과 마이현대 | 한 차종의 공식 설명서가 설정·재생·다운로드·공유를 안내합니다. | 소비자 기능은 확인했습니다. Pleos 제3자 앱이 실시간으로 읽는 API는 확인되지 않았습니다. |
| 사용자가 영상 파일을 가져오기 | Android에는 다른 앱이 공유한 자료를 받는 방법이 있습니다. | 정차 후 원본 앱이 파일을 내보낼 수 있다면 보조 앱으로 받아 사건에 붙이는 경로를 개발할 수 있습니다. 해당 앱의 실제 내보내기는 별도 시험합니다. |
| 허용된 사제 블랙박스 | BlackVue와 연결된 FLEETA 공식 개발 문서에서 영상·이벤트 등의 클라우드 API를 확인했습니다. | Pleos 차량에 설치한 해당 지원 기기만 별도 후보로 검토합니다. 가입·권한·기종·지역·지연·실제 파일 접근 시험이 필요합니다. |
| 블랙박스 로컬 Wi-Fi | FLEETA가 로컬 영상 조회 개요를 공개했으나 상세 가이드·명세는 준비 중이라고 안내합니다. | Pleos에서 바로 연결되는 완료 기능으로 확정하지 않습니다. 원본 앱과 동시 접속 제약 등도 확인합니다. |

현대 빌트인 캠 설명서 예시에는 Wi-Fi 연결 중 모바일 네트워크 사용이 중단된다는 안내가 있습니다. 사고 시 영상부터 가져오려고 인터넷 경로를 바꾸면 첫 알림을 지연시킬 수 있습니다. **첫 사고 알림 전송을 영상 확보보다 우선**하고, 인터넷 상태와 동시 통신은 대상 차량·휴대폰에서 시험합니다.

블랙박스의 전원도 함께 꺼지면 새 영상은 확보하지 못할 수 있습니다. 사고 구간 잠금·원본 다운로드·녹음 채널·시각·보조 전원·파일 손상을 기종별로 확인합니다. 클라우드 이벤트가 수초나 수분 뒤 도착할 수도 있으므로 급한 안내의 유일한 입력으로 사용하지 않습니다.

공식 근거: [현대 빌트인 캠 스마트폰 연결](https://ownersmanual.hyundai.com/full_webhelp/ME/2025/ko_KR/id23C63000W3M.html), [Android 자료 받기](https://developer.android.com/develop/ui/compose/sharing/receive), [FLEETA 공식 제품의 개발자 연결](https://fleeta.io/pages/developers), [클라우드 API](https://developers.fleeta.io/), [로컬 Wi-Fi 개요와 미완료 명세](https://developers.fleeta.io/docs/wifi). 이 설명서의 차량도 Pleos 지원 대상이라는 근거로 사용하지 않습니다.

## 11. 개발 단계와 통과 조건

단계는 작업 순서이며 일부 사용자 요구를 최종 범위에서 버리는 뜻이 아닙니다. 기능을 ‘지원’이라고 표시하려면 해당 단계의 실행 결과가 필요합니다.

| 단계 | 할 일 | 확인할 결과 |
| --- | --- | --- |
| 1. 대상 Pleos 환경 확인 | 차량 정보·속도·브레이크·에어백·음성·화면 제한·다른 앱 표시 중 긴급 표시 경로·휴대폰 연결 방법 확인 | 권한 결과와 지원 목록, 실제 수신값·시각·오류. 미지원 항목과 표시 불가능 상태 구분 |
| 2. 도감과 사진 찾기 | 대상 차량의 전체 공식 목록 정리, 직접·사진 검색과 센터 연결 | 목록 누락 검사, 다중 경고등·흐린 사진·다른 사양 처리, 링크·목적지 일치 |
| 3. 순간 기록과 보관 | 허용된 자료의 최근 구간·사건 저장·재생·정비 공유 | 기록 전후·재발·저장 부족·파일 중단·시각 오차·미지원 자료 처리 |
| 4. 긴급 음성·애니메이션 | 페달 확인과 감속 실패 분기, 차종별 안내 자료, 두 출력의 단계 일치 | 브레이크 상태별 올바른 분기, 지연·잘못된 알림, 화면 제한·음성 실패 처리 |
| 5. 사고 통지와 휴대폰 백업 | 즉시 첫 전송, 응답 없음·야간, 차량 중단 전후 인계 | 전송·수신·열람 구분, 두 기기 중복 사건·음성, 차단·오프라인·권한·배터리 시험 |
| 6. 블랙박스와 추가 장치 | 대상 기기의 공식 연결 방법과 동의 확인 | 실제 원본·채널·파일 잠금·시각·전원 중단·Wi-Fi와 인터넷 충돌 시험 |

특히 다음 상황을 별도로 시험해야 합니다.

- 정상적인 가속인데 브레이크를 밟지 않은 경우와 실제 긴급 요청을 구분합니다.
- 브레이크를 누른 뒤 속도가 줄지 않는 경우, 이미 줄고 있는 경우, 값이 오래된 경우를 나눕니다.
- 브레이크 값의 `true`·`false`·확인 불가, 이미 정차한 차, 정상적인 속도 유지, 후진과 방향 전환을 각각 시험합니다.
- 동승자·방송·앱 자신의 안내 음성이 사고 음성으로 반복 인식되지 않게 합니다.
- 말이 없는 사고와 에어백이 펼쳐지지 않는 사고 의심을 다룹니다.
- 휴대폰 낙하와 실제 사고 의심, 일반 시동 종료와 사고 뒤 전원 차단을 구분합니다.
- 사고 신호가 휴대폰에 전달되기 전과 뒤에 차량 앱이 종료되는 경우를 각각 시험합니다.
- 화면이 사라지거나 소리가 재생되지 않을 때 실행하지 않은 안내를 완료로 표시하지 않습니다.
- 첫 알림을 보낸 뒤 영상이 늦거나 전혀 없는 경우를 정상적인 별도 상태로 처리합니다.
- 위치 조회가 지연되거나 파일 저장이 실패해도 최소 사건 정보의 첫 전송을 시도하는지 확인합니다.
- 내비가 화면에 있고 이 앱이 화면 뒤에 있는 상태에서 음성과 화면 표시를 각각 시험하고 지연을 따로 측정합니다.

## 12. 자료 공유와 현재 미정 사항

보호자 등록·본인 확인·사전 공유 동의, 위치·문장·원본 소리·영상별 범위, 보관 기간·삭제·공유 철회를 제공합니다. 사용자가 바뀌는 Pleos 차량에서는 이전 사용자의 기록이 다음 사용자에게 열리지 않게 합니다. 보호자가 승인 없이 마이크·카메라를 켜는 기능은 포함하지 않습니다.

아직 정해야 할 사항은 실제 Pleos 시험 차량과 사양, 전체 도감의 자료 목록, 블랙박스 모델, 허용되는 원본 캡처 경로, 긴급 안내의 검토 담당과 버전 관리, 급가속·감속 실패 기준, 미응답 확인 시간·구조 요청 음성의 반복 조건, 사건 보관 용량·기간입니다. 필요한 값이 정해지지 않았다는 이유로 검증되지 않은 숫자를 제품 규칙으로 확정하지 않습니다.

## 13. 자료 기준과 이번 확인 범위

2026-11-12의 기존 SDK 리뷰·안전 기능 조사·아이디어 요약을 먼저 읽고 사용자의 최신 지시를 반영했습니다. 새로 공식 Pleos 문서, 현대 설명서·서비스 네트워크, Android 실행 조건, BlackVue·FLEETA의 공식 자료를 읽었습니다. SDK 릴리즈 문서의 버전은 기존 Vehicle 2.3.2·SpeechToText 3.3.1과 같았습니다. 배포 파일을 새로 내려받거나 기존 바이너리 검사를 다시 실행하지는 않았습니다.

경고등 모양이 사양·소프트웨어별로 다를 수 있다는 공식 설명은 분류 방식의 근거로만 사용했습니다. 확인한 DN8HEV/2026·CE1/2024·ME/2025 설명서를 실제 지원 Pleos 차량의 목록이나 긴급 조작 자료로 채택한 것은 아닙니다. [설명서 참고](https://ownersmanual.hyundai.com/full_webhelp/DN8HEV/2026/ko_KR/warning_indicator_lights.html)

시작 시 폴더는 Git 저장소가 아니었으며 앱 소스·서버는 없었습니다. 직접 수행한 것은 기존 파일 읽기, 공식 원문 열람, 일부 URL의 HTTP 확인, 기획 작성·검토·문서 검사입니다. 실제 센서·페달·음성·애니메이션·녹음·영상·블랙박스·서비스센터 API·보호자 통지·전원 차단 백업·안전 효과는 시험하지 않았습니다. 실제 메시지·신고·예약도 보내지 않았습니다.

새 자료의 주소·확인 수준, 시작 파일의 식별값, 요구사항 대응과 검토 결과는 [이번 확인 기록](integrated-vehicle-care-2026-11-12-evidence.json)에 남깁니다. SDK의 기존 정적 근거는 [종합 리뷰](pleos-sdk-review.md)와 [안전 기능 상세](../sdk/vehicle-safety-capabilities.md)에 유지합니다.

## 14. 갱신 안내

후속 작업에서는 이 기획과 SDK 상세를 먼저 읽고, 사용자 결정·Pleos 허용 범위·실제 실행 결과가 바뀌면 해당 부분과 이전 요약의 안내를 함께 갱신해야 합니다. 통합 전 기록과 과거 검사 결과는 이력으로 남깁니다. 경로는 [AGENTS.md](../../AGENTS.md)에 기록합니다.

독립된 읽기 전용 기획 검토에서 나온 네 가지 수정 사항을 반영했습니다. 브레이크 값 없음과 `false` 구분, 감속 실패 진입 조건, 저장·위치 조회와 독립된 첫 알림, 다른 앱 표시 중 긴급 화면 경로와 지연 측정을 보완했습니다. 문서 검사에서는 요구사항 22개와 화면 10개를 대조하고, 관련 Markdown 7개·로컬 링크와 제목 연결 69개·표 57개를 검사해 오류가 없었습니다. 이는 문서와 계획 검사이며 앱 실행·안전 효과 검증은 아닙니다.
