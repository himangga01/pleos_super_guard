# 차량용 앱 아이디어 여섯 가지

작성일: **2026-11-12, 한국 시간**.

**후속 변경:** 사용자가 2·5·6번을 하나의 Pleos 앱으로 합치도록 지시했습니다. 현재 기능 범위는 [Pleos 차량 이상 기록·긴급 안내 앱](integrated-vehicle-care-2026-11-12.md)을 따릅니다. 아래는 통합 전 여섯 안의 이력이며, 경고등 세 항목 제한도 현재 계획에서는 폐기했습니다. 통합 후에는 이 앱과 기존 1·3·4번이 남습니다.

지금까지 다룬 일반 앱 네 가지와 안전 기능 세 가지를 여섯 개로 묶었습니다. 이상 가속 알림과 페달 확인은 함께 사용하는 자료가 많아 하나로 합쳤습니다. 기존 아이디어를 없애거나 구현 범위를 확정한 것은 아닙니다.

이 문서는 비교를 위한 요약본입니다. 자세한 기능과 화면은 [일반 앱 네 가지](selected-app-ideas-2026-11-12.md)와 [안전 앱 세 가지](vehicle-safety-app-ideas-2026-11-12.md)에 유지합니다. 모든 기능은 기획 단계이며 앱과 서버를 만든 결과는 아닙니다.

## 1. 전체 목록

| 번호 | 이름 | 해결하려는 일 | 대표적인 사용 장면 |
| --- | --- | --- | --- |
| 1 | 세이브포인트 | 주차한 곳을 기억하고 다시 찾습니다. | 차에서 내리기 전에 층과 자리 번호를 휴대폰으로 옮깁니다. |
| 2 | 경고등 도감 | 낯선 경고등의 뜻과 공식 안내를 찾습니다. | 차를 세운 뒤 계기판 표시와 같은 그림을 고릅니다. |
| 3 | 귀가 역전골 | 동승자의 하차 장소와 운전자의 귀가 계획을 함께 정합니다. | 모임이 끝난 뒤 두 곳을 거쳐 집으로 가는 경로를 정합니다. |
| 4 | 반찬 입국심사 | 차에 실은 음식을 내려 냉장고에 넣었는지 확인합니다. | 부모님 댁에서 받은 반찬을 집에 가져와 보관합니다. |
| 5 | 이상 가속·페달 착각 대응 | 갑작스러운 가속 상황을 기록하고 페달 입력 확인과 연습을 돕습니다. | 출발 전 브레이크 입력을 확인하고 주행 중 이상 구간을 남깁니다. |
| 6 | 사고 기록·보호자 공유 | 사고 관련 신호와 전후 자료를 보관해 등록한 보호자에게 보냅니다. | 운전자가 휴대폰을 조작하기 어려울 때 위치와 받은 신호를 먼저 전달합니다. |

## 2. 세이브포인트

**주차 정보를 차에서 적고 휴대폰에서 다시 보는 앱입니다.**

큰 주차장에서 차를 찾기 어려운 사람이 사용합니다. 차에서 내리기 전에 ‘지하 3층, 보라색 기둥, 42번’처럼 층과 위치를 적습니다. 차량 위치를 받을 수 있으면 함께 저장합니다.

저장한 정보는 휴대폰 카메라로 읽는 그림인 QR코드로 옮깁니다. 돌아올 때 휴대폰에서 메모를 확인합니다. 차에 도착하면 기록을 끝내거나 지웁니다.

첫 버전에는 현재 주차 기록 한 건, 메모 수정, QR코드, 휴대폰 보관 기능을 넣습니다. 위치를 받지 못해도 메모는 저장할 수 있게 합니다.

층과 주차면 번호를 자동으로 알아내거나 실내 보행 길을 안내하는 기능은 포함하지 않습니다. 기존 주차 저장 기능과 비교해 차량 화면에서 기록을 옮기는 과정이 실제로 편한지 확인해야 합니다.

상세 내용: [주차 기록의 화면과 실패 처리](selected-app-ideas-2026-11-12.md#1-세이브포인트).

## 3. 경고등 도감

**자기 차에 맞는 경고등 설명을 쉽게 찾는 앱입니다.**

경고등 이름을 모르는 운전자가 사용합니다. 차를 세운 뒤 계기판과 같은 그림을 고르고, 계속 켜지는지 깜박이는지 선택합니다. 앱은 해당 차종의 공식 설명을 짧게 보여 주고 원문으로 연결합니다.

첫 버전은 한 차종의 안전벨트, 연료 부족, 타이어 공기압 세 항목으로 제한합니다. 모델·연식·판매 지역이 맞는지 먼저 확인하고, 설명을 소리로 읽는 기능도 후보로 둡니다.

표시를 골랐다는 이유로 고장 원인이나 수리 방법을 확정하지 않습니다. 차종이 다르거나 조건을 모르면 설명을 확정하지 않습니다. 차량 경고등과 자동으로 연결하는 기능은 권한과 실제 수신 결과를 확인한 뒤 확장합니다.

상세 내용: [경고등 설명 자료와 화면](selected-app-ideas-2026-11-12.md#2-경고등-도감), [경고 표시 조회·구독의 권한 차이](../sdk/vehicle-safety-capabilities.md).

## 4. 귀가 역전골

**동승자를 내려 준 뒤 운전자도 계획한 시각에 귀가할 수 있도록 일정을 정하는 앱입니다.**

운동이나 모임을 마치고 여러 사람이 한 차를 탈 때 사용합니다. 운전자는 마지막 목적지와 귀가 목표 시각을 적습니다. 동승자들은 내릴 장소를 정하고 방문 순서를 함께 확인합니다.

예를 들어 세 명을 두 지하철역에 나누어 내려 준 뒤 운전자의 집으로 가는 계획을 만듭니다. 내비에서 유효한 도착 예상 정보를 받으면 귀가 목표보다 얼마나 빠르거나 늦는지 보여 줍니다. 이 계산은 필요한 시간 정보의 수신과 단위를 확인한 뒤 구현해야 합니다.

첫 버전은 하차 장소 두 곳과 마지막 목적지 한 곳을 내비에 보내는 범위입니다. 내비 도착 신호가 와도 실제 하차 여부는 사람이 확인합니다. 계획 변경은 정차 후 진행합니다.

가장 좋은 경로를 자동으로 찾아 주거나 막차 탑승을 보장하는 기능은 포함하지 않습니다. 목표 시각을 지키기 위해 속도를 높이라고 안내하지 않습니다.

상세 내용: [귀가 계획의 이용 순서와 내비 조건](selected-app-ideas-2026-11-12.md#3-귀가-역전골).

## 5. 반찬 입국심사

**차에 실은 음식을 냉장고에 넣을 때까지 확인하는 앱입니다.**

부모님 댁에서 받은 반찬이나 냉장할 케이크를 가져오는 사람이 사용합니다. 출발 전에 음식 이름과 수량을 적고, 도착하면 내려야 할 목록을 확인합니다.

기록은 ‘차에 실음 → 차에서 내림 → 냉장고에 넣음’ 세 단계로 나눕니다. 예를 들어 국 한 통만 내렸다면 반찬 한 통은 목록에 남깁니다. 냉장고에 넣은 뒤에는 휴대폰에서 완료를 표시합니다.

첫 버전에는 음식 목록, 단계별 확인, 휴대폰 체크리스트를 넣습니다. 휴대폰의 완료 상태를 차량에도 반영하려면 두 기기의 기록을 전달하는 서버가 필요합니다. 전송에 실패하면 완료된 것처럼 표시하지 않습니다.

이 앱은 음식 속 온도나 실제 보관 상태를 알지 못합니다. 먹어도 되는지, 언제 상하는지, 안전 시간이 얼마나 남았는지는 판정하지 않습니다. 도착한 것만으로 냉장 보관이 끝났다고 표시하지도 않습니다.

상세 내용: [음식 보관의 세 단계와 확인 범위](selected-app-ideas-2026-11-12.md#4-반찬-입국심사).

## 6. 이상 가속·페달 착각 대응

**갑자기 속도가 늘어난 구간을 기록하고, 브레이크 입력 확인과 페달 선택 연습을 돕는 앱입니다.**

기존의 이상 가속 알림과 페달 확인 도우미를 합친 안입니다. 출발 전에는 정차 상태에서 브레이크 입력을 읽을 수 있는지 보여 줍니다. 주행 중에는 속도·브레이크 상태·위치와 인식한 말을 같은 시간표에 남깁니다.

사용자가 제시한 ‘어 이거 왜이래!’, ‘아이고!’, ‘안돼!’를 음성 시험 문장에 포함합니다. 이런 말과 유효한 차량 상태 변화가 겹치면 위험이 의심되는 구간으로 표시합니다. 말만으로 급발진이나 페달 착각을 확정하지 않습니다.

페달 선택 연습은 별도 모형 페달이나 시뮬레이터에서 진행합니다. 어떤 페달을 골랐는지와 반응 시간을 보여 줍니다. 실제 차량에서 가속 페달을 밟게 하는 연습은 첫 버전에 넣지 않습니다.

현재 공식 경로에서 확인한 자료는 실제 차량 속도, 브레이크 입력 여부, 음성 인식 결과입니다. 가속 페달의 눌린 비율은 대상 차량과 개발 환경에서 지원하는지 추가 확인이 필요합니다. 브레이크 입력 신호도 실제 제동력을 뜻하지 않습니다.

공개 SDK에서 즉시 브레이크를 작동시키거나 가속을 차단하는 기능은 확인되지 않았습니다. 따라서 첫 버전의 범위는 입력 확인·연습·알림·기록입니다. 실제 자동 정지 기능은 제조사의 안전 제어와 별도 개발·검증이 필요합니다.

상세 내용: [이상 가속 알림](vehicle-safety-app-ideas-2026-11-12.md#3-이상-가속-알림), [페달 확인 도우미](vehicle-safety-app-ideas-2026-11-12.md#4-페달-확인-도우미).

## 7. 사고 기록·보호자 공유

**위험 상황이나 사고 관련 신호가 들어오면 당시 자료를 보관하고 등록한 보호자에게 보내는 앱입니다.**

평소부터 최근 자료를 짧게 보관하고, 사건이 생기면 해당 구간을 지우지 않는 방식입니다. 사건 전 30초와 후 60초를 첫 시연의 예시로 정했습니다. 이 시간은 기획값이며 SDK가 보장하는 길이는 아닙니다.

사용자의 긴급 요청이나 새 에어백 전개 신호를 받으면 위치와 받은 신호부터 보냅니다. 놀란 말·급격한 속도 변화·기울기 등은 위험을 의심하는 보조 자료로 검토합니다. 모든 사고를 미리 예측하거나 에어백 신호만으로 전부 감지한다고 설명하지 않습니다.

사용 가능한 자료는 시간에 맞춰 다시 볼 수 있게 합니다. 차량 상태, 위치, 인식 문장은 기본 후보입니다. 실내·외 영상과 원본 소리는 공식 사용 경로와 권한이 확인될 때 추가합니다. 내부 음성 인식 결과가 원본 녹음 파일까지 제공하는 것은 아닙니다.

외부 마이크와 차량 기울기·가속도·회전 센서는 실제 장치 지원 여부를 확인해야 합니다. 핸들 각도를 차체 기울기로 대신하지 않습니다. 자료가 없으면 미지원이나 기록 없음으로 표시합니다.

보호자 등록과 공유 동의를 먼저 받고, 위치·문장·녹음·영상의 공유 범위를 나눕니다. ‘차량 저장’, ‘서버 수신’, ‘보호자 기기 도착’, ‘보호자 열람’도 따로 확인합니다. 통신이나 전원이 끊기면 기록과 전달에 빈 구간이 생길 수 있습니다.

첫 버전에는 사건 기록, 보호자 등록, 위치·차량 상태 전달, 수신 상태 확인을 넣습니다. 영상과 녹음이 없더라도 이를 숨기지 않고 자료별 상태를 보여 줍니다. 보호자 화면과 서버는 별도로 개발해야 합니다.

## 8. 개발 범위를 비교할 때 확인할 것

SDK는 앱이 차량 기능을 사용할 때 쓰는 개발 도구입니다. 아래는 사용 후보와 앞으로 확인할 일이며 실행 성공 목록은 아닙니다.

| 앱 | 차량에서 사용할 후보 | 별도로 만들 부분 | 가장 먼저 확인할 것 |
| --- | --- | --- | --- |
| 세이브포인트 | 위치 | 주차 메모·QR코드·휴대폰 보관 화면 | 휴대폰에 옮긴 기록을 다시 열 수 있는지 |
| 경고등 도감 | 설명 읽기. 차량 상태 자동 연결은 확장 단계 | 검토한 차종별 설명 자료 | 그림·차종·표시 조건과 설명이 정확히 맞는지 |
| 귀가 역전골 | 내비 경유지·경로 요청·시간 정보 | 하차 계획과 귀가 목표 비교 | 경로 요청과 필요한 시간 정보를 받을 수 있는지 |
| 반찬 입국심사 | 도착 알림·선택적 음성 안내 | 음식 목록·휴대폰 확인·상태 전달 서버 | 냉장고 보관 확인이 차량 기록까지 전달되는지 |
| 이상 가속·페달 착각 대응 | 속도·브레이크·음성·위치 | 의심 구간 기록·모형 페달 연습 | 실제 수신값과 오류를 구분하고 잘못된 알림을 측정할 수 있는지 |
| 사고 기록·보호자 공유 | 에어백·속도·위치·음성 등 허용된 정보 | 사건 저장·서버·보호자 화면 | 사건 전후 구간과 전달 상태를 누락 없이 구분하는지 |

차량에서 기록을 시작해 휴대폰으로 이어지는 안은 세이브포인트, 반찬 입국심사, 사고 기록·보호자 공유입니다. 경고등 도감과 귀가 역전골은 차량 화면에서 설명이나 계획을 확인하는 일이 중심입니다. 이상 가속·페달 착각 대응은 차량 신호의 실제 제공 범위가 첫 개발 범위를 크게 바꿉니다.

아직 정하지 않은 사항은 경고등 도감의 첫 대상 차종, 휴대폰 화면의 제공 방식, 안전 앱의 잘못된 알림 허용 기준, 원본 소리·영상의 제공 장치와 보관 기간입니다. 이 문서에서는 개발 순위나 최종 출품작을 확정하지 않습니다.
