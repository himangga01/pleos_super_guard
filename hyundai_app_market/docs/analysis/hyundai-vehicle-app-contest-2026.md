추가 공지는 대표자가 아닌 팀원의 이메일 제출도 허용한다. 전자서명·서명 이미지, DOCX·PDF 제출이 인정된다. 필수 항목과 순서를 유지하면 글꼴·표·이미지·도표를 조정할 수 있다. PPT·PDF·HTML 보조자료는 참고용이며, 영상·첨부자료 분량 제한은 따로 없다. [접수 관련 추가 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000007)

**2026-11-12 제출 형식 재확인:** 자유양식 문서 하나로 대체하는 방식이 아니라 공식 접수양식의 필수 항목과 순서를 유지해 작성하는 방식입니다. 작성·서명한 양식은 **DOCX 또는 PDF**로 제출할 수 있습니다. 별도 PPT·PDF·HTML은 참고용 추가 자료입니다. 공식 양식 안의 소개 자료 분량에는 제한이 없고 작성란을 늘릴 수 있습니다. 현재 상세 PRD는 공식 양식 항목에 맞춘 제출본과 별첨 기술 명세 PDF로 구성하는 안을 권합니다. 이는 제출 구성 제안이며 실제 파일 작성·변환·이메일 제출을 수행한 것은 아닙니다.

이번에는 [지원·제출 방법](https://appdevchallenge.auto-hmg.io/guide/submission)을 다시 열고, 추가 공지를 직접 HTTP로 받아 위의 형식·서명·추가 자료 문구를 확인했습니다. 공식 DOCX도 HTTP 200·55,208바이트로 다시 읽었으며 SHA-256은 `07be893d58b0e96ab7788f0d189d6829f0e59a2cee4bc18cb90ec37eeda2f5fd`입니다. ZIP 내부 `word/document.xml`에서 양식 자체가 기획서라는 안내, 항목, 분량 문구를 확인했습니다. PDF 변환·인쇄 레이아웃·서명·접수 성공 검증은 포함하지 않습니다.

**2026-11-12 글자 수 제한 재확인:** 공식 제출 안내를 다시 열고 연결된 DOCX를 새로 받아 확인했습니다. HTTP 200, 55,208바이트, 위 SHA-256과 동일합니다. 양식은 소개 자료 분량 제한이 없다고 명시하며, 여러 줄 항목의 기본 입력 공간은 약4줄이지만 내용이 길면 작성란이 늘어난다고 안내합니다. 항목별500자·1,000자 같은 숫자 제한은 명시되어 있지 않고 DOCX의 `maxLength` 요소도 없습니다. 1번 ‘앱 한 줄 소개’는 글자 수 제한 대신 **한 문장으로 소개**하라는 내용 지침입니다. 따라서 현재8쪽 공식 양식은 확인된 글자 수·분량 제한을 초과한 것이 아닙니다. 이 확인은 분량 규칙에 관한 것이며 실제 제출·접수 검증은 아닙니다. 추가 공지의 웹 도구 열람은 이번 호출에서 오류가 났으므로 새로 읽은 것으로 취급하지 않았고, 위 결론은 직접 재수신한 공식 양식을 근거로 합니다.

회원가입이 없다는 설명은 **공모전 접수**에 관한 것이다. Pleos 개발자 포털의 계정·프로젝트 절차는 별개다.

## 5. 접수양식 DOCX의 모든 작성 영역

공식 파일을 실제 내려받아 ZIP 내부의 `word/document.xml` 텍스트를 확인했다. 파일은 55,208바이트였고 동의서 표시는 `1020 ver.`이다. 아래는 작성 영역의 구조를 재정리한 것이다. 페이지 수나 인쇄 레이아웃을 검증했다는 의미는 아니다. [공식 DOCX](https://appdevchallenge.auto-hmg.io/downloads/contest-application-consent.docx)

### 5.1 운영 접수 정보

- 개인·팀 구분, 대학(원)생·일반 부문 선택.
- 팀명 또는 개인 이름, 앱·프로젝트명.
- 대표자 이름·역할·이메일·휴대폰번호, 선택 사항인 소속.
- 인원과 작성일.
- 대표자 포함 전원의 이름·소속·휴대폰·이메일·담당 역할.

주민등록번호·신분증·상세주소는 요구하지 않는다. 참가비는 받지 않는다고 양식에 명시한다.

### 5.2 심사용 앱 소개의 8개 항목

| 번호 | 작성 주제 | 포함할 내용 |
| --- | --- | --- |
| 1 | 앱의 짧은 소개 | 한 문장 설명 |
| 2 | 기획 이유 | 대상 고객과 해결할 불편 |
| 3 | 기능·차량 적합성 | 해결 방식과 차 안에서의 가치 |
| 4 | 사용 흐름 | 누가 언제 어떻게 쓰는지 |
| 5 | 구현 계획 | Pleos Connect 개발 범위와 SDK·API 계획 |
| 6 | 효과·확장성 | 고객 분석, 예상 MAU·재이용, 확대 계획 |
| 7 | 선택 참고자료 | 화면·시연·저장소 등. 가산점 대상 |
| 8 | 선택 숏폼 | 게시 링크. 본상 가산점 없음 |

소개자료에는 이름·소속·연락처를 쓰지 않고 운영용 첫 영역에만 적는다. 공유 링크·첨부에도 실명·계정 정보가 드러나지 않는지 확인한다. 소개자료 분량 제한은 없고 별지 추가도 가능하다.

### 5.3 동의와 서명

개인정보 이용 목적·항목·기간·거부 시 제한, 수탁사 안내가 있다. 마지막 영역에 대표자와 각 팀원이 **동의 여부·본인 서명·서명일자**를 작성한다. CC 주소는 다른 수신자에게 보인다는 점도 팀원에게 알려야 한다.

## 7. 심사 기준과 가산점

1차 평가에는 다음 네 항목이 필수다. **배점은 공개하지 않는다.** [심사·시상](https://appdevchallenge.auto-hmg.io/guide/judging-awards)

| 항목 | 평가 내용의 의미 |
| --- | --- |
| 차량 적합성 | 휴대폰 대비 차 안에서 얻는 가치, 주행·정차 및 차량 기능과의 연결 |
| 창의성 | 새로운 접근, 운전자·동승자의 문제 정의와 해결 방식 |
| 기술 활용 | Pleos의 SDK·API가 핵심 기능과 사용 경험에 적절히 쓰이는지 |
| 사업성 | 고객 구체성, 이용자 확보·유지·확장 가능성. MAU·Retention 등의 근거 |

MAU는 월간 활성 이용자 수, Retention은 일정 기간 뒤 이용자가 다시 사용하는 비율을 뜻한다. 예를 들어 첫 주 이용자 100명 중 다음 주에도 30명이 쓰면 이 정의의 주간 재이용 비율은 30%다. **이는 용어 설명용 가상 수치이며 공모전 요구 목표가 아니다.**

시연 영상·소스·APK를 선택 제출하면 단계별 가산점이 있다. 단계별 정확한 점수·상한·영상과 저장소의 조합별 산식은 공개하지 않는다. 2차의 세부 심사 기준도 추후 안내 항목이다.

**연구자 해석:** 단순한 모바일 앱 이식보다 차량 데이터가 서비스 판단에 실제로 영향을 주는 설계가 평가 항목과 잘 맞는다. 이는 공개 항목을 읽은 해석이며 수상 가능성이나 특정 아이디어의 우위를 검증한 결과가 아니다.

## 11. 개발 범위에 적용되는 공모전의 제한

다음 조건은 일반 제품 소개보다 **공모전 개발 범위 공지**를 우선 확인해야 하는 이유다. [개발 범위 및 기술 문의 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)

| 항목 | 공모전의 안내 |
| --- | --- |
| 허용 개발 범위 | 현재 공개된 Pleos Playground SDK·API 문서의 지원 범위 |
| 공개 SDK 다섯 개 | Vehicle·NaviHelper·TTS·STT·FusedLocation 모두 출품 사용 가능. 워크스페이스 ‘준비 중’ 표기와 무관하게 문서대로 에뮬레이터 개발·시험 가능 |
| 문서에 없는 기능 | 구현 대상으로 사용할 수 없으며 향후 계획으로 구분 가능 |
| 미공개 SDK | 기간 중 제공되지 않고 참가자에게 선공개도 하지 않음 |
| Gleo 연동 | 참가팀의 Gleo Interface·App Schema 검토·승인 신청 불가 |
| 차량 마이크 | 외부 음성 인식 서비스로 보내는 구현은 미지원·사용 불가 |
| 음성 인식 경로 | SpeechToText SDK 이용 안내 |
| 2차 시연 | Pleos Connect 에뮬레이터에서 작동하는 앱 |
| 실제 차량 | 심사에 필요 없음 |
| 별도 지원 | 장비 대여·실차 측정 장소·별도 기술 지원 창구 없음 |
| 운영사 문의 | 자격·접수·제출·일정에 한정. 개별 API 동작·구현법 답변 제외 |
| 마켓과의 관계 | 공모전 심사는 앱 마켓 입점 심사와 별개 |

**범위 해석:** 차량 마이크 음성을 외부 STT로 보내는 금지를 모든 외부 API 사용 금지로 확대하지 않았다. 반대로 문서에 없는 기능을 임의로 허용된 것으로 취급하지도 않았다. 아이디어의 필수 경로에 공개 지원이 없는 기능이 들어간다면 이를 구현 완료로 제시할 근거가 없다.

## 12. Pleos 플랫폼 구조와 개발 환경

### 12.1 이름과 구성요소

### 12.4 Virtual Console을 이용한 시연 준비

최소 지원 에뮬레이터는 2.1.0이다. 에뮬레이터의 8088 포트를 PC에 연결한 후 브라우저로 연다. 아래는 **문서에 안내된 명령으로, 이 조사에서 실행하지 않았다.** [셋업 원문](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/use-vehicle-emulator)

```powershell
adb forward tcp:8088 tcp:8088
```

브라우저 주소는 `http://127.0.0.1:8088/`이다. 이는 참가자 PC의 로컬 주소여서 보고서 독자에게 공개 원격 서비스처럼 링크하지 않았다.

| 콘솔 영역 | 시험할 수 있다고 설명하는 상태 |
| --- | --- |
| Vehicle | 차량 알림 |
| Motion | 기어·브레이크·조향·주행 거리 |
| ADAS | 크루즈 제어 상태·목표 속도 |
| Convenience | 도어·창문·시트·조명·와이퍼 등 |
| Safety | 주차 브레이크·안전벨트·경고등 |
| Energy | 잔여 거리·배터리·충전 |
| Climate | 공조·열선·통풍 등 |

테마·시점 변경은 시험 기능과 별개다. 기능이 콘솔에 나타난다는 사실과 출품 앱의 제어 권한·실차 지원 여부는 구분해야 한다.

### 13.2 Vehicle SDK

앱은 `Vehicle` 진입점에서 도메인 객체를 얻는다. 기능 지원·값 범위를 확인하는 Capability API, 조회, 설정, 상태 변경 구독이 구분된다. 호출 결과는 비동기일 수 있으므로 완료 전에 SDK를 해제하지 않아야 한다. [Vehicle 소개](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro)

문서에 열거된 도메인은 **Brake, CarInfo, Display, Door, DrivingMode, EvBattery, Fuel, HVAC, Light, Odometer, Safety, Seat, SideMirror, Steeringwheel, Tire, Toll, TurnSignal, Window, Wiper**다. 각각 제동, 차량 기본정보, 표시 단위, 문, 운전 모드, EV 배터리, 연료, 공조, 조명, 거리·시간, 경고, 좌석, 미러, 핸들, 타이어, 통행료 장치, 방향지시등, 창문, 와이퍼에 대응한다.

도메인 존재만으로 모든 기능이 쓰기 가능하지는 않다. 앱 권한, 대상 영역, 실제 Capability와 오류를 확인해야 한다. 소개 페이지의 Vehicle Service 기준은 **2.3.21**인데 Sample App 가이드는 **2.3.22**를 사용한다. 문서별 기준 환경 차이를 기록하고 실제 설치 환경과 맞춰야 한다.

Vehicle 의존성 연동 문서는 `ai.pleos.playground:Vehicle:2.3.2`를 안내한다. 반면 빠른 시작 예제에는 2.3.1이 남아 있다. 새 출품 앱의 버전은 최신 릴리즈·개별 연동 문서와 일치시키고 실제 빌드로 확인해야 한다. [Vehicle 가져오기](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/project-setup), [빠른 시작](https://document.pleos.ai/docs/pleos-only/getting-started)

### 13.3 NaviHelper SDK

내장 내비 서비스에 목적지·경유지·경로 재탐색·내비 화면 요청을 전달하고 이벤트로 결과를 받는다. 초기화, 리스너 등록, 요청, 콜백 처리, 해제 순서다. 제공 이벤트는 내비 앱의 구현과 상태에 따라 달라질 수 있다. 앱이 독립적인 전체 지도·내비 엔진을 받는다고 확대 해석하지 않았다. [NaviHelper 소개](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro)

### 13.4 TextToSpeech SDK

텍스트를 합성해 차량 오디오로 재생한다. `HYBRID`는 서버 우선 후 연결 실패 시 기기 내 엔진으로 전환, `SERVER`는 서버 전용, `ON_DEVICE`는 기기 내 처리다. 서버 기반 모드는 네트워크와 My Project 자격정보를 이용한 앱 등록이 필요하다고 설명한다. 기기 내 모드는 서버 등록이 필요 없다고 설명한다. 공모전 사용 허용과 서버 등록·실제 실행의 성공 여부는 구분한다. [TTS 소개](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro)

### 13.5 SpeechToText SDK

발화를 텍스트로 바꾸는 SDK다. 발화만 인식하고 음악 재생 등 명령의 실제 동작을 자동 실행하지 않는다. 모드는 TTS와 같은 세 종류이며 서버 방식에는 등록·네트워크 조건이 있다. 일반 문서는 명령 실행 연계로 Gleo를 소개하지만, **공모전에서는 Gleo 승인 신청이 불가능**하다. 따라서 음성 인식 문서가 있다는 이유만으로 Gleo를 쓰는 출품 계획을 확정할 수 없다. [STT 소개](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/intro), [공모전 제한 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)

### 13.6 FusedLocation SDK

최근 위치의 단발 조회, 위치 업데이트 구독·해제, 특정 영역 진입·이탈 알림을 설명한다. `isSupported()`로 실행환경을 먼저 확인한다. 마지막 위치는 새 위치 측정 결과와 같지 않고 값이 없으면 `null`일 수 있다. 위치 데이터에는 위도·경도·고도·방향·신뢰도·시각이 포함된다. 필요 권한은 `pleos.car.permission.FUSED_LOCATION`이다. [위치 SDK 소개](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/intro)

### 13.7 ‘준비 중’ 표기와 공모전 사용 허용

**프로젝트 생성·SDK 사용 신청 문서**에는 다음 상태가 기재되어 있다. [해당 원문](https://document.pleos.ai/docs/pleos-only/create-my-project)

| 구분 | 프로젝트 신청 문서의 표기 |
| --- | --- |
| Vehicle State·NaviHelper | 신청 없이 사용 가능 |
| FusedLocation·TextToSpeech·SpeechToText·Vehicle Control | 준비 중, `Comming Soon` 표기. 신청 불가 |
| 신청이 필요한 기능 | 신청 후 검토·승인 절차 |
| 별도 제휴가 필요한 기능 | 사이트 신청 방식이 아닌 계약 담당자 문의 |

이 문서는 계정 가입·프로젝트 생성, SDK별 상태 확인 절차도 설명한다. 서버 연결용 Client ID·Client Secret, 마켓용 프로젝트 키 등이 있으며, **에뮬레이터 2.1.0 이후 CRN 입력은 필요 없다고 안내**한다. 이 조사에서 개인 계정 로그인이나 자격정보 열람은 하지 않았다.

**2026-11-11 후속 SDK 조사에서 갱신:** 현재 [공모전 개발 범위 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)는 다섯 SDK 모두 출품작에 사용할 수 있고, 워크스페이스의 ‘준비 중’ 표기와 관계없이 문서대로 에뮬레이터에서 개발·시험할 수 있다고 명시한다. 따라서 공모전의 사용 허용 여부는 이 안내를 따른다.

1. **허용 확인:** Vehicle·NaviHelper·TextToSpeech·SpeechToText·FusedLocation 모두 공모전 사용 가능.
2. **배포 확인:** 해당 버전 POM 5개·AAR 5개를 공개 접근으로 확인했다.
3. **실행 미확인:** 계정·AVD의 실제 서비스 동작, 음성 서버 인증, Vehicle 기능별 Capability·제어 범위.
4. **계속 적용되는 제한:** 공개되지 않은 SDK·Pleos LLM SDK, Gleo 승인 신청, 차량 마이크 외부 음성 인식 전송.

18:47 최초 보고서에서는 문서 상태 차이를 이유로 허용 여부를 미확정으로 남겼다. 그 판단은 후속 확인으로 갱신했다. 공지의 정확한 게시·수정 시각은 표시되지 않아 추정하지 않는다. 자세한 API·샘플 검토는 [SDK 심화 리뷰](pleos-sdk-review.md)에 기록했다.

| FusedLocation | 위치 콜백이 nullable로 변경, 오류 콜백 구현 필요, 영역 진입·이탈 알림 추가 |

### 13.9 샘플 앱을 복사할 때의 별도 조건

Vehicle 샘플 가이드는 JDK 17, Gradle 8.10.2, Android Gradle Plugin 8.8.2, Kotlin 2.0.0, compileSdk·targetSdk 35, 샘플 minSdk 23을 기록한다. **배포할 제품 앱의 최소 API 28 조건은 별도로 유지**된다고 문서가 직접 구분한다. [Sample App 가이드](https://document.pleos.ai/docs/pleos-only/tutorial/vehicle-sdk-sample-app)

샘플은 일반 휴대폰 이미지가 아닌 Pleos 전용 AVD를 전제로 한다. 초기화 성공 표시는 서비스 연결·기능 지원의 완료 증거가 아니며, 제어 요청 완료와 실제 상태 변경도 구분한다. 실제 조회·변경 알림으로 검증하고, 필요한 권한과 구독만 사용해야 한다. 조사에서는 샘플을 빌드·설치하지 않았다.

Gleo는 App Schema에 함수와 호출 방식을 정의해 차량 AI와 앱이 상호작용하는 별도 인터페이스다. 일반 가이드가 존재한다는 사실과 공모전에서 승인 신청이 가능한지는 다르다. [Gleo 일반 문서](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/core-concepts)

### 13.10 개발 문서 심화 리뷰

SDK별 공식 가이드·참조 시작점 49개, 추가 API 경로, 공개 패키지와 공식 샘플을 대조했다. Java 목적지 생성자, 경유지 콜백 철자, Vehicle 구독·Set 예제에서 실제 배포 API와 다른 지점을 확인했다. [개발 문서 전체 모음](../sdk/README.md)과 [리뷰 F1~F7](pleos-sdk-review.md)을 후속 개발의 기준으로 읽는다.

| 예전 도구 설명과 2.1.0 릴리즈 | LLM SDK·CRN·동글 기능 종료 | 종료 기능이 필요한 과거 예제를 그대로 전제하지 않음 |
| 최초 제출 안내와 추가 공지 | 대표자 제출 설명과 팀원 발신 허용 | 추가 공지의 허용 반영. 수정 발신자는 최초 주소 유지 |
| 제출 페이지의 입력 표현 | ‘제출 페이지에 입력’과 실제 이메일 접수 설명 공존 | 별도 웹 접수 폼을 추정하지 않고 이메일에 경로·해시 포함 |
| 설명회 일정과 실제 연결 자료 | 다시보기 예정 문구, URL 미확인 | 영상 공개·시청 완료로 표시하지 않음 |
| 결과 발표 단계 | 12월 선정, 2월 순위 공개 | 최종 순위 발표일을 12월로 단정하지 않음 |
| 개인정보관리 안내와 사이트 구조 | 가입 없는 접수와 일반 회원관리 문구 공존 | 실제 계정·삭제 화면 구현을 추정하지 않음 |

개발 환경의 예시 ‘음성 메모’, ‘안전운전 점수’, ‘배달 기사 지원’도 **아이디어 예시**다. 각 예시의 필수 데이터와 API가 모두 무조건 사용 가능하다는 실행 증거로 취급하지 않았다.

## 20. 아직 공개되지 않았거나 확인하지 못한 질문

다음은 참가자가 실제 의사결정을 위해 확인할 수 있는 질문 목록이다. 답을 임의로 채우지 않았다.

### 참가·제출

- 대학원생·휴학생·혼합 팀의 구체적 부문 분류와 증빙 방식은 무엇인가?
- 중복 참여·다작·팀원 교체를 허용하는가?
- 기존 공개 앱·기존 개발작의 어느 범위까지 출품 가능한가? 타 공모전 수상작 제외 외 기준은 무엇인가?
- 공개 GitHub 이력에서 개발자 정보가 보이는 경우 심사용 익명 처리와 어떻게 양립시키는가?
- 이메일 수신 확인 방식과 첨부 용량·링크 서비스 제한은 있는가?

### 개발·심사

- 서버형 TTS·STT의 자격정보·인증과 각 SDK의 AVD 구동 조건을 실제 환경에서 충족하는가?

- 어떤 차량 제어 API·권한·영역이 참가 에뮬레이터에 실제 제공되는가?
- 1차 개발 산출물의 가산점 단계와 배점, 2차 PT의 평가 기준은 무엇인가?
- PT 시간·발표자·참석 인원·장비·인터넷·최종 산출물 제출 마감은 언제인가?
- 설명회 다시보기는 어느 공식 URL에서 제공되는가?

### 수상·후속 행사

- 2027년 2월 행사의 정확한 일시·장소·현장 운영 의무는 무엇인가?
- 교통·숙박·시연 장비·전시 제작 지원 범위는 무엇인가?
- 우선협상·수상자료 보관의 기산일인 결과 발표일은 어느 단계인가?
- 실제 통상실시 계약, 보상·기간·지역·이용 범위는 어떻게 정하는가?
- 숏폼의 평가 기준·중복 수상·공개 유지 조건은 무엇인가?
- 마켓 탑재 지원의 범위, 적용 차종·지역·정식 입점 일정은 무엇인가?

## 22. 실제 검증과 한계

### 이번에 수행한 확인

- 검색으로 공식 공모전과 현대자동차그룹 보도자료를 찾은 뒤 원문을 열었다. 검색 결과 요약만으로 결론을 확정하지 않았다.
- 공모전 공개 페이지 20개를 열람하고, 공지 목록 5건을 모두 확인했다.
- Chrome을 이용해 제출 안내·문의·공지·FAQ 화면을 직접 열었다. 실제 DOM에서 FAQ 질문 21개와 공지 링크 5개를 확인했다.
- DOCX 응답의 실제 형식·크기·SHA-256을 확인하고 내부 XML에서 네 작성 영역과 세부 항목을 읽었다.
- 최종 포스터 원본을 내려받아 이미지를 눈으로 확인했다.
- SDK별 소개·릴리즈·설치·설정·프로젝트 신청·샘플 등 개발 문서를 비교했다.
- 원문 전체 복제 대신 원문 링크를 달라는 사용자의 후속 지시에 따라, 전체 출처 목록을 별도 Markdown에 기록했다.

### 확인 범위를 넘는 것

- 로그인한 Pleos Workspace의 현재 SDK 상태·허가·키는 열람하지 않았다.
- Android Studio·SDK·에뮬레이터·샘플·출품 앱을 설치하거나 실행하지 않았다.
- 실제 차량, 차량 제어, 마이크, 위치, 내비게이션을 시험하지 않았다.
- 설명회 영상을 확보·시청하거나 운영사에 메일을 보내지 않았다.
- DOCX의 텍스트 구조만 검증했다. 인쇄 레이아웃·페이지 수·서명 기능을 렌더링 검증하지 않았다.
- 개발 문서의 모든 API Reference와 하위 가이드 전체를 수집한 것은 아니다. 공모전 안내 전체와 참가 조건에 직접 영향을 주는 연결 문서를 조사 범위로 삼았다.
- 오래된 Vehicle 튜토리얼 링크는 본문이 비어 있어 내용을 검증하지 못했다. 별도의 정상 Sample App 가이드를 확인하고 두 링크를 구분했다.
- 홈페이지·개발 문서는 변경될 수 있다. 제출 직전 공지·양식·SDK 버전을 다시 확인해야 한다.

CLI 확인 도구의 단일 URL 검증 결과는 `weak_ok`였다. 이를 전체 조사에 대한 자동 `sufficient` 판정이라고 바꾸어 쓰지 않았다. 사실 판정은 열린 공식 원문과 브라우저 화면의 직접 대조를 근거로 했다. 세부 도구·파일 검사는 [출처 및 검증 기록](hyundai-vehicle-app-contest-2026-sources.md)에 기록한다.
