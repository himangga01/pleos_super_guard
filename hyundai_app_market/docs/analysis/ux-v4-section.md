## 4. Pleos 화면 맞춤 UI/UX 상세 설계서 (v4)

> **대체 관계**: 이 문서는 [ux-v3-section.md](ux-v3-section.md)(4장, 가로 1280×720 시안 10장 기준)를 **대체**합니다. v3 문서는 이력으로 그대로 둡니다. v3의 "주행 중 허용된 짧은 설명 움직임", "긴급 화면의 발·페달 그림", "보호자 화면의 카카오톡 전달됨·문자 대체 준비 동시 표시", "1280×720 기준 좌표"는 이 문서에서 바뀌었습니다.
>
> 작성일: 2026-11-12. 근거는 1차 비판 반영 결정(D7·D8·D10·D12~D16, 새 기능 N1~N10, 7장 용어·화면 이름·신호 표)입니다. 화면은 모두 **설계 시안**입니다. 앱 구현, 에뮬레이터 실행, 실제 운전 사용성 시험을 한 결과가 아닙니다.

### 4.1 그대로 두는 시각 방향

- 사용자가 확정한 방향을 유지합니다. 디 올 뉴 아반떼 실제 차량 이미지가 홈의 중심입니다. 부위 점을 눌러 증상 아이콘으로 이어집니다.
- 이모지를 쓰지 않고 아이콘을 씁니다. 앱 글꼴은 Pretendard입니다.
- 어두운 배경에 민트(기록)·앰버(경고등·점검·정비소)·레드(긴급)·퍼플(보호자·위치)을 강조색으로 씁니다.
- 긴급 화면은 일반 탭을 숨기고 붉은 배경과 위험 띠를 써서 일반 메뉴와 구별합니다.
- 바뀐 점은 규정과 부딪히는 부분뿐입니다. 세로 한 창을 추가했고, 주행 중 움직임과 발 그림을 뺐습니다. 경고등 기호를 새로 그렸고, 보호자 상태 모순과 대비 미달 색을 고쳤습니다.

### 4.4 세로 ↔ 가로 대응 (기능 패리티)

| 요소 | 세로 한 창 | 가로 |
| --- | --- | --- |
| 메뉴 | 위쪽 탭 4개(경고등 찾기 · 증상 기록 · 보호자 알림 · 정비소). 홈은 로고 | 왼쪽 도크 5개(홈 · 경고등 · 기록 · 보호자 · 정비소) |
| 차 그림 | 가운데. 주행 중에는 숨김 | 가운데. 주행 중에는 숨김 |
| 맥락 정보 | 차 그림 아래 카드(점검 항목, 고른 부위의 증상) | 오른쪽 패널(지금 상태, 고른 부위의 증상) |
| 상태 표시 | 탭 아래 칩 한 줄(정차 중 · 휴대폰 연결됨 · 보호자 2명 준비) | 오른쪽 패널 "지금 상태" 또는 머리줄 칩 |
| 주 버튼 | 아래 고정 2개(840 폭에서 높이 96px, 긴급 148px) | 아래 고정 2개(높이 88px, 긴급 100px) |
| 경고등 | 찾기와 설명을 두 화면으로 나눔 | 한 화면의 왼쪽(찾기)과 오른쪽(후보 · 설명) |
| 긴급 | 띠 → 한 문장 → 정지 그림 → 자막 → 버튼 2개(위에서 아래) | 띠 → 왼쪽 한 문장 · 자막, 오른쪽 정지 그림 → 버튼 2개 |

- 두 배치의 버튼 이름, 버튼 수, 왼쪽·오른쪽 뜻, 들어가는 화면은 같습니다. 가로에서만 되는 기능, 세로에서만 되는 기능이 없습니다.
- 창 크기나 방향이 바뀌어도 고른 부위, 진행 중인 안내 단계, 발송 확인의 남은 시간은 그대로 유지합니다.
- 840×1212와 1280×720은 시안 예시 크기입니다. 실제 창 크기는 에뮬레이터 FormFactorConsole로 확인합니다. 레터박스 없이 두 배치를 각각 채웁니다.

### 4.5 주행 중 규칙

1. 주행 여부는 플랫폼의 `CarUxRestrictions`를 따릅니다. 상태를 알 수 없으면 주행 중으로 봅니다(D9).
2. 애니메이션, 동영상, 자동 스크롤, 화면 전환 효과를 쓰지 않습니다. 발송 확인의 숫자처럼 상태가 바뀔 때 다시 그리는 것만 있습니다(D7).
3. 긴급 그림은 정지 그림 1장입니다. 도로와 차 뒷모습 수준의 기호만 쓰고 발·손 동작 화살표와 발 사진을 넣지 않습니다. 페달 그림은 정차 중 "비상 절차 미리 익히기"에서만 씁니다.
4. 긴급 음성은 대상 차량 취급설명서의 비상 절차 문장만 읽습니다. 화면에는 자막 1줄과 출처를 둡니다. 문장은 아반떼 취급설명서 확인 전 예시로 표시했습니다.
5. 메뉴는 3단계 이하입니다(홈 → 탭 → 화면 → 상세). 긴급 흐름은 메뉴 탐색이 아니라 한 화면씩 넘어가는 안내이고, 화면마다 누를 것은 2개뿐입니다.
6. 전체 화면 팝업을 쓰지 않습니다. 긴급 화면은 앱 창 안에서만 바뀝니다. 앱이 뒤에 있으면 강제로 앞에 띄우지 않고 음성 1번과 시스템 알림 1개만 냅니다(D12).
7. 센서 조합(차속 증가, 브레이크 눌림 등)만으로는 긴급 안내를 시작하지 않습니다. 화면을 바꾸지 않고 "차가 멈추지 않나요?" 확인 질문만 냅니다(D8).
8. 키보드 입력은 정차 중에만 씁니다. 음성 입력은 버튼을 누를 때만 듣습니다(상시 듣기 없음).
9. 주행 중에는 차 그림·부위 선택, 점검 카드, 지도, 차량 스냅샷, 시간표, 페달 그림을 숨깁니다.
10. 모든 글 묶음은 3줄 이하입니다. 긴급 화면의 행동 문장은 2줄 이하입니다.

### 4.6 긴급 흐름의 "같은 자리 같은 뜻"

| 화면 | 왼쪽(빨강, 어두운 글자: 더 많은 도움) | 오른쪽(중립, 흰 글자: 끝내기 · 보내지 않기) |
| --- | --- | --- |
| 긴급 안내 | 멈추지 않아요 → 감속 실패 대처 | 괜찮아요 · 안내 끝내기 |
| 감속 실패 대처 | 도움 요청 → 받는 사람 확인 | 차가 멈췄어요 · 안내 끝내기 |
| 발송 확인(10초) | 지금 보내기 | 괜찮아요 · 보내지 않음 |

- 상태가 바뀌어 다음 화면이 떠도, 손가락이 닿는 자리의 뜻은 바뀌지 않습니다. 오른쪽은 언제나 "끝내기 · 보내지 않기"입니다. 그래서 잘못 눌러도 위험이 커지지 않는 쪽으로 정했습니다(D16).
- 화면이 바뀐 직후 짧은 시간(0.5~0.7초, 자체 설계값이며 시험으로 정함)은 터치를 받지 않습니다. 새 상황은 화면보다 음성으로 먼저 알립니다.
- 잘못 시작했을 때는 오른쪽 "괜찮아요 · 안내 끝내기"로 바로 빠져나갑니다. 끝낸 뒤에도 기록은 남깁니다.

### 4.10 표시 규칙과 한계

- 모든 시안 오른쪽 위에 작은 "설계 시안" 표시를 둡니다.
- [시험 입력] 배지는 시연 모드에서 앱 안 시험 입력 재생기가 넣는 값에만 붙입니다. 시안에서는 차속, 엔진오일 · 브레이크액 · 워셔액 · 출력 저하, 안전벨트 착용, 에어백 전개 신호입니다. 도어 · 좌석 점유 · 브레이크 · 조향 · 주행거리는 Virtual Console 카드로 넣을 수 있어 배지를 붙이지 않았습니다.
- 공식 설명 요약에는 "안내 예시 · 검토 전" 배지와 출처 줄을 둡니다. "차량 계기판 안내와 다르면 차량 안내를 따르세요"를 함께 씁니다.
- 원본 녹음 · 영상은 회색 "향후 지원"으로만 표시합니다(D1).
- 보호자는 "보호자 1 · 2"로 씁니다. 실명, 전화번호, 실제 번호판, 실제 정비소 이름, 실제 지도 이미지를 쓰지 않았습니다. 위치는 측정 시각만 표시하고 정확도(m)는 표시하지 않습니다(D17).
- 차량 사진은 번호판을 지운 컷아웃(`avante-cutout.png`)만 씁니다. 페달 그림(`pedal-detail.png`)은 AI 설명 그림이라고 화면에 적었습니다.
- 대비와 글자 크기는 생성기가 그릴 때마다 계산한 값입니다. 실제 패널의 밝기 · 반사 · 물리 크기, 운전 중 이해도, 오탭률은 확인하지 않았습니다.
