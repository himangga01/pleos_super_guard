## 4. Pleos 화면 맞춤 UI/UX 상세 설계서 (v4.1)

> **대체 관계**: 이 문서는 [ux-v3-section.md](ux-v3-section.md)(4장, 가로 1280×720 시안 10장 기준)를 **대체**합니다. v3 문서는 이력으로 그대로 둡니다. 같은 파일의 v4(2026-11-12, 1차 비판 반영)는 이번 v4.1로 덮어썼고, 바뀐 점은 4.13절 변경 이력에 적었습니다.
>
> 작성일: 2026-11-12. 근거는 2차 비판 반영 결정(DECISIONS-r2의 A 대표 사례, B8~B13, F1~F5, G 화면 문구표, H1~H3)과 그대로 유효한 1차 결정(D7·D8·D10·D12~D17, N1~N12)입니다. 두 결정이 부딪히면 2차 결정을 따릅니다. 화면은 모두 **설계 시안**입니다. 앱 구현, 에뮬레이터 실행, 실제 운전 사용성 시험을 한 결과가 아닙니다.

### 4.1 그대로 두는 시각 방향

- 사용자가 확정한 방향을 유지합니다. 디 올 뉴 아반떼 실제 차량 이미지가 정차 중 홈의 중심입니다. 부위 점을 눌러 증상으로 이어집니다.
- 이모지를 쓰지 않고 아이콘을 씁니다. 앱 글꼴은 Pretendard입니다.
- 어두운 배경에 민트(기록)·앰버(경고등·점검·정비소)·레드(긴급·도움)·퍼플(보호자·위치)을 강조색으로 씁니다.
- 긴급 화면은 일반 탭을 숨기고 붉은 배경과 위험 띠를 써서 일반 메뉴와 구별합니다.
- v4.1에서 바뀐 것은 버튼 자리(4.4절), 주행 중 홈과 상황 선택, 새 확인 질문 화면, 대표 사례 값, 지도 삭제, 긴급 화면의 안내 문장 자리입니다.

### 4.4 버튼 자리 규칙 (F1)

앱 전체에서 아래 두 버튼의 자리 뜻을 하나로 정했습니다.

| 자리 | 뜻 | 색 |
| --- | --- | --- |
| 왼쪽 | 끝내기 · 취소 · 기록 | 중립색. 일반 화면은 어두운 칸(#19283D)과 흰 글자, 긴급 화면은 회보라 칸(#3A3346)과 흰 글자 |
| 오른쪽 | 도움 · 보내기 · 감속 실패 | 빨강. 일반 화면은 진한 빨강(#622230)과 흰 글자, 긴급·확인 질문 화면은 밝은 빨강(#FF5B6B)과 어두운 글자 |
| 오른쪽(빨강이 아닌 화면) | 그 화면의 주 행동 | 주 행동 색. 기록·연습 = 민트, 경고등·점검·정비소 = 앰버, 보호자 = 퍼플 |

- 일반 홈의 오른쪽 빨간 "도움이 필요해요"와 긴급 화면의 오른쪽 빨간 "안 멈춰요"·"도움 요청"·"지금 보내기"가 같은 쪽에 있습니다. 홈 → 상황 선택 → 확인 질문·긴급 안내 → 감속 실패 대처 → 발송 확인으로 넘어가도 "더 많은 도움"은 늘 오른쪽, "끝내기·보내지 않기"는 늘 왼쪽입니다. v4에서 긴급 화면만 빨강이 왼쪽이던 문제(2차 비판 C4-r2-01·C5-212)를 없앴습니다.
- 주행 중 홈은 세로 창에서도 큰 버튼 3개를 가로로 나란히 둡니다. 그래야 빨간 "도움이 필요해요"가 오른쪽에 옵니다. 가운데 "말로 하기"는 중립색입니다.
- 주행 중 홈과 긴급 화면에는 "보호자에게 알리기" 버튼을 두지 않습니다(B9). 보호자 발송은 상황 선택의 "지금 도움 요청"이나 감속 실패 대처의 "도움 요청" 뒤 받는 사람 확인, 또는 발송 확인(10초)에서만 일어납니다.
- 보내는 버튼("지금 도움 요청", "도움 요청", "지금 보내기")은 모두 `send` 아이콘을 씁니다. 상황 선택을 여는 "도움이 필요해요"만 구명환 아이콘입니다.
- 화면이 바뀐 직후 짧은 시간(0.5초, rules-lab `input_guard_ms_after_emergency_transition`)은 터치를 받지 않습니다. 새 상황은 화면보다 음성으로 먼저 알립니다.

### 4.7 주행 중 규칙

1. 주행 여부는 플랫폼의 `CarUxRestrictions`를 따릅니다. 상태를 알 수 없으면 주행 중으로 봅니다(D9).
2. 애니메이션, 동영상, 자동 스크롤, 화면 전환 효과를 쓰지 않습니다. 발송 확인의 숫자처럼 상태가 바뀔 때 다시 그리는 것만 있습니다(D7).
3. 긴급 그림은 정지 그림 **최대 1장**입니다(F5). 그림은 디 올 뉴 아반떼 실사 뒷모습 사진 1장(현대자동차 보도자료 2026.8.5 공식 사진, 보도용 번호판 지움)이고, 발 · 손 동작 화살표, 비상등 같은 덧그림, 발 사진을 넣지 않습니다. 페달 그림은 정차 중 "비상 절차 미리 익히기"에서만 씁니다.
4. 긴급 음성은 대상 차량 취급설명서의 비상 절차 문장만 읽습니다. 시안의 안내 문장 칸은 점선 테두리와 "문장 자리" 표시로 그렸고, 그 안에는 "취급설명서 비상 제동 절차(검토 후 확정 문장)"처럼 자리 이름만 둡니다. 지어낸 조작 문장을 넣지 않았습니다(F5).
5. 주행 중 긴급 화면에는 출처 줄을 두지 않습니다(F5). 출처는 정차 후 화면에서 보여 줍니다.
6. 메뉴는 3단계 이하입니다(홈 → 탭 → 화면 → 상세). 긴급 흐름은 메뉴 탐색이 아니라 한 화면씩 넘어가는 안내이고, 화면마다 누를 것은 2개뿐입니다.
7. 전체 화면 팝업을 쓰지 않습니다. 긴급 화면은 앱 창 안에서만 바뀝니다. 앱이 뒤에 있으면 강제로 앞에 띄우지 않고 음성 1번과 시스템 알림 1개만 냅니다(D12).
8. 센서 조합만으로는 긴급 안내를 시작하지 않습니다. "차가 멈추지 않나요?" 확인 질문만 냅니다. 질문에 "안 멈춰요"로 답하면 감속 실패 대처로, "괜찮아요"로 답하면 질문을 닫습니다(D8 · F2).
9. 키보드 입력은 정차 중에만 씁니다. 음성 입력은 버튼을 한 번 누른 뒤 최대 8초만 듣습니다(B6). 상시 듣기는 없습니다. 음성으로 긴급 안내를 시작할 때도 먼저 "말로 하기"를 누릅니다(F3).
10. "말로 하기"로 들은 말은 STT 결과 문자열로 나눠 기록 메모, 경고등 찾기, 긴급 안내 시작(안 멈춰요 · 저절로 빨라져요), 도움 요청(받는 사람 확인 화면)으로 보냅니다(H1, [시연]). 나누는 낱말 규칙은 rules-lab에서 정합니다.
11. 주행 중에는 차 그림 · 부위 선택, 점검 카드, 차량 스냅샷, 시간표, 페달 그림을 숨깁니다. 앱 안 지도는 정차 중에도 없습니다(B11).
12. 모든 글 묶음은 3줄 이하입니다. 긴급 화면의 행동 문장은 2줄 이하입니다.

### 4.12 표시 규칙, 한계, 남은 일

- 모든 시안 오른쪽 위에 작은 "설계 시안" 표시를 둡니다.
- 경고등 설명에는 "안내 예시 · 검토 전" 배지, "설명 요약(설명서 기준)" 소제목, 출처 줄, "차량 계기판 안내와 다르면 차량 안내를 따르세요"를 함께 씁니다.
- 보호자는 "보호자 1 · 2"로 씁니다. 실명, 전화번호, 실제 번호판, 실제 정비소 이름, 실제 주소, 지도 이미지를 쓰지 않았습니다. 위치는 측정 시각과 예시 주소 문자만 표시하고 정확도(m)는 표시하지 않습니다(D17). 보호자 휴대폰 페이지의 지도는 서버 · 웹 기능입니다(B11).
- 차량 사진은 번호판을 지운 컷아웃(`avante-cutout.png`)만 씁니다. 페달 그림(`pedal-detail.png`)은 AI 설명 그림이라고 화면에 적었습니다.
- 대비와 글자 크기는 생성기가 그릴 때마다 계산한 값입니다. 실제 패널의 밝기 · 반사 · 물리 크기, 운전 중 이해도, 오탭률은 확인하지 않았습니다.

이번 라운드에서 그리지 않은 화면:

- 받는 사람 확인("지금 도움 요청" · "도움 요청" 뒤): 발송 확인과 같은 배치에서 타이머를 빼고 왼쪽 "보내지 않기"(중립), 오른쪽 "보내기"(빨강)로 둡니다.
- 정차 후 확인과 정차 후 할 일 카드(H4), 정비 노트 · 재발 확인(N6), 주 1회 경고등 익히기 카드(N12), 설정 · 동의, 휴대폰 연결(QR), 시연 모드 설정, 보호자 웹 페이지(H5 2단계 열람), 내 위치 영수증함(H6), 주행 중 "말로 하기" 듣는 중 상태, 오류 · 빈 상태, 세로 진입 화면.

메인 세션이 정할 것:

- 정차 후 상황 선택 12칸의 구성. G표와 B9는 "9개 + 긴급 3개"라고 쓰는데, PRD의 증상 9개에는 사고(`COLLISION`)가 들어 있어 긴급 줄 "사고가 났어요"와 겹칩니다. 시안은 사고를 긴급 줄에만 두고, 아래 9칸을 증상 8개 + "경고등이 켜졌어요"(경고등 찾기로 가는 칸, 증상 값 아님)로 채웠습니다.
- B8 본문은 원치 않는 가속 안내의 "왼쪽 = 안 멈춰요", 감속 실패 대처의 "왼쪽 = 도움 요청"이라고 쓰지만, F1과 G표는 빨강을 오른쪽에 둡니다. 시안은 F1 · G표를 따랐습니다. PRD · 별첨 · 양식의 버튼 자리 문장도 G표에 맞춰야 합니다.
- 출발 전 점검의 엔진오일 · 브레이크액 칸, 사고 순간 차 상태의 에어백 · 안전벨트 줄을 경고등과 다른 일반 사물 그림으로 바꿀지(2차 비판 C5-213).
- rules-lab에 확인 질문 반복 억제 키(최대 1회/5분)와 `confirm_prompt_text` 답 버튼 값을 넣는 일(F2). 시안 문구는 이미 그 값에 맞췄습니다.
