## 1. 레퍼런스3539

[원문](https://ref.theseeker.io/r/3539). EV 충전 앱의 차량 상태·지도·충전 진행을 보여 주는 세 화면입니다. 확인한 미디어 ID는3307입니다.

### 실제 보이는 구성

- 첫 화면은 차량 이름과 큰 차량 이미지가 시선을 잡습니다. 이미지 아래 원형 기능 아이콘, 그 아래 배터리·주행거리 카드가 배치됩니다.
- 두 번째 화면은 지도가 중심입니다. 위치·이동 경로·충전 핀과 선택한 시설의 상세 패널이 연결됩니다.
- 세 번째 화면은 충전 진행을 큰 원형 게이지로 보여 주며, 하단에 현재 작업을 멈추는 버튼이 있습니다.
- 동일한 앱이지만 세 화면의 중심 시각 요소가 각각 차량·지도·진행 게이지로 바뀝니다.
- 제목·주요 수치가 굵고, 설명은 상대적으로 작고 가볍습니다. 실제 글꼴 이름은 이미지에서 확인되지 않습니다.

### 플레오스 가드에 가져올 점

‘내 차량’ 화면에서는 아반떼 이미지가 중심이 되어야 합니다. 경고등·증상·보호자 같은 기능 이름은 차량 주변의 짧은 아이콘 조작으로 연결합니다. 내 차량 이미지, 현재 상태, 다음 행동이 한 장면으로 읽히게 만듭니다.

기능별로 화면 중심을 바꾸는 원리를 적용합니다. 경고등은 해당 표시와 대처, 기록은 파형·발생 구간, 긴급 안내는 필요한 동작 그림, 보호자 확인은 지도와 전달 상태가 중심입니다. 모든 화면에 같은 크기의 텍스트 카드 네 개를 반복하지 않습니다.

원형 게이지는 보관 진행이나 발송 카운트다운처럼 실제 진행을 표현할 수 있는 곳에만 사용합니다. 사고 심각도나 차량 안전을 근거 없는 백분율로 표시하지 않습니다.

### 가져오지 않을 점

레퍼런스의 차량 모델을 복사하지 않습니다. 플레오스 가드에는 공식 자료로 확인한 신형 아반떼를 사용합니다. 작은 원형 버튼과 세로 하단 탭을 그대로 옮기지 않고 차량용 큰 터치 영역으로 바꿉니다. 정지 이미지에 보이는 기능 아이콘을 실제 지원 차량 제어 API라고 해석하지 않습니다.

## 2. 레퍼런스3587

### 플레오스 가드에 가져올 점

세 레퍼런스 중 **차량을 직접 선택하는 화면의 형태를 만드는 데 가장 가까운 참고**입니다. 신형 아반떼의 전체 모습을 충분히 크게 배치하고, 선택할 수 있는 부위를 그 위치에 붙입니다.

기본 차량 장면은 내 차를 알아보기 쉬운 앞쪽 사선 모습으로 시작할 수 있습니다. 부위를 고르는 단계에서는 앞·뒤와 바퀴 위치가 분명한 상부 모습 또는 검토된 간단한 차량 도해를 사용합니다. 실내를 선택하면 실제 아반떼 실내 장면으로 바꿔 경고등·핸들·페달 관련 선택을 연결합니다.

이는 레퍼런스에 이미 구현된 동작을 복사하는 것이 아니라, **그 차량 시각화를 부위 선택 기능으로 확장하는 제안**입니다. 사용자가 고른 부위는 ‘사용자 선택’으로 남기며 센서가 그 부위의 고장을 확인한 것처럼 표시하지 않습니다.

### 가져오지 않을 점

사용자의 후속 지시에 따라 큰 글자와 차량이 겹치는 효과를 **앱 진입 로딩 장면**에 적용합니다. 앱 화면을 뒤에 두고 실제 신형 아반떼 이미지를 전면에 겹치며, 큰 앱 이름의 일부가 차량 뒤로 들어가도록 합니다. 홈으로 전환되면 선택 지점과 행동 버튼을 선명하게 보여 줍니다. 레퍼런스의 열린 지붕·실내 노출 형태를 일반 아반떼 구조처럼 그리지 않습니다. 확인되지 않은 내부 부품을 투시한 이미지도 실제 진단 화면으로 사용하지 않습니다.

1. 배경에는 실제 제작할 차량 중심 홈 화면을 낮은 대비로 배치합니다. 큰 텍스트 카드만 있는 이전 홈 시안은 배경 기준으로 사용하지 않습니다.

3. 전면에는 등록한 차량과 맞는 아반떼 이미지를 크게 배치합니다. 기본 제작 기준은 확인한 디 올 뉴 아반떼 공식 외관 사진입니다.
4. 준비 상태는 하단 한 줄과 작은 진행 표시로 보여 줍니다. 실제 연결 상태와 다른 가짜 완료율을 표시하지 않습니다.
5. 준비가 끝나면 같은 차량 이미지를 홈의 선택 위치로 옮기고 배경의 부위 선택·상황 아이콘·컨텍스트 패널을 활성화합니다. 연출 때문에 준비된 홈을 일부러 기다리게 만들지 않습니다.
6. 진행 중 긴급 사건 복귀는 진입 연출을 건너뛰고 현재 안내·알림 상태로 이어갑니다. 이 연출은 앱 창 안에서 제공하며 시스템 Driving view를 가리지 않습니다.

## 3. 레퍼런스8134

[원문](https://ref.theseeker.io/r/8134). 주차 예약 앱의 가입과 지도 기반 탐색 화면입니다. 확인한 미디어 ID는9480입니다.

### 실제 보이는 구성

- 첫 화면은 차량 사진으로 서비스의 대상을 먼저 보여 주고, 아래에 제목·간단한 설명·가입 행동을 배치합니다.
- 두 번째 화면은 현재 위치, 검색·필터, 지도, 선택 가능한 장소 카드 순서입니다.
- 선택한 필터와 주요 지도 핀·행동에 노란색을 사용합니다. 선택 상태가 주변과 구분됩니다.
- 시설 사진과 거리·가격 등의 비교 정보가 연결됩니다. 지도의 대상을 고르면 자세한 내용을 볼 수 있을 것으로 예상되는 배치지만 실제 동작은 이번 이미지 확인으로 검증하지 않았습니다.

### 플레오스 가드에 가져올 점

등록 차량을 확인하는 화면에서 아반떼의 실제 모습·모델·사용자 설정을 함께 보여 줍니다. 서비스센터 탐색과 보호자 위치 화면은 지도와 선택한 대상의 정보가 연결되게 합니다.

정비소를 선택하면 위치만 강조하는 것이 아니라 정비 가능 항목·자료 시각·연락·내비 연결을 같은 패널에서 확인하도록 합니다. 보호자 화면은 사고 위치와 마지막 수신 시각, 차량 상태 요약과 전달 상태를 연결합니다.

### 가져오지 않을 점

가입 폼·키보드·촘촘한 필터·가로 스크롤 목록을 주행 중 조작으로 옮기지 않습니다. 가장 가까운 정비소가 곧바로 현재 문제를 처리할 수 있다고 가정하지 않습니다. 운행 중단이 필요한 상황에서 정비소까지 계속 운전하도록 안내하지 않습니다.

## 4. 세 자료를 합친 적용 방향

| 3587 | 중앙 차량을 기준으로 주변 정보를 배치 | 차량 부위 선택과 실내/외 전환 |

홈에서 먼저 보여 줄 것은 **내 아반떼와 현재 상태**입니다. 차량 이미지 주변에는 앞부분·타이어·실내·뒤쪽처럼 사용자가 이해할 수 있는 부위 선택을 배치합니다. 작은 점만 찍는 방식 대신 충분한 터치 영역과 짧은 이름을 함께 제공합니다. 운전자 기준 좌우와 화면 기준 좌우를 혼동하지 않도록 표시해야 합니다.

차량 부위를 고르면 오른쪽 패널이 그 부위와 관련된 행동으로 바뀝니다. 예를 들어 타이어 선택 뒤에는 ‘떨림’, ‘공기압 표시’, ‘파손 의심’, ‘잘 모르겠음’을 아이콘과 함께 제공합니다. 사용자가 ‘엔진’, ‘서스펜션’ 같은 원인을 먼저 진단해야 다음으로 갈 수 있는 구조는 만들지 않습니다.

어디에서 문제가 생겼는지 모르는 경우를 위해 소리·떨림·냄새·페달 이상을 바로 고르는 경로도 둡니다. 긴급 도움과 정지 실패는 차량 부위 선택을 거치지 않고 바로 접근할 수 있게 합니다.

### 유저스토리 적용 예시

1. **바퀴 쪽 이상:** 아반떼의 해당 바퀴 선택 → 떨림/파손 의심 선택 → 받은 정보·기록·검토된 대처 표시.
2. **어디선가 나는 소리:** 부위 선택을 건너뛰고 마이크·소리 아이콘 선택 → 최근 구간 보관 → 정차 뒤 부위·설명 추가.
3. **낯선 경고등:** 실내/계기판 선택 또는 경고등 바로가기 → 표시 그림/사진 후보 선택 → 해당 차량의 공식 설명.
4. **감속 실패:** 긴급 바로가기 또는 검토된 사건 조건 → 일반 홈을 긴급 전용 장면으로 전환 → 발·페달 또는 해당 차량의 비상 조작 설명과 음성.
5. **보호자 확인:** 지도에서 사건 차량 위치 확인 → 마지막 수신 시각·추정 등급·응답·채널 상태를 같은 패널에서 확인.

## 5. 글꼴과 글자 위계

세 자료의 정확한 폰트 이름은 확인할 수 없습니다. 이미지에서 확인한 것은 굵은 산세리프 제목·강조 숫자와 가벼운 보조 설명의 대비입니다. 3587의 큰 이탤릭 광고 서체를 차량의 지시 문구에 적용하지 않습니다.

| 타이머·주요 숫자 | Bold 700, 고정된 숫자 영역 | 숫자가 바뀔 때 배치가 흔들리지 않음 |

한글의 자간은 과도하게 좁히지 않고 기본값에서 시작합니다. 제목·버튼을 전부 Bold로 만들지 않습니다. 줄 간격과 명암·여백을 함께 조정합니다. 글자 크기는 실제 패널에서 확인하며, 크게 만드는 것만으로 기능 구분을 해결했다고 판단하지 않습니다.

## 6. 수정 우선순위와 확인할 점

첫째, 텍스트 카드 중심 홈을 차량 중심 홈으로 바꿉니다. 둘째, 선택 부위와 오른쪽 정보 패널의 연결을 만듭니다. 셋째, 원인·부위를 모르는 사람도 바로 기록할 수 있게 합니다. 넷째, 긴급 화면·지도·기록의 장면을 각각 다르게 만듭니다. 다섯째, Pretendard의 굵기와 간격으로 정보 위계를 맞춥니다.

확인할 항목은 차량 부위 선택의 오탭, 사용자 기준 좌우 혼동, ‘부위 모름’ 경로 발견, 긴급 바로가기 발견, 선택된 부위와 설명의 일치, 밝은 환경·야간의 글자/아이콘 가독성입니다. 세 레퍼런스는 이 시험을 대신하지 않습니다.

## 7. 조사 기준과 작업 상태

기존 [UX 수정안](ux-redesign-2026-11-12.md), [문서 제작 기록](submission-documents-2026-11-12.md), [프로젝트 안내](../../AGENTS.md)를 읽고 이번 요청을 반영했습니다. 원본은 ref의 get_reference·contact sheet·개별 이미지 도구로 확인했습니다. 색상 명칭은 이미지 관찰과 제공 메타데이터를 참고한 것이며 모든 HEX를 픽셀 측정한 결과는 아닙니다.

세 레퍼런스의 선행 분석 뒤 사용자가 진입 화면의 겹침 연출을 지정했습니다. 공식 아반떼 외관과 로고를 참조한 진입 개념 시안은 이후 [현재 외곽선/U 복원 시안](../../output/submission/assets/pleos-guard-launch-outline.png)으로 수정됐습니다. 배경 앱 장면·큰 이름·차량 전면의 세 겹 구성이며 실제 로딩 기능이나 부위 선택의 구현 결과는 아닙니다. `assets/final/`의 UI 10개에는 실제 Pretendard v1.3.9 파일을 적용했습니다. 생성 이미지 속 글자의 폰트가 검증됐다는 의미와 구별합니다. 공식 양식과 상세 별첨의 문서 디자인은 사용자가 지정한 별도 세션의 페이퍼로지 스타일을 따르며, 현재 상태와 최종 검수는 [문서 제작 기록](submission-documents-2026-11-12.md)을 확인합니다.
