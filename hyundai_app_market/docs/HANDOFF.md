## 1. 현재 상태부터 확인합니다

**공식 양식 14쪽과 상세 별첨 43쪽의 v4.1 Word·PDF가 완성돼 있습니다.** 공식 양식 2~6번은 각각 3,000자입니다. 이번 v4.1은 다음 과정을 거쳐 만들었습니다.

1. 압축 해제 파일 876개를 주제별 12묶음으로 나눠 2회씩 리뷰했습니다.
2. 공모전 사이트 전체와 Pleos 개발 문서·SDK 패키지를 다시 확인했습니다.
3. 1차 비판: 서로 다른 관점의 비판 에이전트 9개가 지적한 214개 항목을 메인 세션이 원문으로 재검증하고, 그 결과로 모든 문서를 v4로 고쳤습니다.
4. 2차 비판: 같은 9개 관점이 v4를 다시 검토해 비판과 새 아이디어 약 220개를 냈습니다. 메인 세션이 SDK 소스, 공식 취급설명서, 현대자동차 보도자료로 다시 확인해 사실 오류 13건, 사업성 7건, 계약 보강 7건, 문서 품질·화면 문구 결정, 새 아이디어 8개를 채택하고 모든 문서를 v4.1로 고쳤습니다.

완료된 것은 조사·기획·설계·화면 시안·제출 문서입니다. **실제 차량 앱, 휴대폰 보조 앱, 서버는 아직 구현하지 않았습니다.** SDK 호출, 에뮬레이터 실행, 카카오톡·문자 발송, 실차 시험을 한 기록도 없습니다. 설계 문서와 문서 제작 스크립트를 실행 가능한 앱으로 소개하면 안 됩니다.

## 4. 사용자가 확정한 요구사항

### 서비스 범위
- 앱 이름은 **플레오스 가드**입니다. Pleos가 탑재된 차량만 대상으로 하며 Pleos 차량 앱이 주제품, 안드로이드 휴대폰은 보조입니다.
- 아이디어 2·5·6번(경고등 도감, 순간 증상 기록·긴급 안내, 사고·보호자 통지)을 하나의 기록 흐름으로 통합했습니다.
- 보호자 알림은 10초 확인, 즉시 발송, 취소를 제공합니다. 알림톡을 먼저 보내고 실패·전달 미확인 때 서버가 문자로 바꿉니다. 접수·전달·열람을 나눕니다.
- 긴급 안내는 음성과 그림이 같은 단계를 가리킵니다. 다만 아래 v4 규칙처럼 주행 중에는 움직이지 않는 그림과 짧은 음성만 씁니다.

### 2026-11-12 비판 라운드에서 정한 v4 기준 (근거는 PRD v4와 각 문서)
- **공모전 공지 8 분리**: 기능을 [시연](공개 SDK로 지금 만들고 에뮬레이터에서 보여 줌), [설계](공개 SDK로 가능하나 서버·휴대폰 앱 구현 필요), [향후](공개 문서에 없는 API·권한 필요)로 나눕니다. 경고등 상태 읽기, 원본 녹음·영상, 블랙박스, 진동 분석(가속도·자이로), 충격 센서, 가속 페달 값, 기어는 [향후]입니다.
- **경고등 API**: `getTelltalesInfo` 등 4개는 구현에서 `PRIVATE_CAR_SAFETY`(signature|privileged)를 요구합니다. 일반 앱은 경고등 상태를 읽을 수 없습니다. 도감은 운전자가 색 → 모양 → 켜짐·깜박임으로 고르는 방식입니다.
- **주행 중 화면**: Pleos 디자인 원칙("운전 중 애니메이션 이미지로 시선을 유도하면 안 됩니다", "운전자의 손이나 발을 움직이는 동작을 유도해서는 안 됩니다")에 따라, 주행 중 긴급 안내는 정지 그림 1장과 취급설명서 비상 절차의 짧은 음성만 씁니다. 페달 그림·애니메이션은 정차 중 "비상 절차 미리 익히기"로 옮겼습니다.
- **긴급 안내 시작**: 운전자가 직접 알릴 때(버튼·음성)만 시작합니다. 센서 조합은 "차가 멈추지 않나요?" 확인 질문만 띄웁니다. 앱은 차를 제어하지 않습니다.
- **주행 상태를 알 수 없으면 주행 중으로 봅니다**(v3의 "정차 중으로 간주"는 오류였음).
- **보호자 알림 범위**: 에어백 전개 신호와 "사고" 선택은 10초 확인 뒤 자동 발송합니다. "지금 도움 요청"은 받는 사람 확인 뒤 즉시 발송합니다. 떨림·소음 같은 증상 선택은 자동 발송하지 않습니다.
- **화면 모델**: Pleos 앱은 기본으로 세로 한 창으로 실행되고 가로·세로 두 배치를 모두 갖춰야 합니다. v4에서 세로 한 창 시안을 기본으로 추가했습니다. 1280×720dp와 80dp는 자체 설계값이며 Pleos 공식 수치가 아닙니다.
- **위치**: FusedLocation에는 미터 단위 정확도가 없습니다. 오차 반경은 표시하지 않고 측정 시각과 `confidence` 원값을 씁니다.
- **휴대폰 보조 앱**: FusedLocation이 차량용 기기만 설치하도록 선언해 같은 APK를 휴대폰에 쓸 수 없습니다. 별도 APK, 정차 중 QR 연결, 서버 중계로 설계합니다.
- **새 기능**: 차가 알려 준 점검 항목, 출발 전 점검 카드, 재현 조건 카드, 정비 노트·재발 확인, 가는 길에 정비소 들르기, 사고 순간 차량 스냅샷, 보호자 연습 알림과 빠른 답, 위치 제공 알림·공유 중지, 경고등 익히기 카드, 비상 절차 미리 익히기, 시연 모드.

### 2026-11-12 2차 비판 라운드에서 정한 v4.1 기준 (v4 기준보다 우선)
- **대표 사례 한 벌**: 그림·양식·별첨·PRD·시연 각본이 같은 값을 씁니다. 사고 장면은 밤 9시 00분 03초 에어백 전개 신호(운전석), 탑승 1명, 안전벨트 착용, 위치 측정 21:00:01, 10초 확인에 응답 없음 → 21:00:13 발송 시작, 보호자 1은 21:01 열람·"전화할게요", 보호자 2는 알림톡 전달 확인 기한 10초 뒤 21:00:23 문자 재발송입니다. 경고등 장면은 주황색 타이어 공기압 경고, 소리 장면은 앞 타이어 끼익 소리 일주일 3회(시속 20km 아래 브레이크), 점검 장면은 워셔액 부족(시험 입력)과 정기 점검까지 2,860km입니다.
- **버튼 이름과 자리**: 왼쪽은 끝내기·취소·기록(중립색), 오른쪽은 도움·보내기·감속 실패(빨강)입니다. "저절로 빨라져요"는 원치 않는 가속 안내, "안 멈춰요"는 감속 실패 대처입니다. 센서 조합은 "차가 멈추지 않나요?" 확인 질문(왼쪽 괜찮아요, 오른쪽 안 멈춰요)만 띄우고 같은 주행에서 5분에 한 번까지입니다. 화면별 문구는 UX 문서의 G표가 기준입니다.
- **주행 중 홈**: 큰 버튼 3개(지금 기록, 말로 하기, 도움이 필요해요). 음성은 "말로 하기"를 한 번 누르면 최대 8초 듣습니다(누르고 있기·상시 듣기 없음). 주행 중 상황 선택은 5개(안 멈춰요, 저절로 빨라져요, 사고가 났어요, 차체 떨림, 타는 냄새), 정차 후 12개입니다.
- **SDK 사실 정정**: 경유지는 NaviHelper `addWaypoint`(권한 `NAVI_ROUTE_SEARCH`), 권한 부족(`SecurityException`)과 기능 미지원(Capability 확인)을 구분, `CAR_SPEED`는 실행 중 허락이 필요한 권한, TTS는 오디오 포커스를 주지 않으므로 앱이 AudioManager로 직접 관리, 기어는 쓰지 않습니다. 시험 입력이 하나라도 섞인 사건은 모의 발송만 합니다.
- **앱 안 지도 없음**: 공개 SDK에 지도가 없어 정비소 들르기는 목록과 "내비에서 보기"(`requestNavigationScreen`), 보호자 상태 화면은 위치 측정 시각과 주소 문자만 씁니다. Pleos 세로 한 창은 보통 내비 옆에 놓인다는 점을 살렸습니다.
- **보호자**: 최대 3명, 인원과 관계없이 무료입니다. 보호자 페이지는 링크 → 휴대폰 번호 뒷자리 확인의 2단계로 엽니다.
- **사업성 산식(가정)**: 1단계(더 뉴 그랜저, 디 올 뉴 아반떼) MAU = 연 15만 대 × 설치율 10% × 월 활성 20% ≈ 3,000명(낮음 600, 높음 6,750), 2030년 약 2천만 대 × 1% × 20% ≈ 4만 명, Retention 가설 D7 35%·D30 20%·M3 15%. 아반떼 전 트림 Pleos Connect 기본 적용은 현대자동차 보도자료(2026.8.5)로 확인했습니다.
- **2차 새 아이디어**: 말로 하기 버튼 하나, 내비 옆 동반 창, 소리 용의자 지우기(공조·창문·와이퍼 상태), 정차 후 할 일 카드, 보호자 페이지 2단계 열람, 내 위치 영수증함, 도착 알림(운전자가 켠 경우만, 사용자 결정 필요), 정비소 도착 체크인.

### 문서와 참가 정보
- **개인 참가**입니다. 개인 체크, 인원 1명, 앱명만 채웠습니다. 성명, 연락처, 소속, 참가 부문, 날짜, 동의 표시, 서명은 사용자가 직접 작성합니다.
- 공모전 양식의 01~04 영역과 1~8번 순서를 유지합니다. **03 동의서와 04 서명은 공모전 원본 디자인 그대로**입니다.
- 기획 부분 글꼴은 페이퍼로지, 앱 화면 글꼴은 Pretendard입니다. 참고 문서의 ■·●·○ 제목 기호는 쓰지 않습니다.
- 설명은 쉬운 한국어와 존댓말을 쓰고, 구현·확인한 사실과 앞으로 할 일을 분리합니다.

## 8. 기술적으로 유지해야 할 조건

- 신호가 없다는 사실을 값 0이나 브레이크 미입력으로 바꾸지 않습니다. 브레이크는 true, false, 확인 불가로 나눕니다.
- Vehicle SDK 값에는 측정 시각이 없습니다. 바뀔 때만 오는 신호는 마지막 수신 시각과 서비스 연결 상태로, 차속처럼 주기적으로 오는 신호는 3,000ms 신선도로 판단합니다.
- 권한이 없으면 SDK가 `SecurityException`을 바로 던집니다. 서비스 연결 전 호출은 기다리고, 콜백은 메인 스레드가 아닙니다.
- 차속은 Vehicle SDK 2.3.2에서 리스너가 삭제됐습니다. Pleos 개발자 FAQ가 안내하는 AAOS `CarPropertyManager`의 `PERF_VEHICLE_SPEED`를 씁니다. 다섯 SDK 목록 밖의 Android 경로이므로 공모전 허용 범위는 운영사무국 문의 대상입니다.
- TTS 기본 오디오 용도는 MEDIA입니다. `setAudioAttributes`로 안내 용도를 지정하고, 음성 앞 150~200ms 무음, Gleo 호출 시 중단, 시동 종료 때 오디오 포커스 반납을 지킵니다. 음성 인식은 버튼을 누를 때만 하고 외부 음성 인식 서비스로 보내지 않습니다.
- 주행 중 성능 예산(Pleos 심사 기준): CPU 5% 미만, RAM 400MB 이하.
- 운전자의 위치 제공 동의, 보낼 때마다 운전자에게 받은 사람·시각 알림, 제공 기록 보관을 지킵니다. 위치기반서비스 사업 신고는 출시 전 요건입니다.
- 검토된 차량별 안내만 씁니다. 긴급 조작 순서를 앱이나 LLM이 즉석에서 만들지 않습니다. LLM SDK는 공모전 기간에 제공되지 않습니다.

```text
cd output/submission
python3 build_v4.py --out qa/<새 폴더> [--stage official|annex|all] [--install]
```

- 입력: `docs/submission/official-content-3000/0[2-6]-*.txt`, `docs/submission/official-form-v4.json`, `docs/submission/annex-v4/annex.md`, `assets/v4/…`.

- 필요한 글꼴: 페이퍼로지(`assets/paperlogy/`)와 Pretendard를 사용자 글꼴 폴더에 설치하고, fontconfig에서 맑은 고딕을 Noto Sans CJK KR로 연결했습니다. 이 대체 때문에 LibreOffice로 만든 공식 양식 1~12쪽의 글자 모양은 Word 변환본과 조금 다를 수 있습니다. 가능하면 최종 제출 전 Windows Word로 DOCX를 열어 PDF로 다시 저장하는 것을 권합니다.
