### 0.2 구현 등급 표시

공모전 공지 8은 공개된 Pleos Playground 문서의 SDK·API 범위 안에서 개발하고, 문서에 없는 기능은 향후 계획으로 적도록 합니다. 그래서 이 별첨은 모든 기능에 아래 표시를 붙입니다.

- **[시연]**: 공개 SDK와 Pleos 문서가 안내하는 경로로 지금 만들 수 있고, 에뮬레이터에서 보여 줄 기능입니다.
- **[설계]**: 공개 SDK로 가능하지만 서버나 휴대폰 앱처럼 추가 구현이 필요한 기능입니다. 2차 발표에서는 모의 서버로 보여 줍니다.
- **[향후]**: 공개 문서에 없는 API·권한·장치가 필요한 기능입니다. 계획으로만 적습니다.
- **[시험 입력]**: 에뮬레이터가 값을 주지 않아 앱 안 재생기로 넣은 값입니다. 화면에도 같은 표시를 붙입니다.

## 1. 기획 배경과 대상 {nobreak}

### 1.1 운전자가 겪는 네 가지 문제

표: 문제와 필요한 도움
| 문제 | 지금 겪는 일 | 필요한 도움 |
|---|---|---|
| 낯선 경고등 | 이름을 몰라 검색할 말을 정하기 어렵습니다. 찾은 설명이 내 차 사양과 맞는지도 다시 따져야 하고, 주행 중에는 휴대폰을 볼 수 없습니다. | 바로 서야 하는지, 정비소에 들르면 되는지를 한 줄로 알기 |
| 사라지는 증상 | 출발할 때만 나는 소리, 특정 속도의 떨림은 정비소에 가면 나타나지 않습니다. 운전자는 기억에 기대어 설명합니다. | 언제, 몇 km로, 어떤 조작 중이었는지 남기기 |
| 위급한 순간 | 원하지 않게 빨라지거나 브레이크를 밟아도 줄지 않는다고 느끼면 크게 당황합니다. 취급설명서를 그 자리에서 찾아 읽을 수 없습니다. | 지금 할 행동 하나를 짧은 음성으로 듣고, 평소에 미리 익혀 두기 |
| 혼자 운전 중 사고 | 에어백이 터지지 않은 사고나 고장은 운전자가 직접 연락해야 합니다. 가족은 위치를 받아도 언제 잰 위치인지 모릅니다. | 가족에게 먼저 할 일, 위치, 측정 시각을 함께 알리기 |

네 문제에는 공통점이 있습니다. 운전자, 가족, 정비사가 같은 사실을 보지 못합니다. 지금은 경고 뜻은 휴대폰 검색으로, 소리는 녹음 앱으로, 위치는 지도 앱으로, 연락은 전화로 따로 처리합니다. 도구를 바꿀 때마다 상황의 앞뒤가 끊기고, 정비소에서는 처음부터 다시 설명해야 합니다. 플레오스 가드는 같은 순간의 정보를 한 기록에 모아 세 사람이 함께 보게 합니다.

| 사용자 | 상황 | 앱을 여는 순간 |

| 첫 차를 산 지 3개월 된 초보 운전자 | 경고등이 낯설고, 출퇴근에 매일 차를 씁니다. | 출발 전 점검, 경고등이 켜졌을 때, 낯선 소리가 났을 때 |

### 1.3 왜 차량 앱이어야 하는가

자동차는 이 문제를 풀기에 가장 좋은 자리입니다. 차는 그 순간의 속도, 브레이크, 조향각, 방향지시등, 공조와 창문, 문과 안전벨트 상태, 주행거리, 위치를 알고 있습니다. 휴대폰은 이 값을 알 수 없습니다. 플레오스 가드는 Pleos Connect의 앱 화면에서 동작하며, 운전자 앞의 주행 정보 화면과 시스템 영역은 가리지 않습니다.

Pleos 화면은 앱 영역에 앱을 두 개까지 나란히 둘 수 있고, 두 앱을 함께 띄우면 각 앱은 보통 세로 창이 됩니다. 주행 중에는 내비 옆 세로 창이 플레오스 가드의 기본 자리입니다. 그래서 앱은 지도를 직접 그리지 않고 옆의 내비에 맡깁니다(4.1).

표: 휴대폰 앱과 차량 앱의 차이
| 상황 | 휴대폰 앱 | 플레오스 가드(차량 앱) |
|---|---|---|
| 증상이 생긴 순간 | 차량 상태를 알 수 없습니다. | 차속·브레이크·조향각·방향지시등·공조·창문 상태를 시간표로 남깁니다. |
| 사고 순간 | 좌석별 정보가 없습니다. | 좌석별 에어백 전개, 좌석 점유, 안전벨트, 문 상태를 함께 보냅니다. |
| 주행 중 사용 | 손에 들고 볼 수 없습니다. | 차의 주행 제한 신호에 맞춰 큰 버튼 세 개와 음성만 남깁니다. |
| 경고등 찾기 | 이름을 알아야 검색할 수 있습니다. | 색·모양·말로 찾고, 차가 알려 준 점검 항목으로 후보를 앞에 둡니다. |
| 정비소 가기 | 지도 앱을 따로 엽니다. | 지금 가던 길에 정비소를 경유지로 넣고, 지도는 옆 창의 내비가 보여 줍니다. |

## 2. 차별점과 기존 수단과의 관계 {nobreak}

플레오스 가드는 기존 수단 사이를 잇는 앱입니다. 119 신고, 블루링크의 사고 통보·SOS·차량 진단, 차의 안전 보조 장치는 그대로 두고, 그 앞뒤에서 운전자가 뜻을 알고, 기록하고, 가족·정비사와 나누게 돕습니다.

표: 기존 수단과 플레오스 가드의 관계
| 기존 수단 | 잘하는 일 | 닿지 않는 부분 | 플레오스 가드의 역할 |
|---|---|---|---|
| 블루링크 사고 통보·SOS | 에어백이 전개되면 사고를 자동 접수하고 상담원과 연결해 119, 보험사 등에 지원을 요청합니다. SOS 버튼도 있습니다. | 공개 설명서상 에어백이 전개되지 않는 사고에는 제공되지 않고, 가족에게 직접 알린다는 내용은 없습니다. 배터리 파손으로 전원이 끊기면 제공되지 않을 수 있습니다. | 운전자가 정한 가족에게 위치, 측정 시각, 먼저 할 일을 직접 알립니다. 전원이 끊기면 이 앱도 동작하지 않으며, 끊기기 전에 서버에 도착한 사건만 서버가 발송을 이어 갑니다. |
| 블루링크 차량 진단 | 엔진·변속 시스템 경고등이 켜지면 원격 진단과 상담원 안내를 하고, 견인·정비소 길 안내·정비 예약도 이어 줍니다(사양 적용 시). | 다른 경고등의 즉시 뜻 찾기, 경고 없이 잠깐 나타난 증상, 가족 연락 | 이 상담을 대신하지 않습니다. 상담에 앞서 바로 보는 뜻과 할 일, 경고 없는 순간 증상의 기록, 가족 연락을 맡습니다. |
| 차량의 페달 오조작 안전 보조 | 장애물이 가까운 정차·저속 상황에서 가속 페달을 세게 밟으면 차가 구동력을 먼저 제한하고 제동을 제어하며, 팝업과 경고음으로 알립니다. | 그 밖의 주행 상황에서 느끼는 원하지 않는 가속의 안내, 상황 기록, 가족 연락 | 운전자가 알리면 취급설명서의 비상 절차를 음성으로 전하고 기록합니다. 안내는 이 장치와 별개로 운전자 보고로만 시작합니다. |
| 시스템 출발 전 안내와 3D 차량 상태 | 주행 정보 화면이 문·안전벨트·브레이크 같은 출발 준비와 차량 상태를 그림으로 보여 줍니다. | 정비 일정, 끝나지 않은 기록, 보호자·휴대폰 준비 | 출발 전 점검 카드는 시스템 안내가 다루는 문·안전벨트를 빼고, 점검 항목·정비 일정·끝나지 않은 기록·보호자 준비를 보여 줍니다. |
| 계기판 경고등과 취급설명서 | 경고를 바로 표시하고 공식 뜻을 줍니다. | 이름을 모르면 설명서에서 찾기 어렵습니다. 기록과 공유가 없습니다. | 색·모양·말로 찾아 설명서 기반의 뜻을 보여 주고, 기록에 남깁니다. |
| 휴대폰 검색·녹음·지도 | 정보가 많고 자유롭게 녹음할 수 있습니다. | 주행 중 쓰기 어렵고, 내 차 사양과 맞는지 따로 확인해야 합니다. 도구마다 기록이 끊깁니다. | 차 화면에서 한 기록으로 묶습니다. |

정리하면 플레오스 가드는 차 안에서 '이상을 알아차림 → 뜻을 이해함 → 기록함 → 가족·정비사와 나눔'을 잇는 앱입니다. 차량 안전 장치의 개입, 블루링크 상담, 보험사의 사고 처리는 각 수단이 맡고, 플레오스 가드는 그 사이를 채웁니다. 블루링크 내용은 공개 취급설명서(기존 내비 세대) 기준이며, Pleos Connect 차량의 제공 범위는 출시 전에 확인합니다. 페달 오조작 안전 보조 설명은 현대자동차그룹 소개 자료와 디 올 뉴 아반떼 보도자료를 따릅니다.

### 2.1 새로운 점

- **한 기록 번호.** 경고등 찾기, 증상 기록, 긴급 안내, 보호자 알림, 정비 기록이 한 시간표로 이어집니다. 운전자, 보호자, 정비사가 같은 사실을 봅니다.
- **평소와 비교하는 재현 조건 카드.** 공개 SDK로 받는 차량 상태를 평소 주행과 비교해, 이 증상 때 유난히 겹친 조건만 정리합니다. 예: "일주일에 세 번, 모두 시속 20km 아래에서 브레이크를 밟을 때". 공조·창문·와이퍼 상태도 함께 남겨 "에어컨 바람 소리였는지"를 가려냅니다.
- **말로 하기 버튼 하나.** 주행 중에는 버튼 하나를 누르고 말하면, 앱이 기록 메모, 경고등 찾기, 긴급 안내, 도움 요청으로 나눠 보냅니다.
- **주행 중과 정차 중을 나눈 긴급 안내.** 주행 중에는 정지 그림 한 장과 짧은 음성만 씁니다. 페달 그림과 설명 애니메이션은 정차 중 연습 화면에만 두고, 브레이크 신호로 연습을 확인합니다.
- **보호자가 받자마자 할 일을 아는 알림.** 알림 첫 줄에 할 일이 있고, 보호자의 빠른 답은 차 화면과 음성으로 운전자에게 돌아옵니다.
- **정직한 표시.** 읽을 수 없는 값은 "확인 불가"로, 시험 값은 [시험 입력]으로 표시합니다. 화면은 앱이 실제로 아는 것만 보여 줍니다.

## 3. 기능 명세

이 장은 기능마다 사용자 이야기, 화면, 입력 신호, 처리 규칙, 실패·결측 처리를 적습니다. 기능별 구현 등급은 0.1과 5.4의 표에 모았습니다. 입력 신호 표의 Vehicle SDK 권한 이름 앞에는 모두 `pleos.car.permission.`이 붙습니다. 보호 수준 normal은 일반 앱이 매니페스트 선언만으로 받을 수 있는 권한이라는 뜻이고, dangerous는 실행 중에 운전자 허락을 받는 권한입니다.

모든 기능은 세 가지 공통 규칙을 따릅니다. 첫째, 같은 사건은 하나의 기록 번호와 시간표를 씁니다. 둘째, 받은 값마다 출처, 받은 시각, 품질을 함께 저장합니다(6.3). 셋째, 주행 중에는 4.2의 화면 규칙을 따릅니다.

### 3.1 주행 중 홈과 말로 하기 [시연]

주행 중에는 홈의 차 그림과 위쪽 탭을 숨기고 큰 버튼 세 개만 남깁니다. 왼쪽 "지금 기록", 가운데 "말로 하기", 오른쪽 빨간 "도움이 필요해요"입니다. 보호자에게 보내는 일은 상황 선택과 받는 사람 확인을 거칩니다. "도움이 필요해요"는 상황 선택을 열고, 상황 선택은 주행 중에 큰 카드 다섯 개(안 멈춰요·저절로 빨라져요·사고가 났어요·차체 떨림·타는 냄새)만 보여 줍니다. 상황 선택의 아래 버튼은 왼쪽 "고른 증상 기록", 오른쪽 "지금 도움 요청"입니다.

![주행 중 홈. 차 그림과 탭을 숨기고 큰 버튼 세 개(지금 기록 · 말로 하기 · 도움이 필요해요)만 남깁니다.](assets/v4/portrait/p-home-driving.png){w=5}

"말로 하기"는 버튼을 한 번 누르면 최대 8초 동안 한 문장을 듣습니다. 앱이 듣는 때는 이 버튼을 누른 뒤뿐입니다. SpeechToText 기기 안 모드(ON_DEVICE)의 결과 문자열을 정해 둔 낱말과 견줘 아래 네 갈래로 보냅니다.

표: 말로 하기가 나누는 네 갈래
| 말한 내용(예) | 가는 곳 | 비고 |
|---|---|---|
| "앞 타이어에서 끼익 소리" 같은 증상 설명 | 지금 기록과 기록 메모 | 말한 문장을 메모로 붙입니다. |
| "주황색 타이어 모양" 같은 색·모양 낱말 | 경고등 찾기 후보와 운행 판단 한 줄 | 결과는 음성 한 번과 화면 한 줄입니다. |
| "안 멈춰요", "저절로 빨라져요" | 감속 실패 대처, 원치 않는 가속 안내 | 긴급 안내를 바로 시작합니다(3.4). |
| "도움 요청" | 받는 사람 확인 화면 | 보내기는 화면에서 누를 때만 합니다. |

알아듣지 못하면 한 번만 다시 묻고, 그래도 나눌 수 없으면 말한 내용을 기록 메모로 남깁니다. 차량 마이크 음성은 기기 안에서만 처리합니다.

### 3.2 F1 경고등 찾기 [시연]

**사용자 이야기.** 고속도로를 달리던 초보 운전자가 계기판에 켜진 주황색 표시를 봅니다. 주행 중 홈의 "말로 하기"를 누르고 "주황색 타이어 모양"이라고 말합니다. 후보 "타이어 공기압 경고"와 "가까운 정비소에 들르세요"라는 한 줄이 음성과 함께 나옵니다. 운전자는 바로 세울 경고는 아님을 알고, 다음 휴게소에 차를 세운 뒤 "정차 후 자세히"를 엽니다.

![세로 한 창의 홈(왼쪽)과 경고등 찾기(오른쪽). 홈은 위쪽 탭 네 개와 아래 버튼 '지금 기록'·'도움이 필요해요'를 둡니다. 경고등은 색 → 모양 → 켜짐·깜박임으로 찾고, '문구로 찾기'·'말로 찾기'도 씁니다.](assets/v4/composite/pair-home-warning.png){w=13}

| 경고등 켜짐 상태 | Safety `getTelltalesInfo`, `registerTelltales` | PRIVATE_CAR_SAFETY (signature·privileged) · [향후] |

#### 처리 규칙

- 운전자는 정차 중에 색(빨강·주황·초록·파랑 등) → 모양 → 켜짐·깜박임을 차례로 세 번 누릅니다. 앱은 지원 차량의 도감에서 후보를 최대 3개까지 보여 줍니다. 모양 아이콘은 제조사 원본이 아니라 단순한 기호로 그립니다.
- "말로 찾기"는 버튼을 한 번 누르면 최대 8초 듣고, 결과 문자열에서 색과 모양 낱말을 골라 같은 후보를 찾습니다.
- 주행 중에는 "말로 하기"로만 찾습니다(3.1). 결과는 경고등 설명의 운행 판단 한 줄("바로 세우세요" 또는 "가까운 정비소에 들르세요")과 음성 한 번이며, 세 줄을 넘지 않습니다. 세 번 누르기와 자세한 설명은 정차 후에 엽니다.
- 차가 알려 준 점검 항목: 엔진오일, 브레이크액, 워셔액, 출력 저하 신호가 바뀌면 관련 도감 항목을 후보 맨 앞에 올리고 기록으로 남깁니다. 화면에는 "차가 알려 준 점검 항목"이라고 써서 경고등 상태와 구별합니다.
- 설명 문장은 대상 차량 취급설명서를 바탕으로 쓰고, 검토 전 문장에는 "안내 예시(검토 전)" 표시를 붙입니다.
- 출발 전 점검 카드는 앱을 열었을 때 정차 중 홈 맨 위에 보입니다. 점검 항목(엔진오일·브레이크액·워셔액·출력 저하), 정비 일정, 끝나지 않은 기록, 보호자·휴대폰 준비를 한 장으로 보여 주고, 출발하면 접힙니다. 정비 일정은 운전자가 정비 노트에 적어 둔 다음 점검 주행거리까지 남은 거리입니다. 문과 안전벨트는 시스템 출발 전 안내가 맡으므로 이 카드에서 빼고, 사고 순간 스냅샷에만 씁니다.
- 경고등 익히기 카드는 일주일에 한 번 정차 중 홈에 내 차 경고등 하나를 보여 줍니다. 운전자는 뜻을 읽고 "계속 가도 되나요?"에 답을 고릅니다.
- 사진으로 경고등 찾기 [설계]: 정차 후 휴대폰 보조 앱으로 계기판을 찍으면, 사진이 차 화면의 후보 옆에 놓입니다. 운전자는 사진과 후보를 직접 비교해 고릅니다. 사진을 자동으로 알아보는 기능은 [향후]입니다.

![경고등 설명(왼쪽)과 출발 전 점검(오른쪽). 설명은 후보 바로 아래에 운행 판단 한 줄('가까운 정비소에 들르세요')을 두고 '정차 후 자세히'·'정비소 들르기'로 이어집니다. 점검 카드는 워셔액 부족([시험 입력]), 다음 점검까지 2,860km, 끝나지 않은 기록, 보호자·휴대폰 준비를 보여 주고 '확인했어요'·'정비소 들르기'를 둡니다.](assets/v4/composite/pair-result-check.png){w=13}

#### 실패·결측 처리

- 신호를 지원하지 않거나 권한이 없으면 그 항목만 "이 차에서 확인 불가"로 표시합니다. 색·모양 찾기는 그대로 씁니다.
- 음성 인식이 결과를 내지 못하면 한 번만 다시 묻고, 이어서 버튼 찾기로 돌아갑니다.
- 맞는 후보가 없으면 "가까운 정비소에 문의하세요"와 함께 기록 남기기를 제안합니다.

### 3.3 F2 증상 기록 [시연]

**사용자 이야기.** 출근길에 초보 운전자가 앞 타이어 쪽에서 "끼익" 하는 소리를 잠깐 듣습니다. 주행 중이라 "지금 기록"만 한 번 누릅니다. 앱은 아무것도 묻지 않고 "기록했습니다"라는 짧은 음성만 냅니다. 회사 주차장에 차를 세우자 기록 화면이 "어떤 증상이었나요?"를 묻고, 운전자는 "소음"을 고른 뒤 "말로 메모"로 "앞 타이어 쪽 끼익 소리"를 남깁니다. 일주일 동안 같은 소리를 세 번 기록하자, 재현 조건 카드가 "평소와 달리 세 번 모두 시속 20km 아래에서 브레이크를 밟을 때"라고 정리합니다.

![지금 기록(왼쪽)과 재현 조건(오른쪽). 기록은 누른 순간 앞뒤의 차량 상태 시간표와 '기록 끝내기'·'말로 메모'를 보여 줍니다. 재현 조건은 같은 증상 세 번을 평소 주행과 비교해 겹친 조건(시속 20km 아래, 브레이크 밟는 중)과 소리 원인 후보에서 뺀 것(에어컨·창문·와이퍼)을 보여 주고 '기록 목록'·'정비소에 보여 주기'를 둡니다.](assets/v4/composite/pair-record-pattern.png){w=13}

표: F2 입력 신호
| 입력 | API·출처 | 권한(보호 수준) · 등급 |
|---|---|---|

#### 처리 규칙

- "지금 기록"을 한 번 누르면 누른 시각 앞 30초와 뒤 60초 동안 받은 차량 값을 시간표로 묶습니다. 이를 위해 차량 앱은 최근 값을 기기 안에 잠시만 보관합니다. 화면은 누른 시각 앞 20초와 뒤 10초를 먼저 보여 줍니다. 주행 중에는 아무것도 묻지 않고 짧은 음성으로 저장을 알립니다.
- 차를 세우면 어떤 증상이었는지 묻습니다. 운전자는 떨림·소음·쏠림·냄새·타이어·잘 모르겠음 같은 증상을 고르고, 짧은 메모를 말이나 글로 덧붙입니다. 부위는 홈의 아반떼 그림(앞부분·앞 타이어·실내·뒤쪽)에서 고르고, 모르면 비워 둡니다.
- 운전자가 고른 증상과 차량 값은 출처를 나눠 저장합니다. 정비사는 "운전자 선택"과 "차량 SDK" 값을 구별해 봅니다.
- 재현 조건 카드: 같은 부위·같은 증상이 세 번 이상 쌓이면 만듭니다. 후보 조건은 차속 구간(20km/h 단위), 브레이크 밟음, 조향 방향, 방향지시등, 출발 뒤 경과 시간, 공조 바람 세기, 창문 열림, 와이퍼 상태입니다. 앱은 주행 중 차량 상태를 60초에 한 번 가볍게 남겨 평소 비율을 구하고, 세 번 중 두 번 이상 나타났으며 평소 비율의 1.5배 이상인 조건만 보여 줍니다. 모든 기록에 같은 조건은 "공통", 일부에만 있는 조건은 "자주"로 씁니다. 주행거리처럼 늘 쌓이는 값은 조건에서 뺍니다.
- 소리 용의자 지우기 [시연]: 기록 순간의 공조 바람 세기, 에어컨, 창문 열림, 와이퍼 상태를 함께 남깁니다. 이 값이 평소와 같았으면 재현 조건 카드에 "소리 원인 후보에서 뺀 것"으로 적어, 정비사가 공조 소리나 차 밖 소리를 먼저 가려내게 합니다.
- 정비 노트에는 운전자가 정비소에서 들은 결과와 다음 점검 주행거리를 남깁니다. 주행거리가 500km 늘면 정차 중에 "같은 증상이 다시 있었나요?"를 묻습니다. "아니요"면 기록을 정비 완료로 닫고, "다시 있어요"면 같은 기록에 이어 붙입니다.

#### 실패·결측 처리

- 값이 오지 않으면 비어 있는 값과 품질 상태로 남깁니다. 브레이크 값이 없으면 "확인 불가"로 남기고 "밟지 않음"과 구별합니다.
- 차속이 3초 넘게 끊기면 오래된 값으로 표시합니다. 재현 조건 계산에서는 오래된 값과 확인 불가 값을 빼고, 몇 번의 기록이 빠졌는지 카드에 적습니다.
- 위치나 차속 권한을 허락받지 못하면 그 값 없이 기록하고, 정차 중 설정·동의 화면에서 다시 요청합니다.

### 3.4 F3 긴급 안내 [시연]

**사용자 이야기.** 원하지 않게 차가 빨라지는 느낌이 들자 운전자가 "도움이 필요해요"를 누르고 "저절로 빨라져요"를 고릅니다. 앱은 일반 메뉴를 숨기고 원치 않는 가속 안내를 엽니다. 해당 차량 취급설명서의 비상 절차를 짧은 음성 한 문장과 움직이지 않는 그림 한 장으로 전합니다. 브레이크를 밟아도 속도가 줄지 않으면 오른쪽 "안 멈춰요"를 눌러 감속 실패 대처로 넘어가고, 잘못 눌렀다면 왼쪽 "괜찮아요"로 바로 끝냅니다.

![원치 않는 가속 안내(왼쪽)와 비상 절차 미리 익히기(오른쪽). 주행 중 안내는 '앞을 보세요', 음성, 정지 그림 한 장(아반떼 실사 뒷모습 사진)과 '괜찮아요(안내 끝내기)'·'안 멈춰요(감속 실패 대처)'만 둡니다. 미리 익히기는 정차 중에만 열리고 브레이크 신호로 연습을 확인하며 '그만하기'·'다음 단계'를 둡니다.](assets/v4/composite/pair-emergency-practice.png){w=13}

![확인 질문. 센서 조합이 맞으면 '차가 멈추지 않나요?'만 묻습니다. '괜찮아요'는 끝내고 '안 멈춰요'는 감속 실패 대처로 갑니다.](assets/v4/portrait/p-confirm.png){w=5}

#### 처리 규칙

- 안내는 운전자의 직접 보고로만 시작합니다. 상황 선택에서 고르거나, "말로 하기"를 먼저 누른 뒤 말하는 경우입니다. "저절로 빨라져요"는 원치 않는 가속 안내로, "안 멈춰요"는 감속 실패 대처로 갑니다.
- 센서 조합은 확인 질문만 띄웁니다. 차가 움직이는 중(초속 1m 이상)에 브레이크가 1초(1,000ms) 넘게 밟혀 있는데 속도가 0.5m/s 넘게 줄지 않는 것처럼 판정 설정값에 정한 조합이 보이면 "차가 멈추지 않나요?"를 묻습니다. 같은 주행에서 확인 질문은 5분에 한 번까지만 띄웁니다.
- 원치 않는 가속 안내는 일반 메뉴를 숨기고 대상 차량 취급설명서의 비상 절차 문장을 그대로 읽습니다. 단계마다 정지 그림 한 장과 한 문장을 씁니다.
- 감속 실패 대처는 안내 자막 자리에 "취급설명서 비상 제동 절차(검토 후 확정 문장)"를 표시하고, 검토를 마친 문장만 넣습니다. 정지 그림은 최대 한 장이고, 주행 중에는 출처 줄을 숨깁니다. 버튼은 왼쪽 "차가 멈췄어요"(안내 끝내기), 오른쪽 "도움 요청"입니다.
- 버튼 자리 규칙은 앱 전체가 같습니다. 왼쪽은 끝내기·취소·기록(중립색), 오른쪽은 도움·보내기·감속 실패(빨강)입니다. 홈의 빨간 "도움이 필요해요"와 같은 쪽이라, 긴급 화면으로 넘어가도 빨간 버튼의 자리가 바뀌지 않습니다. 화면이 바뀐 직후 0.5초 동안은 누름을 받지 않습니다.
- 정차가 확인되거나 "차가 멈췄어요"를 누르면 음성 안내를 끝내고 정차 후 확인 화면을 엽니다. 운전자는 "괜찮아요", "보호자에게 알리기", "기록 보기" 가운데 하나를 고릅니다. 이 화면에 119와 블루링크 SOS 이용 방법을 함께 보여 줍니다.
- 정차 후 할 일 카드 [설계]: 사고나 감속 실패 뒤 차가 멈추면 취급설명서의 "정차 후 조치" 문장(비상등 켜기, 안전한 곳으로 대피하기 등)을 검토를 거쳐 큰 글씨 카드로 보여 줍니다. 안내 시작, 단계, 운전자 반응은 모두 기록에 남습니다.
- 비상 절차 미리 익히기는 차가 정차해 주행 제한이 없을 때만 열립니다. 페달 그림과 설명 애니메이션은 이 화면에서만 씁니다. 앱이 "브레이크 페달을 밟아 보세요"라고 말하면 Brake 신호로 실제로 밟았는지 확인한 뒤 다음 단계로 갑니다. 한 번의 연습은 3분 안에 끝나고, 연습 기록은 사고 기록과 따로 둡니다.

#### 실패·결측 처리

- 음성을 낼 수 없거나 오디오 포커스를 얻지 못하면 화면으로만 안내하고 그 사실을 기록합니다.
- Gleo가 호출되거나 전화가 걸려 오면 앱 음성을 멈추고, 끝나면 현재 단계를 처음부터 다시 말합니다.
- 브레이크 값이 없으면 "브레이크 확인 불가"로 표시하고, 안내는 운전자 보고에 따라 이어 갑니다.
- 취급설명서와 대조하기 전의 문장은 "시연용 초안"으로 표시합니다. 출시 빌드에는 검토를 마친 문장만 넣습니다.

### 3.5 F4 보호자 알림 [시연]·[설계]

#### 처리 규칙

- 위험 등급에 따라 보내는 방법이 다릅니다(7.2). 에어백 전개 신호와 운전자의 "사고가 났어요" 선택은 발송 전 확인 10초 뒤 자동으로 보냅니다. "지금 도움 요청"은 받는 사람 목록이 보이는 확인 화면에서 "보내기"를 누르면 바로 보냅니다. 차체 떨림·타는 냄새 같은 증상 선택은 자동으로 보내지 않고, 운전자가 정차 후 "보호자에게 알리기"를 고를 때만 보냅니다.
- 사고 순간 차량 스냅샷을 함께 보냅니다. 대표 사례에서는 운전석 에어백 전개, 탑승 1명(운전석), 운전석 안전벨트 착용, 문 모두 닫힘, 위치(21:00:01 측정)입니다.
- 보호자 메시지 첫 줄은 할 일입니다. "먼저 전화해 보세요. 받지 않고 사고가 의심되면 119에 이 위치를 알려 주세요." 그 아래에 위치를 잰 시각, 주소, 운전자 응답 여부가 나옵니다(예시는 7.4). 지도는 보호자 휴대폰의 보호자 웹이 서버·웹 기능으로 보여 주고, 차 화면에는 지도를 그리지 않습니다.
- 보호자가 알림 페이지에서 [확인했어요] 또는 [전화할게요]를 누르면 차 화면과 짧은 음성으로 운전자에게 전해집니다.
- 보호자 등록: 보호자는 초대 메시지에서 번호 인증과 수신 동의를 마칩니다. 그 뒤 "[연습]" 알림을 한 번 받아 발신 이름과 알림 모양을 익힙니다. 보호자는 최대 3명까지 등록하고, 인원과 관계없이 무료입니다.
- 보호자 페이지 2단계 열람 [설계]: 보호자가 링크를 열면 휴대폰 번호 뒷자리를 한 번 더 확인한 뒤에 위치와 상태를 보여 줍니다. 서버는 링크의 일회용 값을 보호자 세션으로 바꿔 씁니다.
- 위치를 보낼 때마다 운전자에게 받은 사람과 보낸 시각을 알리고, 그 자리에서 공유를 멈출 수 있게 합니다. 내 위치 영수증함 [설계]: 운전자는 언제 누구에게 위치가 갔는지 목록으로 보고, 거기서도 공유를 멈춥니다.
- 이미 보낸 뒤 운전자가 "괜찮아요"를 누르면 정정 알림을 보냅니다. 보낸 알림은 기록에 그대로 둡니다.
- 도착 알림 [설계]: 운전자가 켠 경우에만, 내비 길안내가 목적지 도착으로 끝나면 보호자에게 "잘 도착했어요"를 보냅니다. 기본은 꺼져 있습니다.

#### 실패·결측 처리

- 등록한 보호자가 없거나 동의가 없으면 보내지 않고, 화면에 119와 블루링크 SOS 이용 방법을 보여 줍니다.
- 통신이 끊기면 기기 안 대기열에 두고 같은 기록 번호로 다시 보냅니다. 서버에 이미 올라간 알림 작업은 휴대폰 보조 앱이 이어받을 수 있습니다(3.7).
- 위치가 없으면 "위치 확인 안 됨"으로 먼저 보내고, 위치가 들어오면 알림 페이지만 갱신합니다. 주소 변환은 발송과 따로 진행합니다.

### 3.6 F5 정비소 연결 [시연]·[설계]

**사용자 이야기.** 휴게소에서 경고등 설명을 읽은 운전자가 "정비소 들르기"를 누릅니다. 앱은 가까운 정비소 세 곳과 후보마다 도착 예상 시각을 목록으로 보여 줍니다. "내비에서 보기"를 누르자 옆 창의 내비가 후보 위치를 보여 줍니다. 운전자가 "경유지로 추가"를 누르면, 지금 가던 목적지는 그대로 두고 정비소가 경유지로 들어갑니다.

![정비소 들르기. 후보 세 곳과 도착 예상 시각을 목록으로 보여 주고 지도는 그리지 않습니다. '내비에서 보기'는 옆 내비에 후보를 띄우고, '경유지로 추가'는 지금 경로에 정비소를 더합니다.](assets/v4/portrait/p-service.png){w=5.5}

표: F5 입력 신호
| 입력 | API·출처 | 권한(보호 수준) · 등급 |
|---|---|---|
| 현재 길안내 상태 | NaviHelper `getRouteStateInfo` | NAVI_ROUTE(normal) · [시연] |
| 경유지 추가(길안내 중) | NaviHelper `addWaypoint` | NAVI_ROUTE_SEARCH(normal) · [시연] |

| 예약·접수 연동 | 정비소 제휴 API | [향후] |

#### 처리 규칙

- 길안내 중이면 `addWaypoint`로 지금 경로에 경유지를 더해 가던 목적지를 유지합니다. 길안내 중이 아니면 `requestRoute`로 정비소를 목적지로 정합니다. `requestRouteWithWaypoints`는 목적지와 경유지를 새로 지정하는 요청이라 이 장면에서는 쓰지 않습니다. 경유지는 Pleos 문서에 따라 최대 2곳입니다.
- `requestTrip`의 응답은 후보까지의 거리와 걸리는 시간이며, 요청 번호가 없습니다. 그래서 후보를 한 번에 하나씩 차례로 물어 도착 예상 시각을 받습니다. 원래 목적지 도착이 얼마나 늦어지는지는 경유지를 넣은 뒤에 내비가 다시 계산한 값으로만 알립니다.
- 공개 SDK에는 지도를 그리는 기능이 없으므로, 지도는 옆 창의 내비에 맡깁니다(`requestNavigationScreen`).
- 주행 중에는 음성으로 후보를 듣고 큰 버튼 하나로 고릅니다.
- 정비소에서는 정차한 차 화면으로 기록을 함께 보거나, QR로 정비사 휴대폰에 24시간만 열리는 읽기 전용 요약을 보냅니다. 운전자가 고른 기록만 보냅니다.
- 정비소 도착 체크인 [설계]: 고른 정비소 가까이에 도착하면 위치로 이를 알아채고, 재현 조건 카드를 홈 맨 위에 올려 바로 보여 줄 수 있게 합니다.
- 고른 정비소와 시각은 같은 기록에 남습니다.

#### 실패·결측 처리

- 내비게이션 연결이 실패하거나 도착 예상 계산에 오류가 나면 거리 순 목록과 주소만 보여 줍니다.
- 앱 자체 정비소 좌표로 경유지 요청이 되지 않으면 "내비에서 보기"로 내비의 장소 검색을 열어 줍니다.
- 정비 공유 링크는 만료되거나 운전자가 철회하면 바로 닫힙니다.

### 3.7 F6 휴대폰 보조 앱 [설계]

**사용자 이야기.** 딸은 아버지 차의 App Market에서 플레오스 가드를 내려받고, 아버지 휴대폰에 보조 앱을 설치합니다. 차를 세운 상태에서 차 화면의 코드를 휴대폰으로 찍고, 차 화면의 확인 버튼을 누르면 두 앱이 연결됩니다. 글자 입력이 많은 보호자 번호 등록은 휴대폰에서 합니다.

- **별도 설치 파일.** 휴대폰 보조 앱은 Pleos SDK를 넣지 않은 별도 APK입니다. FusedLocation SDK가 차량용 기기에서만 설치되도록 선언되어 있어, 차량 앱과 같은 설치 파일을 휴대폰에 쓸 수 없기 때문입니다.
- **연결.** 정차 중 차 화면에 일회용 코드(QR)를 띄우고, 휴대폰으로 찍은 뒤 차 화면의 확인 버튼을 눌러야 연결이 끝납니다. 먼저 찍은 사람이 소유자가 되는 일을 막기 위해서입니다. 소유자를 바꿀 때는 따로 이전 절차를 거칩니다. 이후에는 서버를 거쳐 같은 기록 번호를 씁니다.
- **맡는 일.** 보호자 번호 입력과 인증, 연습 알림 관리, 계기판 사진 비교를 맡습니다. 사진은 정차 후 차 화면의 후보 옆에 놓이고, 운전자가 직접 비교해 고릅니다. 사진 자동 인식은 [향후]입니다.
- **보호자 알림 이어받기.** 차량 앱이 서버에 사건을 올린 뒤 연락이 끊기면, 휴대폰은 서버에 남은 알림 작업과 남은 확인 시간으로 발송 확인을 이어 보여 줍니다. 이어받는 범위는 서버에 올라간 사건까지입니다. 통신이 없을 때 휴대폰 문자 작성 화면을 미리 채워 여는 기능은 [향후]입니다.
- **위치 출처.** 휴대폰이 잰 위치는 차량 위치와 다른 출처로 표시합니다.

### 3.8 F0 시연 모드 [시연]

- **시험 입력 재생기.** 미리 쓴 각본(JSON)으로 차속, 에어백 전개, 안전벨트, 엔진오일 같은 값을 넣습니다. 이 값은 실제 SDK 값과 같은 입구로 들어가 같은 규칙으로 처리되고, 신호마다 출처와 품질을 `TEST_INPUT`으로 저장합니다. 화면의 값마다 "차량 SDK", "시험 입력", "운전자 선택" 가운데 하나의 표시를 붙입니다.
- **모의 발송.** 시험 입력이 하나라도 섞인 사건은 실제 보호자에게 보내지 않고 모의 발송만 합니다. 모의 서버는 같은 메시지를 PC 브라우저의 보호자 웹 화면에 보여 줍니다.
- **출시 빌드.** 시연 모드는 출시 빌드에서 숨깁니다. Pleos 앱 심사는 시험용 더미 데이터를 남기지 않을 것을 요구합니다.

## 4. 화면 설계

### 4.1 세로 한 창을 기본으로, 가로는 확장으로

Pleos 문서에 따르면 앱은 따로 지정하지 않으면 세로(portrait) 한 창으로 실행되고, 두 앱을 함께 띄우면 각 앱은 보통 세로 창이 됩니다. 모든 앱은 가로와 세로 두 배치를 갖춰야 하고, 레터박스 없이 화면을 채워야 하며, 어떤 배치에서도 같은 기능을 보여야 합니다(기능 패리티). 플레오스 가드는 세로 한 창을 기본 배치로 설계하고, 가로 화면은 같은 기능을 넓게 보여 주는 확장 배치로 둡니다.

**내비 옆 동반 창 [시연].** 주행 중에는 내비 옆 세로 창이 기본 자리입니다. 앱은 지도를 그리지 않고, 위치를 보여 줄 일이 있으면 `requestNavigationScreen`으로 옆 내비 화면에 맡깁니다. 앱 창에는 기록과 판단, 큰 버튼만 남깁니다.

표: 세로 한 창과 가로 화면의 배치
| 영역 | 세로 한 창(기본) | 가로 화면(확장) |
|---|---|---|
| 메뉴 | 위쪽 탭 4개: 경고등 찾기·증상 기록·보호자 알림·정비소(홈은 왼쪽 위 로고) | 왼쪽 도크 5개: 홈과 같은 4개 메뉴 |
| 차 그림 | 가운데. 주행 중에는 숨깁니다. | 가운데 큰 그림. 주행 중에는 숨깁니다. |
| 맥락 정보 | 차 그림 아래 패널 | 오른쪽 패널 |
| 주 버튼(정차 중) | 아래 2개: 왼쪽 지금 기록, 오른쪽 도움이 필요해요 | 같은 이름, 같은 자리 |
| 주 버튼(주행 중) | 큰 버튼 3개: 지금 기록·말로 하기·도움이 필요해요 | 같은 이름, 같은 순서 |
| 긴급 화면 | 앱 창 전체를 긴급 화면으로 바꿉니다. | 같은 문장, 같은 그림, 같은 자리의 두 버튼 |

창 크기나 방향이 바뀌어도 고른 부위, 진행 중인 안내 단계, 발송 확인의 남은 시간은 그대로 유지합니다. 실제 창 크기는 에뮬레이터의 FormFactorConsole로 12.9인치 세로와 14.6인치 가로 등 화면 종류별로 확인합니다.

![가로 화면의 홈. 세로와 같은 기능을 왼쪽 도크, 가운데 차 그림, 오른쪽 맥락 패널로 넓게 배치하고, 아래 버튼도 '지금 기록'·'도움이 필요해요'로 같습니다.](assets/v4/landscape/ui-home.png){w=12.5}

### 4.2 주행 중 화면 규칙

- 단계마다 움직이지 않는 그림 한 장과 짧은 음성만 씁니다. 애니메이션과 동영상은 정차 중 연습 화면에만 둡니다.
- 글은 세 줄 이하로 씁니다. 주행 중 홈은 큰 버튼 세 개, 상황 선택은 큰 카드 다섯 개(정차 후 12개), 긴급 화면은 버튼 두 개만 둡니다(3.1).
- 메뉴 깊이는 3단계 이하로 두고, 목록은 한 화면에 들어가게 줄입니다.
- 긴급 화면도 앱 창 안에서만 바꿉니다.
- 발이나 손의 동작을 이끄는 그림(발 이동 사진, 화살표)은 정차 중 연습 화면에만 둡니다.
- 글자 입력, 설정, 보호자 등록, 동의 변경, QR 연결, 경고등 자세한 설명은 정차 후에만 엽니다.
- 주행 상태를 알 수 없으면 주행 중으로 보고 화면을 줄입니다.
- 지금 시안은 야간 테마입니다. 조명 환경에 맞춰 밝기와 대비를 바꾸도록 주간 테마를 더합니다.
- 가로 화면의 긴급 안내도 세로와 같은 문장, 같은 그림, 같은 자리의 두 버튼을 씁니다.

![가로 화면의 확인 질문. 세로와 같은 문장과 같은 자리의 두 버튼('괜찮아요'·'안 멈춰요')을 씁니다.](assets/v4/landscape/ui-confirm.png){w=10}

### 4.3 화면 수치와 근거

화면 수치는 Pleos 공식 문서에 있는 값과 이 앱이 스스로 정한 값을 나눠 적습니다. Pleos 문서에는 버튼 크기의 dp 수치가 없으므로, 80dp는 자체 설계값입니다.

표: 화면 수치의 근거

|---|---|---|---|

| Pleos 공식 | 글자 높이 | 기본 5mm 이상, 보조 3mm 이상 | Pleos 디자인 원칙 |
| Pleos 공식 | 최소 글자 크기 | 12sp 이상 권장 | Pleos 타이포그래피 |
| Pleos 공식 | 입력 응답 | 0.25초 이하 | Pleos 디자인 원칙, 앱 심사 |
| Pleos 공식 | 버튼 반응, 앱 실행 | 2초 이내, 10초 이내 | Pleos 앱 심사 |
| Pleos 공식 | 주행 중 문단 | 3줄 이하 | Pleos 디자인 원칙 |

### 4.4 화면 문구표

앱 전체에서 왼쪽 버튼은 끝내기·취소·기록(중립색), 오른쪽 버튼은 도움·보내기·감속 실패(빨강)입니다. 오른쪽이 빨강이 아닌 화면은 오른쪽을 주 행동 색으로 둡니다. 문서, 그림, 계약은 아래 이름을 그대로 씁니다.

표: 화면별 위쪽 내용과 버튼 이름
| 화면 | 위쪽 | 왼쪽 버튼(중립) | 오른쪽 버튼(빨강 또는 주 행동) |
|---|---|---|---|
| 홈(정차) | 탭: 경고등 찾기 · 증상 기록 · 보호자 알림 · 정비소 | 지금 기록 | 도움이 필요해요 |
| 홈(주행 중) | 차 그림·탭 숨김, 큰 버튼 3개 | 지금 기록 · 말로 하기(가운데) | 도움이 필요해요 |
| 상황 선택 | 주행 중 5개, 정차 후 12개 | 고른 증상 기록 | 지금 도움 요청 |
| 확인 질문 | 차가 멈추지 않나요? | 괜찮아요 | 안 멈춰요 |
| 원치 않는 가속 안내 | 앞을 보세요 · 음성 안내 | 괜찮아요(안내 끝내기) | 안 멈춰요(감속 실패 대처) |
| 감속 실패 대처 | 취급설명서 비상 제동 절차 | 차가 멈췄어요(안내 끝내기) | 도움 요청 |
| 발송 확인 10초 | 무엇을 감지했는지 · 받는 사람 | 괜찮아요(보내지 않음) | 지금 보내기 |
| 보호자 알림 상태 | 보호자별 한 줄 상태 · 위치 측정 시각(지도 없음) | 기록 보기 | 공유 중지 |
| 경고등 찾기 | 색 → 모양 → 켜짐·깜박임 | 문구로 찾기 | 말로 찾기 |
| 경고등 설명 | 주행 중 한 줄 판단 | 정차 후 자세히 | 정비소 들르기 |
| 출발 전 점검 | 점검 항목 · 정비 일정 · 끝나지 않은 기록 · 보호자·휴대폰 준비 | 확인했어요 | 정비소 들르기 |
| 지금 기록 | 차량 상태 시간표 | 기록 끝내기 | 말로 메모 |
| 재현 조건 | 같은 증상 3회 · 평소보다 겹친 조건 | 기록 목록 | 정비소에 보여 주기 |
| 비상 절차 미리 익히기 | 정차 중에만 · 단계 1/3 | 그만하기 | 다음 단계 |
| 정비소 들르기 | 후보 목록 · 도착 예상 시각(지도 없음) | 내비에서 보기 | 경유지로 추가 |

이 밖에 점검 항목, 정비 노트, 정차 후 확인, 설정·동의, 휴대폰 연결, 내 위치 영수증함, 시연 모드 화면은 정차 중에만 엽니다. 받는 사람 확인은 "도움 요청"에서 열리며 받는 사람 목록과 "보내기"만 보여 줍니다.

## 5. Pleos SDK 사용 계획 {nobreak}

### 5.1 SDK별 사용 표

공모전이 허용한 공개 SDK 5종을 모두 쓰고, 차속과 주행 제한은 Pleos 문서가 안내하는 AAOS 경로로 읽습니다. Vehicle SDK 권한은 이름 앞에 `pleos.car.permission.`이 붙고, 문서상 보호 수준이 normal이라 실행 중 승인 창이 없습니다. 위치(`FUSED_LOCATION`)와 AAOS 차속(`CAR_SPEED`)은 dangerous라서 실행 중에 운전자 허락을 받고, 거부하면 그 값 없이 동작합니다. 모든 Vehicle 도메인은 먼저 `check…Capabilities`로 이 차가 지원하는지 확인합니다.

표: SDK·도메인별 메서드, 권한, 쓰는 기능
| SDK·도메인 (권한, 보호 수준) | 쓰는 메서드 | 쓰는 기능 · 에뮬레이터 확인 |
|---|---|---|
| Vehicle 2.3.2 Brake (CAR_DRIVE, normal) | `getCurrentBrakePedalStatus`, `registerBrakePedalStatus` | 긴급 안내, 확인 질문, 지금 기록, 미리 익히기 · Virtual Console Brake Pedal |

| Vehicle TurnSignal (CAR_LIGHTS, normal) | `getCurrentTurnSignalState`, `registerTurnSignalState` | 재현 조건 · Turn Signal State 카드 |

| Vehicle Fuel, EvBattery (CAR_ENERGY, normal) | `getFuelPercent`, `getEvBatteryStateOfCharge` | 기록과 사고 스냅샷 · Battery SOC 카드, 연료는 시험 입력 |

| AAOS Car API (권한 없음) | `CarUxRestrictionsManager`의 `registerListener` | 주행 제한에 따른 화면 축소 · adb `driving_regulation on/off` |
| TextToSpeech 3.3.1 (TTS_SERVICE, 미기재) | `Mode.ON_DEVICE`, `setLocale(Locale.KOREA)`, `setAudioAttributes`, `speak`, `stop` | 긴급 안내, 결과 읽기 · 소리 출력, `onStart`·`onDone` 기록 |
| SpeechToText 3.3.1 (STT_SERVICE, 미기재) | `Mode.ON_DEVICE`, `request`, `stop`, `ResultListener.onUpdated` | 말로 하기, 말로 찾기, 말로 메모 · Extended Controls 마이크 |
| FusedLocation 1.1.3 (FUSED_LOCATION, dangerous) | `isSupported`, `initialize`, `registerFusedLocationCallback`, `getLastKnownLocation` | 사건 위치와 측정 시각, 정비소 도착 · 에뮬레이터 위치 설정 |
| NaviHelper 3.0.5 (NAVI_ROUTE·NAVI_ROUTE_SEARCH·NAVI_CUSTOM_MAP, normal) | `getCurrentLocationInfo`·`getRouteStateInfo`·`requestTrip`(NAVI_ROUTE), `addWaypoint`·`requestRoute`(NAVI_ROUTE_SEARCH), `requestNavigationScreen`(NAVI_CUSTOM_MAP) | 주소, 정비소 들르기, 내비에서 보기 · 에뮬레이터 내비게이션 |

매니페스트에는 실제로 쓰는 권한만 선언합니다. `PRIVATE_*` 권한과 차량을 제어하는 `CONTROL_*` 권한은 선언하지 않습니다. 음성 입출력은 기기 안 모드(ON_DEVICE)로 쓰므로 앱 등록과 네트워크가 필요 없습니다.

### 5.2 공통 처리 규칙

- **지원 확인.** 기능을 켜기 전에 지원 확인 API를 부릅니다. 지원하지 않는 기능은 Capability 결과(AccessType NONE 등)로 알 수 있고, 그 항목은 "이 차에서 확인 불가"로 표시합니다.
- **권한 오류.** 권한이 없으면 SDK가 `SecurityException`을 던집니다. 구독(register) 계열은 호출 즉시 던지고, 조회 계열은 실패 콜백으로 알려 줍니다. 앱은 둘 다 잡아서 그 항목만 "권한 없음"으로 표시합니다. 지원 여부와 권한 오류는 서로 다른 경로로 판단합니다.
- **서비스 연결.** `initialize` 전의 호출은 실패하고, 연결 중의 호출은 대기열에 쌓입니다. 대기에는 시간 제한이 없으므로 앱이 자체 시간 제한을 둡니다.
- **콜백 스레드.** 결과와 이벤트 콜백은 메인 스레드가 아닌 곳에서 옵니다. 화면 갱신은 메인 스레드로 넘깁니다.
- **값과 시각.** Vehicle SDK 값에는 측정 시각이 없습니다. 그래서 앱이 받은 시각을 함께 저장합니다.
- **재연결.** 서비스가 다시 연결되면 SDK가 구독을 다시 등록합니다. 앱은 재연결 직후 현재 값을 한 번 다시 읽습니다.
- **뒤에 있을 때.** 앱이 백그라운드로 가면 화면 갱신과 필요 없는 구독을 멈추고, 에어백 전개와 브레이크 구독은 유지합니다. 앱 프로세스가 없으면 신호를 받을 수 없습니다. 앱이 뒤에 있을 때 사고 신호가 오면 화면을 강제로 띄우지 않고 음성 1회와 시스템 알림 1개를 냅니다. 끝날 때는 `release`로 연결을 풉니다.

### 5.3 차속은 AAOS 경로로 읽습니다

Vehicle SDK 2.3.2에서는 차속 리스너가 빠졌습니다. Pleos 개발자 FAQ는 계기판과 같은 차속을 AAOS(안드로이드 차량용 운영체제)의 `CarPropertyManager`로 `PERF_VEHICLE_SPEED`를 읽어 얻으라고 안내합니다. 플레오스 가드는 이 안내를 따릅니다.

- 읽는 곳: `CarPropertyManager`의 `PERF_VEHICLE_SPEED` 속성
- 권한: `android.car.permission.CAR_SPEED`(dangerous, 실행 중 허락)
- 거부하면: 확인 질문과 재현 조건의 속도 칸을 끄고 "속도 권한 없음"을 표시합니다. 운전자의 직접 보고는 그대로 받습니다.
- 저장: m/s 단위로 받아 `speed_mps`에 저장합니다.
- 신선도: 주기적으로 오는 값이므로 3초(3,000ms) 넘게 끊기면 오래된 값으로 봅니다.
- 시연: Virtual Console에 차속 카드가 없으므로 시험 입력 재생기로 넣고 [시험 입력]을 표시합니다.

이 경로는 Pleos 개발자 FAQ와 SDK API 정책 문서가 안내하는 경로입니다. SDK API 정책은 속도·기어 상태 같은 표준 데이터를 AAOS Car API로 받는 데이터로 분류하고, Pleos SDK에는 같은 기능을 따로 두지 않는다고 밝힙니다. 그래서 공지 8이 말하는 "공개된 개발 문서의 API 범위" 안에 있습니다.

### 5.4 공지 8 준수표

### 6.2 오프라인 우선 기록

- 모든 기록은 먼저 차량 기기 안에 저장한 뒤 서버로 보냅니다. 주소 변환이나 사진 업로드와 따로 진행합니다.
- 기록마다 기기에서 만든 고유 번호를 붙입니다. 통신이 끊기면 기기 안 대기열에 두고 같은 번호로 다시 보내며, 서버는 한 번만 처리합니다(멱등 처리).
- 앱이 다시 시작되면 진행 중인 안내 단계와 발송 확인의 남은 시간을 되살립니다. 서버의 "접수"는 보호자가 받았다는 뜻이 아니므로 접수, 전달, 열람을 따로 기록합니다.
- 기기 시계는 서버 시각 응답과 비교해 오차를 재고, 기록 시각을 맞출 때 씁니다.

### 6.3 자료 품질과 신선도

표: 신호 품질 상태(값마다 출처 source, 받은 시각 received_at, 품질 quality를 함께 저장)
| 화면 표시 | 품질(`quality`) | 뜻 |
|---|---|---|
| 값 그대로 | OK | 정상으로 받은 값 |
| 오래된 값 | STALE | 주기적으로 오는 값이 3,000ms 넘게 끊김, 위치는 측정 뒤 60초가 지남 |
| 확인 불가 | UNAVAILABLE | 서비스 연결이 끊기거나 값이 오지 않음 |
| 권한 없음 | PERMISSION_DENIED | 권한이 없음 |
| 이 차에서 확인 불가 | NOT_SUPPORTED | 이 차가 지원하지 않음 |
| [시험 입력] | TEST_INPUT | 시험 입력 재생기가 넣은 값 |

- **주기형 신호**(차속)는 3초 넘게 끊기면 오래된 값으로 봅니다.
- **변화 알림형 신호**(브레이크, 문, 방향지시등)는 바뀔 때만 옵니다. 그래서 마지막으로 받은 시각과 서비스 연결 상태로 유효한지 판단합니다.
- 값이 없으면 비어 있는 값(null)과 품질 상태로 남깁니다.
- 위치는 SDK가 준 측정 시각과 `confidence` 원값을 그대로 저장합니다. FusedLocation은 미터 단위 정확도를 주지 않으므로 위치는 측정 시각과 함께 보여 줍니다. 휴대폰 위치는 다른 출처로 표시합니다.

### 6.4 사건 하나가 지나가는 길

에어백 전개 신호 하나가 보호자에게 닿기까지의 순서입니다. 각 단계는 앞 단계의 결과를 기다리지 않아도 되도록 나눴습니다. 오른쪽 열은 대표 사례의 시각입니다.

표: 에어백 전개 신호의 처리 순서
| 단계 | 하는 곳 | 하는 일 | 대표 사례 |
|---|---|---|---|
| 1. 신호 수신 | 차량 앱 어댑터 | Safety 구독으로 좌석별 에어백 전개를 받고, 출처·받은 시각·품질을 붙입니다. | 21:00:03 운전석 |
| 2. 기록 저장 | 차량 앱 | 차량 상태 스냅샷과 위치를 묶어 기기 안에 먼저 저장합니다. | 위치 21:00:01 측정 |
| 3. 판단 | 차량 앱 | L3로 보고 발송 확인 10초 화면을 띄웁니다. 주행 중이면 화면 규칙을 그대로 따릅니다. | 응답 없음 |
| 4. 사건 전송 | 차량 앱 → 서버 | 고유 번호를 붙여 사건을 올립니다. 통신이 없으면 대기열에서 다시 보냅니다. | – |
| 5. 발송 | 서버 | 시간이 끝나면 보호자별로 알림톡을 보내고, 알림톡 전달 확인 기한(10초) 안에 전달 확인이 없으면 문자로 바꿉니다. | 21:00:13 발송 시작, 보호자 2는 21:00:23 문자 |
| 6. 확인과 답 | 보호자 웹 → 차량 앱 | 보호자가 번호 뒷자리를 확인하고 열람한 뒤 빠른 답을 누르면 차 화면과 음성으로 전합니다. | 보호자 1, 21:01 열람, "전화할게요" |
| 7. 정리 | 차량 앱 | 정차 후 무엇을 누구에게 보냈는지 한 번 알리고, 위치 제공 기록을 남깁니다. | – |

|---|---|---|
| L1 기록 | 경고등 찾기 결과, 지금 기록, 소음 같은 가벼운 증상 | 기록만 남깁니다. |
| L2 확인 필요 | 차체 떨림, 타는 냄새, 타이어, 출력 저하 같은 증상 선택 | 자동으로 보내지 않습니다. 운전자가 정차 후 "보호자에게 알리기"를 고르면 받는 사람 확인 뒤 보냅니다. |
| L3 긴급 도움(자동) | 에어백 전개 신호, 운전자의 "사고가 났어요" 선택 | 발송 전 확인 10초를 띄우고, "괜찮아요(보내지 않음)"를 누르지 않으면 자동으로 보냅니다. |
| L3 긴급 도움(직접 요청) | "지금 도움 요청", 감속 실패 대처의 "도움 요청" | 받는 사람 목록이 보이는 확인 화면에서 "보내기"를 누르면 바로 보냅니다. |

표: 알림 정책 상태(`policy_state`)
| 화면 이름 | 상태 | 뜻 |
|---|---|---|
| 기록만 보관 | RECORD_ONLY | 자동 발송 없이 기록만 둔 상태(L1·L2)입니다. 운전자가 알리기를 고르면 받는 사람 확인으로 갑니다. |
| 10초 확인 | COUNTDOWN | 발송 전 확인 10초가 진행 중입니다. |
| 발송 시작 | RELEASED | 시간이 끝났거나 "지금 보내기"를 눌렀습니다. |
| 발송 중 | DISPATCHING | 보호자별로 보내고 있습니다. |
| 발송 종료 | SETTLED | 결과는 ALL_CONFIRMED(모두 전달), PARTIAL(일부 전달), NONE_CONFIRMED(전달 확인 없음) 가운데 하나입니다. |
| 보내지 않음 | CANCELLED | 확인 시간 안에 "괜찮아요(보내지 않음)"를 눌렀습니다. |
| 받는 사람 없음 | BLOCKED_NO_RECIPIENT | 119와 블루링크 SOS 이용 방법을 보여 줍니다. |
| 동의 없음 | BLOCKED_NO_CONSENT | 운전자 위치 제공 동의나 보호자 수신 동의가 없습니다. |
| 만료 | EXPIRED | 알림 유효 시간(24시간)이 지나 닫혔습니다. |

같은 차량에는 열린 알림을 하나만 둡니다. 2시간 안에 생긴 새 사건은 열린 알림에 묶고, 정정 알림은 예외로 따로 보냅니다. 묶인 사건에서 "괜찮아요(보내지 않음)"를 고르면 열린 알림 전체를 멈춥니다.

표: 전달 상태(`delivery_state`)
| 화면 표시 | 상태 | 서버 처리 |
|---|---|---|
| 보낼 준비 중 | PENDING | 발송 작업을 만들었습니다. |
| 접수됨 | ACCEPTED | 발송사가 접수했습니다. |
| 접수 확인 중 | SUBMISSION_UNKNOWN | 결과를 다시 조회하고, 기한이 지나면 문자로 바꿉니다. |
| 전달됨 | DELIVERED | 보호자 휴대폰에 전달됐습니다. |
| 전달 미확인 | DELIVERY_UNCONFIRMED | 기한 안에 전달을 확인하지 못해 문자로 바꿉니다. |
| 실패 | FAILED | 발송사가 실패를 알렸습니다. |
| 취소 | CANCELLED | 발송 전에 취소됐습니다. |

전달 상태는 보호자마다, 그리고 알림톡(KAKAO)과 문자(TEXT) 묶음마다 따로 둡니다. 화면은 보호자 한 명당 한 줄로 보여 줍니다. 대표 사례에서는 "보호자 1 · 알림톡 전달됨 · 21:01 열람 · 전화할게요", "보호자 2 · 알림톡 미확인 → 21:00:23 문자 전달됨"입니다. 열람은 상태가 아닙니다. 보호자가 링크를 열어 1단계 화면(무슨 일·시각·먼저 할 일)을 받으면 열람 시각(`opened_at`)을 따로 기록하고, 위치와 상태는 번호 뒷자리를 확인한 2단계에서 보여 줍니다. 링크 미리보기 접근은 열람으로 세지 않습니다.

### 7.3 10초의 뜻

문서에 나오는 10초는 두 가지이며, 이름을 나눠 씁니다.

- **발송 전 확인 10초.** 차 화면에서 운전자에게 주는 시간입니다. 운전자는 왼쪽 [괜찮아요(보내지 않음)] 또는 오른쪽 [지금 보내기]를 고릅니다. 고르지 않으면 시간이 끝날 때 자동으로 보냅니다.
- **알림톡 전달 확인 기한.** 서버가 정하는 시간입니다. 발송사에 처음 보낸 시각부터 기한(지금 설정값 10초) 안에 전달이 확인되지 않으면 문자로 바꿉니다. 다시 보내도 기한은 늦춰지지 않습니다. 대표 사례에서는 21:00:03 에어백 신호, 21:00:13 발송 시작, 21:00:23 문자 전환으로, 사고 감지부터 문자 전환까지 약 20초입니다.

이 밖의 시간 규칙은 "주기형 신호 신선도 3초"와 "보호자·정비 공유 링크 24시간"입니다.

### 7.4 보호자 메시지 예시

아래 예시는 알림톡 템플릿 심사에 낼 초안이며, 대표 사례의 값을 씁니다. 실제 발송에는 승인된 템플릿, 발신 채널, 보호자의 수신 동의가 필요합니다.

표: 보호자 알림톡 예시(사고, 대표 사례)
| 줄 | 내용 |
|---|---|
| 제목 | [플레오스 가드] 아버지 차에서 사고 신호가 왔습니다 |
| 먼저 할 일 | 먼저 전화해 보세요. 받지 않고 사고가 의심되면 119에 이 위치를 알려 주세요. |
| 감지 | 운전석 에어백 전개 신호 (21:00:03) |
| 화면 응답 | 10초 동안 없음 |
| 위치 | 서울 ○○구 ○○로 부근 (21:00:01 측정, 차량 위치) |
| 탑승 | 1명(운전석), 운전석 안전벨트 착용 |
| 상황 보기 | 보호자 전용 링크(휴대폰 번호 뒷자리 확인 뒤 24시간 열림) |
| 알림 | 이 알림은 119에 자동으로 신고되지 않습니다. |

- 머리말은 항상 `[플레오스 가드]`입니다. 연습 알림은 "[연습] 플레오스 가드 알림은 이렇게 옵니다. 실제 상황이 아닙니다."로 시작합니다.
- 첫 줄 다음에 보호자가 할 일을 둡니다. 보호자에게는 내부 등급 이름(L3) 대신 상황을 씁니다.
- 위치에는 측정 시각과 출처(차량·휴대폰)를 붙입니다.
- "화면 응답: 10초 동안 없음"처럼 확인한 사실만 씁니다.
- 보호자가 전화를 걸어 오면 차의 앱 음성은 멈추고, 통화가 끝나면 남은 안내를 다시 읽습니다(9.2).
- 정정 알림 예: "[플레오스 가드] 정정 안내. 21:00 알림 뒤 운전자가 화면에서 '괜찮아요'를 눌렀습니다(21:02)."

## 8. 데이터와 API 설계 요약 {nobreak}

이 장은 저장소의 설계 파일(요청 시 제공)인 서버 API 정의, 데이터베이스 정의, 판정 설정값, 인수 시나리오를 요약합니다. 현재 판(계약 v3.1)은 서버 API 경로 56개·작업 59개·스키마 171개(OpenAPI 3.1.0), 데이터베이스 테이블 36개(v3.1), 판정 설정 rules-lab 2.1.0, 화면 토큰 ui-tokens 5.1.0, 인수 시나리오 133개(3.1.0)이며, 설계 파일끼리 맞춰 보는 정적 검사를 통과(PASS)했습니다. 앱과 서버를 실행한 결과는 아닙니다. 이 별첨의 이름과 숫자는 설계 파일과 같고, 설계 파일에 아직 없는 것은 "계약 미반영(향후)"으로 표시합니다.

### 8.1 핵심 열거형

표: 핵심 열거형(enum, 한 항목이 가질 수 있는 값을 미리 정해 둔 목록)
| 이름 | 값 |

표: 수동 증상의 기본 등급과 안내(설계값, 시험으로 조정)
| 증상(화면 이름) | 값 | 최소 등급 | 주행 중 · 기본 안내 |
|---|---|---|---|
| 떨림(차체 떨림) | VIBRATION | L2 | 큰 카드 · G_VIBRATION_STOP(안전한 곳에 세우고 확인) |
| 냄새(타는 냄새) | BURNING_SMELL | L2 | 큰 카드 · G_SMELL_STOP |
| 사고(사고가 났어요) | COLLISION | L3 | 큰 카드(긴급) · G_COLLISION, 발송 전 확인 10초 |
| 타이어 | TIRE_DAMAGE | L2 | 정차 후 · G_TIRE_STOP |
| 잘 모르겠음 | UNKNOWN | L1 | 정차 후 · G_UNKNOWN_CHECK(기록, 다시 묻기) |
| 쏠림 | PULLING | L2 | 정차 후 · G_PULLING_STOP |
| 소음 | NOISE | L1 | 정차 후 · G_NOISE_CHECK(기록) |
| 페달 이상 | PEDAL_PROBLEM | L2 | 정차 후 · G_PEDAL_CHECK. 주행 중에는 "안 멈춰요"·"저절로 빨라져요" 카드의 기록값 |
| 출력 저하 | POWER_LOSS | L2 | 정차 후 · G_POWER_LOSS |

- 위 표는 작업 59개 가운데 대표 작업이며, 경로와 매개변수 이름은 설계 파일과 같습니다. 보호자 공유 링크만 따로 철회하는 작업과 보호자 인증 번호 다시 받기는 계약 미반영(향후)이며, 지금은 동의 철회와 보호자 삭제로 열린 링크를 닫습니다.
- 생성 요청에는 멱등 키(같은 요청을 한 번만 처리하게 하는 번호)를 붙입니다. 202 응답은 접수만 뜻하고, 409 응답은 버전 충돌입니다. 취소와 발송이 겹치면 먼저 처리한 쪽을 따르고, 이미 보냈다면 정정 절차를 안내합니다.
- 시험 입력이 섞인 사건은 서버가 실제 발송을 막고 모의 발송만 합니다.

## 9. 안전·개인정보 설계 {nobreak}

### 9.1 주행 제한

플레오스 가드는 주행 중에도 긴급 안내를 써야 하므로 매니페스트에 주행 중 사용(Distraction Optimization, DO)을 선언할 계획입니다. Pleos 문서는 DO를 선언하지 않은 앱을 주행 중 사용할 수 없다고 정합니다. 선언한 뒤에도 앱은 AAOS의 `CarUxRestrictions`가 알려 주는 제한에 따라 화면을 줄입니다. 지역은 플랫폼이 알려 주는 제한을 그대로 따릅니다.

표: 주행 제한 항목과 처리(이름 앞의 UX_RESTRICTIONS_는 생략)
| 제한 | 플레오스 가드의 처리 |
|---|---|
| NO_KEYBOARD | 글자 입력을 숨기고, 말로 메모만 받습니다. |
| NO_SETUP | 보호자 등록, 동의 변경, QR 연결, 설정을 숨깁니다. |
| LIMIT_STRING_LENGTH, LIMIT_CONTENT | 경고등 자세한 설명을 숨기고, 한 줄 운행 판단만 보여 줍니다. |
| NO_VIDEO | 애니메이션을 멈추고, 비상 절차 미리 익히기를 잠급니다. |
| 상태를 알 수 없음 | 주행 중과 같게 처리합니다. |

### 9.2 오디오 규칙

- TextToSpeech의 `setAudioAttributes`로 음성의 용도를 정합니다. 내비게이션 안내 용도와 알람 용도 가운데 에뮬레이터 시험으로 고릅니다. 일반 앱이 쓸 수 없는 긴급 용도는 쓰지 않습니다.
- TextToSpeech SDK는 합성한 오디오 데이터와 오디오 포커스 코드를 앱에 주지 않습니다. 그래서 앱이 Android `AudioManager`로 오디오 포커스를 직접 요청하고 반납합니다.
- 음성 앞부분이 잘리는지는 에뮬레이터에서 확인하고, 필요하면 안내 문장 앞에 짧은 쉼표 문구를 둡니다.
- Gleo가 호출되거나 전화가 걸려 오면 앱 음성을 멈추고, 끝나면 현재 단계를 처음부터 다시 말합니다. 보호자가 "먼저 전화해 보세요"를 보고 전화를 걸어 와도 같은 규칙입니다.
- 시동이 꺼져 대기 상태(Suspend)로 들어가는 순간을 일반 앱이 아는 공개 경로는 확인이 필요합니다(AAOS `CarPowerManager`는 signature 권한). 그래서 앱 화면이 멈추는 시점에 음성을 멈추고 포커스를 반납한 뒤 상태를 저장합니다.
- 음성 인식은 버튼을 한 번 누르면 최대 8초만 합니다. 앱 음성이 나오는 동안에는 인식을 멈춰 자기 목소리를 알아듣지 않게 합니다.
- 사고 뒤에는 큰 음성이나 사이렌 대신, 정차가 확인되면 무엇을 보냈는지 차분하게 한 번 알립니다.

### 9.3 긴급 안내 시작 조건

- 안내는 운전자의 직접 보고(상황 선택, 또는 "말로 하기"를 누른 뒤 말)로만 시작합니다.
- 센서 조합은 "차가 멈추지 않나요?"라는 확인 질문만 띄우고, 같은 주행에서 5분에 한 번까지만 묻습니다.
- 브레이크 밟음 신호와 감속이 보이지 않는다는 사실만으로 감속 실패 대처에 자동으로 들어가지 않습니다.
- 앱은 알리고 기록하는 일만 합니다. 문 잠금 해제 같은 차량 제어 API는 쓰지 않습니다.

### 9.4 위치 제공 동의와 기록

- 운전자 본인에게 위치 제공 동의를 받습니다. 동의 버튼을 누르는 것만 동의로 봅니다.
- 위치를 보낼 때마다 운전자에게 "누구에게, 언제" 보냈는지 차 화면으로 알리고, 그 자리에서 공유를 멈출 수 있게 합니다.
- 보낸 내역은 위치 제공 기록으로 보관하고, 운전자는 내 위치 영수증함에서 봅니다. 이 기록은 언제 누구에게 보냈는지를 남겨야 하므로, 계정을 지워도 개인을 알아볼 수 없게 바꿔 보관합니다.
- 보호자도 번호 인증과 수신 동의를 마친 사람만 받습니다. 서버는 인증한 번호로만 보냅니다.
- 위치기반서비스 사업 신고와 위치정보 이용약관은 출시 전 요건으로 둡니다. 구체적인 법 조문 해석은 출시 전에 따로 확인합니다.

### 9.5 보관과 삭제

- 서버의 사건 자료는 기본 30일 동안 보관하고, 운전자가 더 보관하기로 고른 기록만 따로 둡니다.
- 보호자 링크와 정비 공유 링크는 24시간 뒤 만료되고, 운전자가 언제든 철회할 수 있습니다.
- 운전자는 공유 중지, 보호자 연결 끊기, 휴대폰 연결 해제, 계정 삭제를 직접 할 수 있습니다. 보호자도 스스로 탈퇴할 수 있습니다.
- 운전자가 동의를 철회하면 해당 자료를 쓰는 경로를 바로 끊고 저장된 자료를 지웁니다. 위치 제공 기록은 9.4의 규칙을 따릅니다.
- 앱 이용 통계는 별도 동의를 받고, 계정과 연결하지 않은 설치 번호로 하루 단위 사용 여부만 셉니다. 거부해도 기능은 그대로 씁니다. 통계는 자체 서버에서만 셉니다. 이용 통계 동의 항목과 수집 작업은 계약 미반영(향후)입니다.

### 9.6 공유 차량

한 차를 여러 가족이 함께 쓰면 출발 전에 "이번 운전자"를 고르거나 바꿉니다. 기록과 보호자 알림은 고른 운전자 기준으로 나눕니다. 차량 앱 연결이 끊기거나 오래 정차하면 서버가 그 주행을 자동으로 닫습니다. 게스트 운전자의 위치 자동 발송은 기본으로 꺼져 있고, 켜는 동의는 정차 중에만 받습니다.

### 9.7 성능 예산과 보안

- 주행 중 CPU 5% 미만, RAM 400MB 이하라는 Pleos 성능 기준을 지킵니다. 음성 인식은 누를 때만, 위치는 구독으로만 받고, 평소 주행 표본은 가볍게 남겨 이 예산 안에 들도록 설계합니다. 실제 사용량은 에뮬레이터에서 잽니다.
- 발송사 비밀키는 서버에만 둡니다.
- 전화번호, 인증 토큰, 기기 키는 일반 로그와 예시 파일에 남기지 않고, URL 경로에도 넣지 않습니다.
- 기기에 저장하는 민감 정보는 Android Keystore 키로 암호화하고, 통신은 TLS 1.2 이상을 씁니다.

## 10. 에뮬레이터 시연 계획 {nobreak}

### 10.1 시연 준비

- Pleos Connect 에뮬레이터 2.1.0 AVD(Android 14)를 콜드 부트로 띄웁니다. 빠른 부팅에서는 차량 신호를 쓸 수 없습니다. `adb forward tcp:8088 tcp:8088`로 Virtual Console을 열고, Extended Controls에서 마이크 입력을 켭니다.
- PC에서 모의 서버와 보호자 웹 화면을 띄웁니다. 시연 발송은 모두 모의 발송입니다.
- 위치(`FUSED_LOCATION`)와 차속(`CAR_SPEED`) 허락을 미리 받아 둡니다.
- 시연 전에 한국어 기기 안 음성 엔진, NaviHelper 연결, 앱 자체 정비소 좌표로 `addWaypoint`·`requestTrip` 호출, FusedLocation 첫 위치, 좌석 점유 값, 공조·창문·와이퍼 카드 값, 주행 제한 명령에 따른 화면 축소를 확인합니다. 정비소 좌표 호출이 되지 않으면 그 장면은 "내비에서 보기"로 바꾸고, 확인에 실패한 다른 장면은 미리 녹화한 화면으로 바꿉니다.

| 취급설명서 대조 검토 | 다음 단계 | 시연 문장은 시연용 초안으로 표시합니다. |
| 사용자 시험 | 다음 단계 | 12.6의 계획대로 진행합니다. |

### 11.3 개발 순서

1차 결과 전에는 차량 신호가 화면에 들어오는 길부터 만듭니다. 먼저 SDK 연결 시험 화면으로 신호마다 첫 수신 시각과 성공·실패를 남기고, 장면별로 실제 시연과 녹화 대체를 정합니다. 신호 어댑터, 품질 상태, 기록 저장 위에 홈, 경고등 찾기, 지금 기록, 긴급 안내 화면을 얹습니다. 2차 발표 전에는 서버와 보호자 쪽을 만듭니다. 모의 발송기로 발송 확인, 취소, 정정, 문자 전환 흐름을 끝까지 시험하고, 같은 기록의 중복 발송과 발송 직전 취소가 겹치는 경우를 확인합니다.

### 12.2 예상 MAU

예상 월간 활성 사용자(MAU)는 탑재 차량 수 × 설치율 × 월 활성률로 계산합니다. Pleos 탑재 대수는 공개되지 않았고, 2025년에 팔린 아반떼와 그랜저에는 Pleos가 없습니다. 그래서 같은 차종의 신형(더 뉴 그랜저 2026년 5월, 디 올 뉴 아반떼 2026년 8월 출시)이 2025년과 비슷한 규모로 1년 동안 팔린다고 가정하고, 2025년 국내 판매량 합계(7만 9,335대 + 7만 1,775대 = 15만 1,110대)를 약 15만 대로 씁니다. 1년 판매량만 세므로 입점이 늦어질수록 실제 탑재 차량은 더 많아집니다. 설치율과 월 활성률은 App Market 통계가 공개되지 않아 모두 가정입니다. 월 활성률은 12.3의 재사용률 목표(30일 20%)와 맞춰 기준값을 20%로 둡니다.

표: 예상 MAU 산식(모든 값은 가정)
| 구분 | 탑재 차량 | 설치율 | 월 활성률 | 예상 MAU |
|---|---|---|---|---|
| 낮음 | 8만 대(아반떼만) | 5% | 15% | 약 600명 |
| 기준 | 15만 대(그랜저와 아반떼) | 10% | 20% | 약 3,000명 |
| 높음 | 15만 대 | 15% | 30% | 약 6,750명 |
| 2030 확대 | 약 2천만 대(그룹 계획, 해외 포함) | 1% | 20% | 약 4만 명 |

MAU는 차량 앱의 활성 차량 수로 셉니다(차 1대를 1명으로 계산). 보호자 웹을 연 보호자는 따로 셉니다. 2030년 숫자는 확대 가능성을 보여 주는 가정이며 예측이나 실적이 아닙니다. 입점 뒤에는 실제 사용 자료로 다시 계산합니다.

### 12.3 활성 사용자와 재사용률

활성 사용자는 그 달에 점검 확인, 경고등 찾기, 기록 열람 가운데 하나를 직접 한 사람입니다. 앱을 켜기만 한 경우와 긴급 기능 사용은 넣지 않습니다. 재사용률(Retention)은 설치한 날 기준으로 다시 활성 행동을 한 비율이며, App Market 입점 뒤 이용 통계에 동의한 첫 사용자 집단에서 잽니다.

표: 재사용률 정의와 목표(가설)
| 지표 | 정의 | 목표 | 못 미칠 때 |

| 7일(D7) | 설치 7일 뒤 다시 활성 행동을 한 비율 | 35% | 첫 실행 흐름과 출발 전 점검 카드를 다시 봅니다. |

### 12.4 반복 이용 기능과 확보 경로

긴급 상황은 드물기 때문에 평소에 다시 열 이유를 기능으로 만듭니다. 출발 전 점검 카드, 500km 뒤 재발 확인을 묻는 정비 노트, 주 1회 경고등 익히기 카드입니다. 앱은 시동과 함께 저절로 열리지 않습니다. 앱을 열면 홈 맨 위에 카드가 보이고, 사용자가 켠 경우에만 할 일이 있는 날 정차 중 하루 한 번 알림을 보냅니다. 세 기능의 7일·30일 재방문율을 따로 재서 어떤 기능이 앱을 다시 열게 하는지 확인합니다.

- **App Market 검색.** "경고등", "점검", "가족 알림" 같은 검색어와 차량 관리 분류로 찾기 쉽게 합니다.
- **보호자가 부모 차에 깔아 주는 흐름.** 1단계의 핵심 확보 경로입니다. 설치 안내는 알림 본문이 아니라 보호자 웹과 정비사 요약 화면 아래에 둡니다. 보호자 차가 Pleos 차량이면 그 차에도 권합니다.
- **제휴 후보.** 차량 출고 안내와 블루핸즈 정비 접수 때 소개하는 방식은 현대자동차와 협의할 후보입니다.
- **경쟁 위험.** 그룹이 차량 관리 앱을 늘릴 계획이므로 같은 영역의 공식·협력 앱이 나올 수 있습니다. 한 기록 연결과 보호자 경험으로 차별화하고, 제휴를 먼저 검토합니다.

### 13.2 Pleos 기술 문의 항목

- **발·페달 안내와 운전자 주의 분산 원칙.** Pleos 디자인 원칙은 운전자의 손이나 발을 움직이는 동작을 유도하지 말라고 합니다. 취급설명서의 비상 절차를 음성으로 읽는 긴급 안전 안내가 이 원칙과 어떤 관계인지 확인합니다.
- **긴급 음성의 오디오 용도.** 일반 앱의 긴급 안내 음성에 내비게이션 안내 용도와 알람 용도 가운데 무엇을 권하는지, 통화 중에는 어떻게 해야 하는지 묻습니다.
- **음성 서비스.** TextToSpeech와 SpeechToText 권한의 보호 수준, ON_DEVICE 모드의 한국어 엔진, 음성 서비스가 음성 앞부분 무음을 처리하는지 확인합니다.
- **Suspend 진입.** 일반 앱이 시동 종료로 대기 상태에 들어가는 순간을 아는 공개 방법이 있는지 묻습니다.
- **AAOS 차속 경로.** 공개 문서가 안내하는 경로로 쓰고, 입점 심사에서 허용 범위를 최종 확인합니다.
- **카드가 없는 신호의 시험 방법.** 에어백 전개, 안전벨트, 엔진오일 신호를 에뮬레이터에서 바꿀 공식 방법이 있는지, 와이퍼 카드가 `WiperState`를 바꾸는지 묻습니다.
- **좌석 점유 값과 NaviHelper 요청.** 좌석 점유의 참·거짓이 Virtual Console의 Occupied·Empty와 같은 뜻인지, 자체 정비소 좌표로 경로를 요청할 때 POI 번호를 비워도 되는지, `requestTrip`이 내연기관 차에서도 동작하는지 묻습니다.
- **앱이 뒤에 있을 때의 알림.** 앱이 꺼져 있거나 뒤에 있을 때 정차 중 하루 한 번 알림을 보낼 수 있는지 확인합니다.
- **한국 지역 주행 제한과 입점 조건.** 한국이 주행 제한 정책의 어느 지역에 해당하는지, Vehicle SDK 권한 사전 승인 절차와 앱 이름에 Pleos 표기를 쓰는 조건을 확인합니다.

출시 전에는 취급설명서 문장과 경고등 그림의 이용 조건(현대자동차 협의), Pleos Connect 차량의 블루링크 제공 범위, 알림톡 템플릿 심사와 문자 발신번호 등록, 위치기반서비스 사업 신고와 위치정보 이용약관, 연령 등급, 공식 차량 사진의 사용 권리를 확인합니다.

| Pleos Playground, App Market | 개발자에게 SDK와 문서를 주는 곳(Playground)과 차량 앱을 내려받는 장터(App Market)입니다. |
| SDK, API | SDK는 앱 개발용 도구 묶음이고, API는 앱이 다른 프로그램의 기능을 부르는 약속된 방법입니다. |
| AAOS | 차량용 안드로이드 운영체제(Android Automotive OS)입니다. 차속과 주행 제한 상태를 알려 줍니다. |
| Virtual Console | 에뮬레이터에서 브레이크, 문, 좌석 같은 차량 값을 바꾸는 웹 화면입니다. |
| FormFactorConsole | 에뮬레이터에서 화면 크기와 방향을 바꿔 보는 도구입니다. |
| CarUxRestrictions, DO | 차가 주행 중일 때 앱 화면에 거는 제한과, 주행 중 사용을 선언하는 설정(Distraction Optimization)입니다. |
| TTS, STT, ON_DEVICE | 글을 음성으로 읽는 기능(TextToSpeech), 음성을 글로 바꾸는 기능(SpeechToText), 네트워크 없이 기기 안에서 처리하는 방식입니다. |
| 말로 하기 | 주행 중 홈 가운데 버튼입니다. 한 번 누르고 한 문장을 말하면 기록 메모, 경고등 찾기, 긴급 안내, 도움 요청으로 나눠 보냅니다. |
| 확인 질문 | 센서 조합이 이상할 때 안내를 시작하지 않고 "차가 멈추지 않나요?"만 묻는 화면입니다. |
| 내비 옆 동반 창 | 내비 옆 세로 창에 플레오스 가드를 두고, 지도는 내비에 맡기는 배치입니다. |
| 오디오 포커스 | 여러 앱의 소리가 겹치지 않게 누가 소리를 낼지 정하는 규칙입니다. |
| Gleo | Pleos Connect의 음성 비서입니다. |
| 경고등(텔테일) | 계기판에 켜지는 경고·표시 등입니다. |
| 기록(사건) | 한 번의 이상 상황에 속한 모든 정보를 묶은 단위입니다. 서버에서는 사건(incident)이라고 부릅니다. |
| 차량 상태 스냅샷 | 어느 순간의 차량 값을 출처와 받은 시각과 함께 묶은 자료입니다. |
| 재현 조건 카드 | 같은 증상 기록 세 번 이상을 평소 주행과 비교해, 유난히 겹친 조건을 정리한 카드입니다. |
| 주기형 신호, 변화 알림형 신호 | 주기적으로 오는 값(차속)과, 바뀔 때만 오는 값(브레이크·문)입니다. |
| 신선도 | 값이 얼마나 최근에 받은 것인지를 뜻합니다. 주기형 신호는 3초가 기준입니다. |
| 발송 전 확인 10초 | 보호자 알림을 보내기 전 운전자가 취소하거나 바로 보낼 수 있는 시간입니다. |
| 알림톡 전달 확인 기한 | 서버가 알림톡 전달을 기다린 뒤 문자로 바꾸는 기한입니다. 지금 설정값은 10초입니다. |
| 시험 입력 | 에뮬레이터가 주지 않는 값을 앱 안 재생기로 넣은 값입니다. |
| 멱등 처리 | 같은 요청이 여러 번 와도 한 번만 처리하는 방식입니다. |
| MAU, Retention | 한 달 동안 실제로 쓴 사람 수와, 설치 뒤 다시 쓰는 사람의 비율입니다. |
| L1, L2, L3 | 위험 등급입니다. L1 기록, L2 확인 필요(운전자가 고를 때만 알림), L3 긴급 도움입니다. |
| [시연], [설계], [향후] | 지금 시연할 기능, 추가 구현이 필요한 기능, 공개 SDK 밖이라 계획으로만 둔 기능입니다. |

### B.4 그림과 글꼴

- 차량 사진(그림 2)은 현대자동차그룹 디 올 뉴 아반떼 공식 자료(현대자동차 보도자료, 2026.8.5)입니다. 화면 속 차량 사진(홈의 앞모습, 주행 중 긴급 화면의 뒷모습)은 같은 보도자료의 공식 사진에서 잘라 썼고 보도용 번호판은 지웠습니다.
- 앱 진입 화면(그림 1)은 공식 차량 사진과 화면 시안을 바탕으로 만든 생성 이미지 시안입니다. 비상 절차 미리 익히기 화면의 페달 그림도 생성 이미지 시안입니다.
- 화면 시안은 기획 시안이며 실제 구동 화면이 아닙니다. 앱 시안 글꼴은 Pretendard(SIL Open Font License 1.1), 아이콘은 Lucide(ISC License)입니다. 이 문서의 글꼴은 페이퍼로지입니다.
