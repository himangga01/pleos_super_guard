## 글자 수 기준

- 각 원고는 12개 문단입니다. 문단은 빈 줄 하나로 나눕니다.
- 파일 끝의 개행을 빼면 원고 문자열 길이는 정확히 3,000입니다. 문단 사이 줄바꿈 22개가 포함되므로 글자·공백은 2,978자입니다.
- Word의 공백 포함 문자 수(`ComputeStatistics(5)`)는 수동 줄바꿈 1개를 1자로 셉니다. 이전 Windows 작업에서 이 계산과 Word 실측이 같다는 것을 확인했습니다.
- 이번 v4는 Linux에서 만들었습니다. 그래서 글자 수는 **XML 계산값**(작성란 `w:t` 글자 수 + `w:br` 개수)으로 확인했고, Word로 다시 재지는 않았습니다. 제출 전에 Windows Word에서 한 번 더 재는 것을 권합니다.
- 항목 제목과 양식 안내 문구는 세지 않습니다. 한 줄 소개(1번), 참고자료(7번), 숏폼(8번)은 3,000자 대상이 아닙니다.

## v4에서 바뀐 점

- 공모전 공지 8에 따라 공개 SDK로 지금 만들 수 있는 기능과 향후 계획을 나눴습니다. 경고등 상태 자동 연동, 원본 녹음·영상, 블랙박스, 진동 분석은 향후 계획으로만 씁니다.
- 5번에 SDK별 사용 계획(Vehicle 2.3.2, AAOS 차속 경로, NaviHelper 3.0.5, TextToSpeech·SpeechToText 3.3.1, FusedLocation 1.1.3), 에뮬레이터 시연 방법, 일정을 넣었습니다.
- 6번에 타깃 고객, 가정을 밝힌 예상 MAU 산식, Retention 목표, 경쟁 수단과의 관계, 수익 모델 후보, 확대 단계를 넣었습니다. 판매량과 Pleos Connect 적용 계획은 현대자동차그룹 뉴스룸 공개 자료로 확인했습니다.
- 긴급 안내는 운전자가 직접 알릴 때 시작하고, 주행 중에는 짧은 음성과 움직이지 않는 그림만 씁니다. 페달 그림과 애니메이션은 정차 중 "비상 절차 미리 익히기"로 옮겼습니다.
- 새 기능을 넣었습니다: 차가 알려 준 점검 항목, 출발 전 점검 카드, 재현 조건 카드, 정비 노트와 재발 확인, 가는 길에 정비소 들르기, 사고 순간 차량 스냅샷, 보호자 연습 알림과 빠른 답, 경고등 익히기 카드, 비상 절차 미리 익히기.
- 4번은 세 인물(가정)의 장면으로 다시 썼습니다.

## 적용 방법

`output/submission/build_v4.py`가 이 원고와 `docs/submission/official-form-v4.json`(1·7·8번 문구와 그림 목록)을 읽어 공식 양식을 만듭니다. 이 스크립트는 기존 결과물을 덮어쓰지 않고 지정한 출력 폴더에 만든 뒤, 검사를 통과하면 `--install`로 정식 파일을 바꿉니다. 이전 스크립트(`build_documents.py`, `restyle_documents.py`, `expand_official_content.py`)를 직접 실행하면 옛 원고와 디자인으로 돌아갈 수 있으니 실행하지 않습니다.

개인정보 공란, 03 동의서·04 서명 영역의 원본 디자인, 앱 이름, Pleos 차량 전용 범위는 그대로 유지합니다.
