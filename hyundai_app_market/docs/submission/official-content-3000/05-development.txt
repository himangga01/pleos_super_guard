차량 앱을 중심으로 휴대폰 보조 앱과 서버를 만듭니다. 차량 앱은 Kotlin과 Compose, Android API 28 이상으로 만들고 Pleos Connect 에뮬레이터 2.1.0으로 시험합니다. 차량 기능은 공모전이 허용한 공개 SDK Vehicle 2.3.2, NaviHelper 3.0.5, TextToSpeech 3.3.1, SpeechToText 3.3.1, FusedLocation 1.1.3과 Pleos FAQ가 안내하는 AAOS 차속 경로를 씁니다. 서버는 TypeScript와 PostgreSQL을 씁니다.

Vehicle SDK는 증상 기록과 점검의 바탕입니다. Brake로 브레이크 페달 상태를, SteeringWheel로 조향각을, TurnSignal로 방향지시등을, Door로 문 상태를, Odometer로 주행거리를 받습니다. Safety에서는 엔진오일과 브레이크액 수준, 워셔액 부족, 출력 저하 경고, 안전벨트 미체결, 좌석별 에어백 전개를, Seat에서는 좌석 점유를 읽습니다. 모두 일반 앱이 받을 수 있는 normal 수준 권한입니다.

각 기능은 먼저 check로 시작하는 지원 확인 API를 불러 이 차에서 쓸 수 있는지 봅니다. 지원 여부는 확인 결과로, 권한 부족은 SDK가 바로 던지는 SecurityException으로 알아차려 그 항목만 "확인 불가"로 둡니다. 서비스 연결 전 호출은 기다리게 되므로 시간 제한을 두고, 콜백은 메인 스레드가 아닌 곳에서 오므로 화면 갱신은 따로 넘깁니다. 받은 값에는 출처, 받은 시각, 품질 상태를 함께 저장합니다.

차속은 Vehicle SDK 2.3.2에서 속도 리스너가 빠져 AAOS CarPropertyManager의 PERF_VEHICLE_SPEED로 읽고, 실행 중 허락이 필요한 CAR_SPEED 권한을 거부하면 차속 없이 동작합니다. 차속처럼 주기적으로 오는 값은 3초 넘게 끊기면 오래된 값으로 봅니다. 브레이크처럼 바뀔 때만 오는 값은 마지막 수신 시각과 서비스 연결 상태로 유효성을 판단합니다. 값이 없으면 눌리지 않았다고 바꾸지 않고 확인 불가로 처리합니다.

주행 중 화면은 Distraction Optimization 사용을 선언하고 CarUxRestrictions가 알려 주는 제한을 따릅니다. 제한이 켜지면 긴 설명, 설정, 보호자 등록, 움직이는 그림을 멈추고 큰 버튼과 음성만 남깁니다. 주행 상태를 알 수 없으면 주행 중으로 봅니다. 화면은 Pleos 기본 형태인 세로 한 창과 가로 화면을 모두 만들어 같은 기능을 제공하고, FormFactorConsole로 화면 크기별 배치를 확인합니다.

음성은 TextToSpeech를 기기 안 모드와 한국어로 씁니다. setAudioAttributes로 안내 음성 용도를 정하고, 오디오 포커스는 앱이 직접 요청하고 돌려주며, Gleo나 전화가 오면 즉시 멈춥니다. 음성 입력은 "말로 하기"를 누르면 SpeechToText로 최대 8초만 듣고, 결과 문장에서 정해 둔 말과 메모만 씁니다. 차량 마이크 음성을 외부 음성 인식 서비스로 보내지 않습니다.

위치는 FusedLocation의 좌표와 측정 시각, confidence 값을 그대로 저장합니다. 오차 반경은 표시하지 않습니다. 주소는 NaviHelper 현재 위치 정보로 받습니다. 정비소 연결은 NaviHelper의 addWaypoint로 가던 경로에 경유지를 더하고(NAVI_ROUTE_SEARCH 권한), requestTrip으로 후보별 도착 예상 시간을 비교합니다. 도감과 긴급 음성 문장은 취급설명서와 대조해 버전을 관리합니다.

서버는 기록, 보호자, 동의, 위치 제공 기록, 알림 작업을 나눠 관리합니다. 카카오톡 알림톡을 먼저 보내고 정한 기한 안에 전달이 확인되지 않으면 문자로 바꿉니다. 접수, 전달, 열람을 따로 저장하고 중복 발송을 막습니다. 운전자가 위치 제공에 동의한 범위 안에서만 보내고, 보낼 때마다 받은 사람과 시각을 남겨 운전자에게 보여 줍니다. 시험 입력이 섞인 기록은 모의 발송만 하고, 발송사 비밀키는 서버에만 둡니다.

휴대폰 보조 앱은 Pleos SDK를 넣지 않은 별도 앱입니다. FusedLocation이 차량용 기기에서만 설치되도록 선언돼 있어 같은 설치 파일을 휴대폰에 쓸 수 없기 때문입니다. 두 앱은 정차 중 차 화면의 QR로 한 번 연결하고 서버를 거쳐 같은 기록 번호를 씁니다. 차량 앱의 연락이 끊겨도 이미 서버에 올라간 보호자 알림은 서버가 끝까지 보내고, 휴대폰은 그 상태를 보여 줍니다. 휴대폰은 계기판 사진 비교와 보호자 연습 알림도 맡습니다.

2차 발표는 에뮬레이터로 합니다. 브레이크 페달, 문, 방향지시등, 좌석 점유, 주행거리, 조향각은 Virtual Console에서 값을 바꿔 실제 SDK 수신으로 보여 줍니다. 차속, 에어백 전개, 엔진오일 경고처럼 Virtual Console에 없는 값은 앱 안의 시험 입력 재생기로 넣고 화면에 "시험 입력"이라고 표시합니다. 주행 제한은 adb 명령으로 켜서 화면이 줄어드는 모습을 보여 주고, 알림은 모의 서버와 보호자 웹 화면으로 시연합니다.

일정은 접수 뒤 바로 시작합니다. 11월 23일 1차 결과 발표 전까지 차량 앱의 홈, 경고등 찾기, 지금 기록, 긴급 안내 화면과 Vehicle SDK 연결을 만듭니다. 12월 3일 2차 발표 전까지 보호자 알림 서버와 모의 발송, 휴대폰 연결, 정비소 경유지, 시연 모드를 완성하고 끊긴 값과 앱 재시작까지 시험합니다. 지금 끝낸 일은 기획, 화면 시안, API와 데이터 계약 설계이며 앱 코드와 실제 발송은 아직 하지 않았습니다.

공개 SDK에 없는 기능은 향후 계획으로 분명히 나눕니다. 계기판 경고등 상태 자동 연동은 PRIVATE 권한이 필요해 일반 앱이 쓸 수 없습니다. 원본 녹음과 영상, 블랙박스, 진동 분석에 필요한 가속도·자이로 센서, 충격 센서, 가속 페달 값도 공개 경로가 없습니다. 이 기능은 해당 API가 공개되거나 제휴로 권한을 받은 뒤 같은 기록 구조에 더합니다. 그전까지는 차량 상태 시간표와 운전자의 선택으로 같은 목적을 돕습니다.
